## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
Проблема (жалоба Pavel 2026-10-03): уведомление бота о завершении фазы привязано к child.on('close') процесса qwen — между отчётом комментарием (последний шаг phase-1/2/3 шаблонов) и ответом в чат 7+ минут (финальный вывод qwen на большом контексте на Catalina). VL-44: комментарий 02:38, сообщение в чат 02:45.

Решение: ранний триггер onExit — по появлению отчётного комментария в файле задачи, а не по выходу процесса. В startPhase (только при переданном onExit — бот): (1) экспорт findTaskFilePath из src/core/store.ts (строка 216, сейчас не экспортируется); (2) снапшот comments.length через getTask на старте запуска; (3) fs.watch на файл задачи + debounce ~500мс (FSEvents шлёт серию событий); (4) чистая функция isPhaseReport(snapshotCount, task): boolean — новые комментарии появились, ПОСЛЕДНИЙ новый: author '@agent' И текст /^Фаза .*выполнена/ (покрывает «Фаза 1 (Spec)…», «Фаза 2 (Plan)…», «Фаза 3 (Code)…», «Фаза Close…»); (5) при срабатывании — onExit(record с source:'report') РОВНО один раз: guard notified на ActiveRun; close/error потом только обновляют lastRuns, БЕЗ повторного onExit; (6) watcher.close() в finish() (guard error+close сохраняется по памяти spawn-close-after-error-pitfall).

Альтернативы отклонены: exit вместо close (задержка в финальном выводе qwen, не в stdio); ожидание process exit с таймаутом (ненадёжно).

## Проблема
В фазе Close нужно было дописать раздел §12 в `doc-27`. Вызовы `document_update {id:'doc-27', title, type}` без `content` возвращали `outcome:'noop'` с сообщением «Изменений нет: title, type документа уже имеют эти значения» и подсказкой «переходи к следующему пункту фазы». Это читается агентом как «изменений не требуется / работа сделана», хотя тело документа НЕ переписано. Агент повторил вызов 6+ раз подряд (детектор цикла поймал `noop_repeat`), фаза не завершилась. Корень: `document_update` — update-семантика «только переданные поля», и при передаче уже совпадающих полей ответ честно сообщает noop, но для документа, который надо ДОПИСАТЬ, «нет изменений» ложно. Отдельный случай (VL-384): документ физически не влезает в вызов — `doc-10` 192 КБ (≈48k токенов), прочитать целиком ради `content` и записать обратно нельзя, а частичной правки не было вовсе, поэтому точечные правки документов делали обходом через `node -e`/`edit` в главном репо мимо MCP (осознанное нарушение правила «backlog правится только через MCP»).

Решение (до VL-399). Передавать `content` (полное новое тело) в том же вызове `document_update`, что и остальные поля. Если тело большое (>8 КБ) — не читать его чанками через `read_file` (вывод обрезается, символы теряются), а собрать скриптом: `node -e "const fs=require('fs'); ..."` — прочитать файл целиком, вклеить новый раздел, записать обратно. Если документ слишком велик для полного `content` (сотни КБ) — править файл в главном репо точечно (`edit` с уникальным якорем или `node -e` со `split/join` по точной подстроке), затем подтверждать результат `git diff --stat` и `grep` по новым значениям. Условие снятия обхода, зафиксированное здесь же: появление у документа режима частичной правки (патч/якорь) — VL-399 его выполнил.

Обновление VL-399 (2026-11-10): частичная правка появилась — `document_edit {id, old_string, new_string, replace_all?}` правит ТЕЛО документа по якорю, не читая и не переписывая его целиком, поэтому обход `node -e`/`edit` по backlog/docs больше не нужен ни для дописывания раздела, ни для документов в сотни КБ: тело остаётся на диске, в вызов уходит только якорь и замена. Урок сохраняется как правило про noop: ответ `noop` на update-инструмент — сигнал «аргументы уже такие», а НЕ «действие не нужно»; прежде чем повторять, проверь, не забыл ли ты поле, ради которого вызвал инструмент. Для правки абзаца теперь и это не требуется — бери `document_edit`, а `content` в `document_update` передавай только при осознанной полной замене тела (guard отклоняет подозрительное сжатие без `full_replace: true`).

Обновление VL-397 (2026-11-10): обратная сторона того же правила — `document_update` без `content` НЕ всегда noop. Если переданные поля (title/tags) реально меняются, вызов применяется: title правит frontmatter, файл переименовывается, а тело берётся из `entry.body` и сохраняется (в ответе видны applied-поля). Это штатный путь «сменить шапку, не трогая тело» для больших документов; noop-риск остаётся только при передаче уже совпадающих значений.

## Решение
При правке части документа вызывай `document_edit` с уникальным якорем (`old_string`) — тело не нужно читать и копировать целиком; `document_update {content}` держи для осознанной полной замены тела и передавай `full_replace: true`, если новый текст существенно короче. Ответ `noop` на любой update-инструмент читай как «переданные поля уже такие», а не как «работа сделана»: перед повтором проверь, не забыл ли ты поле, ради которого вызвал инструмент. `document_update` без `content` законен, когда меняются только шапка/теги — тело сохраняется само.

## Пример
Пометка «устарело» в doc-10: вместо `document_update {id:'doc-10', content:'<короткий текст>'}` (инцидент 2026-11-10 — утрачены §3–§12, ответ был победным) вызывается `document_edit {id:'doc-10', old_string:'## 1. Назначение', new_string:'> Устарело: см. doc-27\n\n## 1. Назначение'}` — тело остаётся на диске, в ответе `applied.replaced: 1` и размеры до/после. Обратный случай (VL-397): `document_update {id:'doc-10', title, tags}` БЕЗ `content` — законный вызов, потому что переданные поля реально меняются (title → файл переименован, теги дописаны); тело при `content === undefined` берётся из `entry.body` и сохраняется, а ответ не noop.

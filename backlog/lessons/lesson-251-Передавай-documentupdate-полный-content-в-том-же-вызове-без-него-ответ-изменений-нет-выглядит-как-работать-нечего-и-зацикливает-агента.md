## Проблема

В фазе Close нужно было дописать раздел §12 в `doc-27`. Вызовы `document_update {id:'doc-27', title, type}` без `content` возвращали `outcome:'noop'` с сообщением «Изменений нет: title, type документа уже имеют эти значения» и подсказкой «переходи к следующему пункту фазы». Это читается агентом как «изменений не требуется / работа сделана», хотя тело документа НЕ переписано. Агент повторил вызов 6+ раз подряд (детектор цикла поймал `noop_repeat`), фаза не завершилась.

Корень: `document_update` — update-семантика «только переданные поля», и при передаче уже совпадающих полей ответ честно сообщает noop. Но для документа, который надо ДОПИСАТЬ, «нет изменений» ложно: изменение есть, его просто не передали.

## Решение

Передавать `content` (полное новое тело) в том же вызове `document_update`, что и остальные поля. Если тело большое (>8 КБ) — не читать его чанками через `read_file` (вывод обрезается, символы теряются), а собрать скриптом: `node -e "const fs=require('fs'); ..."` — прочитать файл целиком, вклеить новый раздел, записать обратно. Для правки одного раздела достаточно нативного `edit` с якорем.

Ответ `noop` на update-инструмент — сигнал «аргументы уже такие», а НЕ «действие не нужно». Прежде чем повторять, проверь: не забыл ли я поле, ради которого вызвал инструмент.

## Пример

Плохо (6 повторов, цикл):
```
document_update {"id": "doc-27", "title": "...", "type": "specification"}
→ noop: "Изменений нет: title, type уже имеют эти значения"
```

Правильно:
```
edit(path="backlog/docs/doc-27-….md", old_string="**Статус:** … §11", new_string="**Статус:** … §11; … §12")
+ node -e "<вклеить готовый раздел §12 в конец файла>"
→ grep -n "^## 12" подтверждает раздел на месте
```

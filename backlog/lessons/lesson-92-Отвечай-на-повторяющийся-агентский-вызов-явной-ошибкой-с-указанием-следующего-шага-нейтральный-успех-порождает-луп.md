## Проблема

Агент зациклился на `backlog_finish_phase` (VL-234 → VL-251). Инструмент на
no-op (статус = текущий, нет отчёта) отвечал нейтрально-успешно:
`«Статус: Planned; отчёт: нет; …»`. Для модели это «принято, но чего-то не
хватает» → повтор байт-в-байт. Loop detection срабатывал, но писал директиву
в `role: assistant` (модель читала её как свой текст) и не запоминал
отклонённую сигнатуру — после «Продолжить» луп шёл по второму кругу.

## Решение

1. **No-op и неполный вызов — ошибка, а не успех.** Инструмент, который
   ничего не изменил, обязан ответить `isError` с текстом «уже завершено /
   не передан report», датой и источником существующего результата. Мягкое
   частичное применение оставлять только для невалидных значений полей.
2. **Директива loop detection — tool-результатом** (`role:'tool'` с
   `tool_call_id` заблокированного вызова), с явным «Следующий шаг: …».
   `fail()` после этого — только при 2-й блокировке подряд.
3. **Отклонённые сигнатуры персистить в мету сессии** (`blocked_signatures`),
   читать при resume и блокировать до исполнения, объединяя через merge с
   дедупликацией и капом.

## Пример

```ts
if (blocked.has(signature)) {
  await pushMessage({ role: 'tool', tool_call_id: call.id, content: loopDetectionDirective(call.name, repeatLimit) });
  if (++blockedStreak >= 2) return fail(`Loop detection: … ${NEXT_STEP_HINT}`);
  continue;
}
```

## Проблема

Добавление интерактивного мастера в существующую CLI-команду (`vibelog init`) ломает десятки тестов, которые спавнят CLI через `spawnSync` без TTY: процесс ждёт ввод на stdin и висит до таймаута, а легаси-строки вывода, на которые опираются старые тесты, исчезают.

## Решение

1. Интерактив включай по строгому условию: `process.stdin.isTTY && process.stdout.isTTY && !flags.yes && !flags['no-wizard']`. Без TTY поведение команды остаётся прежним — старые spawn-тесты не трогаются.
2. Легаси-строки вывода сохраняй дословно (например «Создана директория», «MCP-сервер vibelog настроен»): регресс-тесты на вывод — инвариант, их правка маскирует регресс.
3. Для raw-mode чекбоксов: `setRawMode(true)` только при `isTTY`, восстановление в `finally` + `rl.close()`; без TTY — fallback на нумерованный ввод (`1,2` через запятую), чтобы логика выбора оставалась тестируемой.

## Пример

VL-210: первый полный прогон дал 2 падения (`src/cli/cli.test.mjs`, `src/cli/init-mcp.test.mjs`) — не из-за тестов, а из-за переписанных строк вывода. Восстановление строк дословно вернуло зелень без правки тестов.

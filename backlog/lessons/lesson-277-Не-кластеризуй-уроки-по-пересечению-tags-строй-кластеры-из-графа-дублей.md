## Проблема
Группировка уроков по пересечению tags (union-find) сливает весь корпус в один мега-кластер, а группировка по одной метке даёт десятки ложных кластеров: общая метка (`тесты`, `docs`, `build`) — это область работ, а не правило.

## Решение
Строй кластеры правил из компонент связности графа уже посчитанных дублей (`duplicate_of` из аудита), а tag-группы принимай только при смысловой близости заголовков (Jaccard ≥ 0.12) и размере ≤ 4 — иначе кластер не правило, а область.

## Пример
В `buildConsolidationPlan` (VL-400) кластеры строятся из компонент связности графа `duplicate_of` плюс tag-групп с Jaccard заголовков ≥ 0.12 и размером ≤ 4. На корпусе 274 уроков это дало 4 осмысленных кластера; union-find по tags дал один мега-кластер, группировка по одной метке — 81 «кластер» из несвязанных уроков.

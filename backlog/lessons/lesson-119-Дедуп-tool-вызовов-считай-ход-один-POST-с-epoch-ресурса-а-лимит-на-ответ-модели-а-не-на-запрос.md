## Проблема

Веб-чат VL-255: один ответ модели содержал ~50 tool-вызовов с дословными повторами (name+args повторились ≈8 раз), часть — по несуществующим путям. Нужна дешёвая защита: не исполнять точный дубль, ограничить число вызовов, сказать модели явно, что повтор бессмысленен. При этом наивные границы ломают легитимные сценарии (чтение файла после записи, пакетное чтение в несколько LLM-итераций).

## Решение

1) **Граница «ход» = один POST `/api/chat`** — стейт guard'а в памяти `produce()`, сбрасывается на запрос. Инцидент был внутри одного ответа, этого достаточно; персистентный дедуп потребовал бы писать состояние в jsonl треда (отдельная задача).
2) **Ключ дубля — точный**: `name + '|' + стабильная JSON-сериализация args` (рекурсивная сортировка ключей объектов, порядок массивов сохраняется, `undefined`/функции отбрасываются). Грубый `repeatKey` из `repeat-tracker` (path/pattern) остаётся для предупреждений/метрики, а не для блокировки.
3) **Лимит считай на ответ модели (`resp.toolCalls`), а не на запрос**: внутри POST до 8 LLM-итераций, лимит «на запрос» режет легальное пакетное чтение (6 вызовов × 3 итерации). Дефолт 16, `beginTurn()` перед каждым `llm.streamChat` сбрасывает только счётчик ответа.
4) **Легитимный повтор — epoch по ресурсу**: `toolRepeatTarget(name,args)` (read_file/edit → path, grep/glob/search → pattern); write-вызов инкрементит epoch своего ресурса ДО записи сигнатуры, поэтому повторное чтение после записи проходит, а дословный повтор записи — блокируется.
5) **Синтетические ответы только через единую точку `executeTool`** — тогда дедуп работает и в обычном цикле, и в resume после Allow/Deny, и в `advanceToNextApproval`. События `tool_start`/`tool_end` остаются снаружи (парность для фронта), `isError: false` — это сообщение модели, не ошибка инструмента.

## Пример

```ts
export function callSignature(name: string, args: unknown): string {
  return `${name}|${stableJson(args)}`;
}
// writeEpoch: Map<resourceKey, number>; noteExecuted для write: bumpEpoch → запись сигнатуры с новым epoch
```
Блокированный вызов отдаёт `{"ok":false,"duplicate":true,"message":"… — используй полученный ранее результат."}` / `{"ok":false,"limit":true,"message":"Лимит tool-вызовов на один ответ исчерпан (16) — заверши ход и продолжи следующим."}` — с явным следующим шагом, а не нейтральным «успех» (lesson-92).

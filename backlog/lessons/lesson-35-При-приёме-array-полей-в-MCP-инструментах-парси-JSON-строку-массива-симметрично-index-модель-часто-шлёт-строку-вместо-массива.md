## Проблема

Модель/shaper может передавать значение array-поля как JSON-строку `["A","B"]` вместо реального массива. В VL-183 `manage_ac {action:"add", text:"[\"A\",\"B\"]"}` записал JSON одним критерием, потому что ветка `Array.isArray(args.text)` не срабатывала, а строка уходила в scalar-ветку. Тот же паттерн уже был закрыт для `index` (parseChecklistIndexes, VL-120/VL-135), но для `text` — упущен.

## Решение

При приёме array-полей на границе MCP добавляй симметричный разбор JSON-строки: если строка после trim начинается с `[` — try JSON.parse; успех + Array.isArray + все элементы-непустые строки → обработай как массив; иначе fallback на scalar (битый JSON и тексты вида «[blocker] …» не теряются). Паттерн действует для ВСЕХ array-полей инструментов — закрывай симметрично при добавлении array-поля.

## Пример

VL-183: `manageChecklist` case 'add' парсит JSON-строку `text` и батч-пушит каждый элемент отдельным критерием; тесты v11.test.mjs покрывают JSON-строку, реальный массив и scalar-фолбэк.

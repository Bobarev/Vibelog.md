## Проблема
В auto-runner раннер считал фазу успешной только по `run.exitCode === 0`. Агент мог честно отработать фазу (процесс завершился с кодом 0), но не вызвать `finishPhase` — статус задачи остался прежним. В этом случае раннер снова выбирал ту же фазу и запускал её заново → бесконечный цикл одной фазы без прогресса.

## Решение
Трактуй фазу как успешную только при двух условиях: `exitCode === 0` **И** фактическая смена статуса задачи после завершения (до/после — сравнить статус через `getTask`). Нет смены статуса → считай отсутствием прогресса и уходи в обычный retry-путь; исчерпание попыток → `failed` + уведомление в чат. Guard срабатывает на любой «тихой» неудаче, где процесс завершился нолём, но задача не сдвинулась.

## Пример
```ts
const before = getTask(cwd, id)?.status;
const run = await startTaskPhase(...); // onExit
const after = getTask(cwd, id)?.status;
const success = run.exitCode === 0 && before !== after;
if (!success) { /* retry или failed по nextFailureAction */ }
```
Применимо к любому оркестратору, где «процесс отработал» ≠ «эффект достигнут»: успех проверяй по наблюдаемому состоянию системы, а не по коду завершения.

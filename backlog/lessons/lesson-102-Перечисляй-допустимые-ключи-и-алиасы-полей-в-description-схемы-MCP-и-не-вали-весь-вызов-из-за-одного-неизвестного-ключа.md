## Проблема

`backlog_view_task` с `fields: ["id","title","status","phase","notes"]` возвращал только `{"error":"Неизвестные поля: phase, notes..."}`. Схема (то, что видит модель) не перечисляла допустимые ключи и алиасы, поэтому имена угадывались; один неверный ключ из пяти обнулял весь вызов — холостой ход и повтор с другим набором.

## Решение

1. В `description` параметра-списка перечислить канонические ключи и поддерживаемые алиасы (`notes` → `implementationNotes`, `plan` → `implementationPlan`, `ac` → `acceptanceCriteria`, `dod` → `definitionOfDone`) и прямо сказать, что неизвестный ключ вызов не прерывает.
2. Неизвестные ключи не бросают ошибку: остальные запрошенные поля возвращаются, а в ответ добавляется `_warning` со списком проигнорированных имён, fuzzy-подсказкой ближайших (Левенштейн + вхождение подстроки, до 3 кандидатов) и полным списком допустимых.
3. Алиасы применять только после точного совпадения с реальным ключом — иначе алиас перебьёт поле, которое позже добавили в `Task`.
4. Один общий хелпер (`resolveFields` + `pickFields`/`pickFieldsList`) для одиночных и списковых инструментов; реестр допустимых ключей — рантайм `Object.keys(task)`, статический список в схеме лишь подсказка (lesson-32).

## Пример

`fields: ['id','notes','phase']` → `{ id: 'VL-260', implementationNotes: '...', _warning: 'Неизвестные поля проигнорированы: phase. Ближайшие: implementationPlan, implementationNotes.' }` — один вызов вместо двух, агент сразу видит правильное имя.

## Проблема

Фаза Close VL-359 упала (код 1) уже после того, как успела переписать `backlog/docs/doc-8-MCP-справочник-Vibelogmd.md` (722 → 489 строк: переименованы все H2/H3, вырезаны разделы `backlog_finish_phase`, `milestone_remove`, `lesson_audit`-подробности). Правка осталась незакоммиченной в главном репозитории. Следующий ран Close увидел её в `git status` как «остаток документации задачи» и по инструкции («закоммить остатки одним docs-коммитом») закоммитил бы недоделанный черновик чужого рана — с потерей 233 строк справочника.

## Решение

Незакоммиченный diff в `backlog/docs/` — не автоматически «мой остаток». Перед коммитом документации:

1. Сверь `git log --oneline -3 -- <файл>`: если последний коммит файла — не эта задача, правка пришла извне.
2. Прочитай `git diff -- <файл>` и оцени характер: переписывание структуры (переименование заголовков, удаление разделов) — это черновик упавшей фазы, а не дополнение по существу задачи.
3. Такой diff откати (`git checkout -- <файл>`) и внеси минимальную правку по существу задачи сам — аддитивную, в существующем стиле.
4. В отчётном комментарии фазы зафиксируй, что чужой черновик откачен.

## Пример

VL-359: `git diff` по doc-8 показал `-## Задачи` / `+## Инструменты` и удаление `### backlog_finish_phase` — структурная переделка, к задаче (guard-ответы веб-чата в контракте `outcome`) отношения не имеющая. Diff откачен, вместо него добавлен один буллет `extra` в раздел «Контракт ответа write-инструментов»; сборка и полный прогон (190 файлов, 3548 passed) зелёные.

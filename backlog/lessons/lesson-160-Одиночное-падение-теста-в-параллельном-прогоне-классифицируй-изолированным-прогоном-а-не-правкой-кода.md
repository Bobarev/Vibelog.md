## Проблема

В полном прогоне `pnpm test` (fileParallelism, isolate:false) падает один тест, который изолированно проходит. Соблазн — править `src/` в фазе Close или считать релиз заблокированным.

## Решение

1. Прогнать упавший файл изолированно (`npx vitest run <файл> -t "<имя теста>"`).
2. Прошёл — это флак от параллельной интерференции (общий tmp-каталог, файловая гонка, общий worker без isolate), а не регрессия.
3. Повторить полный прогон **один раз** с фиксацией причины повтора в отчётном комментарии фазы.
4. В фазе Close код не править: подтверждённая регрессия — аварийный итог `aborted: true`, исправление — новой фазой Code.

## Пример

VL-290: `src/web/orchestrator.test.mjs:1342` («файл задачи закоммичен после записи token_usage», VL-277) упал в первом полном прогоне; изолированно — passed; два следующих полных прогона подряд зелёные → публикация релиза 1.11.0 продолжена без правок кода.

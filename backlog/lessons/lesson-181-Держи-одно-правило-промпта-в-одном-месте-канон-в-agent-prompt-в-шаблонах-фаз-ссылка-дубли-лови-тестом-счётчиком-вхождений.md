## Проблема

Промпты фаз накапливали одно и то же правило в 2–4 местах одного шаблона и в нескольких шаблонах дословно («пакетное чтение», «никогда git add -A», «README — витрина», лимит tool-calls). Модель читает повтор как шум и перестаёт различать важное: после сокращения `phase-spec` примерно на 30% поведение фазы заметно улучшилось, а остальные шаблоны не ревизовались (VL-312).

## Решение

Одна каноническая формулировка правила — в общем промпте (`templates/agent-prompt.md`), в шаблонах фаз — максимум одна ссылка на неё. Структура шаблона фазы: «Что делает фаза» → короткий «Порядок» → «Экономия ходов» → отдельные «Запреты» → «Финал». Дубли ловить механически: тест-сторож считает вхождения ключевых подстрок и падает при превышении лимита, а также проверяет обязательные маркеры шагов у каждого шаблона.

## Пример

`src/web/phase-prompt.test.mjs`, блок VL-312: карта `RULE_MAX_IN_PHASE = { 'Пакетное чтение': 1, 'git add -A': 0, ... }` — счётчик вхождений в каждом `templates/phases/*.md`, плюс `REQUIRED_MARKERS` (Порядок, Запреты, `backlog_finish_phase`, отчёт) с проверкой длины шаблона. Ревизия VL-312 дала −115 строк и −2840 символов на 13 шаблонах без потери шагов и запретов.

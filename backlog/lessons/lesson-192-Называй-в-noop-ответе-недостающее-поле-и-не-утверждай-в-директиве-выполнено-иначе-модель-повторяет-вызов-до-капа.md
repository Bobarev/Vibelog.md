## Проблема

Close VL-318 (сессия `agent-1793712738536`) упал кодом 1: модель 4 раза дословно повторила `lesson_update {id, title, tags, sourceTasks, verifiedBy}` без `content`, каждый раз получая noop, кап `MAX_NOOP_REPEATS_PER_RUN` сработал → `fail()` → откат статуса → авто-resume с нуля. Рецидив семейства VL-303/304/309/310/318.

Три причины, каждая из которых по отдельности достаточна:

1. **noop-ответ не называл, чего не хватает.** `applied` перечислял переданные поля (`title/tags/source_tasks/verified_by`) — читается как «применено», а отсутствующее в вызове `content` не упоминалось нигде. Модели неоткуда узнать, что тело урока пустое.
2. **Директива повтора сообщала неверный факт.** `noopRepeatDirective` говорила «вызов с теми же аргументами уже был выполнен и ничего не изменил» — но вызов не исполнялся ни разу, с первого раза ответ был noop. Модель читала «не выполнен» и повторяла.
3. **Шаблон фазы создавал сущность с пустым обязательным по смыслу полем.** `lesson_create {"title","tags","sourceTasks"}` без `content`, а `createLessonFile` писал `input.content || ''` — так родился `lesson-191` с `body: ""`.

## Решение

- **Ack-ответ обязан называть недостающее.** Аддитивные `missing: SkippedField[]` + `hint` в ack-контракте (`ackNoopDetailed`/`ackErrorDetailed`), `applied` — строго переданные поля. Если у сущности есть незаполненное обязательное по смыслу поле, noop-ответ без `missing` — дефект.
- **Директива повтора описывает факт, а не догадку:** «вызов `<имя>` НЕ исполнен (поля уже такие). Повтор ничего не изменит. Следующий шаг: прочитай состояние или смени аргумент — добавь отсутствующее поле». Держи текст < 400 байт (инвариант VL-310).
- **Отказ вместо noop, когда менять нечего, а поле пустое:** `content` не передан и тело пустое → `ackErrorDetailed` (`ok:false`, **без** `noop:true`) — сигнатура не попадает в `noopSignatures`, повтор исполняется заново и снова отдаёт текст ошибки, цикл «noop → кап → fail → авто-resume» рвётся.
- **Шаблон фазы передаёт все обязательные по смыслу поля** (`content` со структурой Проблема/Решение/Пример), а `createLessonFile` подставляет скелет при пустом `content` — CLI без `-d` тоже даёт осмысленный урок. Инвариант закреплён тестом `src/web/phase-prompt.test.mjs`.
- **Накопленный мусор виден механически:** finding `empty_body` в `lesson_audit` (детерминированно, без порогов).

## Пример

```json
// было: модель видит «применено» и повторяет
{ "ok": false, "noop": true, "applied": { "title": "…", "tags": ["…"] } }

// стало: назван пропуск и следующий шаг
{ "ok": false, "noop": true, "applied": { "title": "…" },
  "missing": [{ "field": "content", "reason": "тело урока пустое — не заполнено" }],
  "hint": "Передай непустой content (Проблема / Решение / Пример)" }
```

Проверка при ревью: если noop-ответ не позволяет модели понять, ЧТО добавить, — это не «мягкий сигнал», а генератор дословных повторов.

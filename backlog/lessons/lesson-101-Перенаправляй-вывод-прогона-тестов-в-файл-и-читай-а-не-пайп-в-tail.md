## Проблема
`pnpm test 2>&1 | tail -25` показывает хвост вывода, но `$?` отражает exit code `tail`, а не самого прогона. В фазе Close это даёт ложное «exit code: 0» при упавших тестах — или наоборот маскирует причину повторного прогона в отчёте. Отдельная ловушка: `pnpm test` проекта — это последовательная `&&`-цепочка из трёх команд (`build`, `vitest run --exclude src/web/static.test.mjs`, затем `vitest run src/web/static.test.mjs`), поэтому `tail` показывает только хвост последней, короткой стадии (static.test.mjs, 8 тестов, ~1 с) и полностью скрывает сводку основного прогона: видно «Test Files 1 passed», а судить о полном прогоне по этому хвосту нельзя. Ловушка устойчиво повторяется: пайп выглядит как «прогон прошёл», а exit code 0 относится к tail.

## Решение
Перенаправляй весь вывод в файл, печатай `$?` сразу после команды и грепни сводку. Файл лога держи в `.vibelog/tmp/` (VL-329: временные файлы не пишутся в корень проекта), а не в `/tmp` — инструменты песочницы в проектном каталоге отвергают абсолютные пути вне проекта. Сводку основной части прогона греппай по `Test Files|Tests ` с конца файла или читай read_file с диапазоном, а не через `tail`: у `pnpm test` несколько команд vitest, и хвост принадлежит последней, короткой. Признак успеха основного прогона без явной сводки — отсутствие в логе строк `Failed Tests`/`FAIL`. Если пайп уже сделан и сводка сомнительна — не повторяй прогон вслепую: сверь состав `test`-скрипта (`node -e "require('./package.json').scripts"`) и выведи `$?` каждой стадии отдельно.

## Пример
VL-242: `env -u VIBELOG_CWD pnpm test > .vibelog-test.log 2>&1; echo "EXIT=$?"` → `EXIT=0`, `Test Files 88 passed`.

VL-393 (Close): `pnpm test 2>&1 | tail -18` показал только `static.test.mjs 8 passed` — сводка основного прогона (203 файла) осталась за пределами хвоста; вердикт пришлось подтверждать тем, что вторая команда `&&`-цепочки вообще выполнилась (первый vitest и build вернули 0). Правильно: `pnpm test > .vibelog/tmp/run.log 2>&1; echo "EXIT=$?"; grep -E "Test Files|Tests " .vibelog/tmp/run.log`.

VL-426 (Close): та же ловушка повторена несмотря на урок — `pnpm test 2>&1 | tail -15` дал «Test Files 1 passed» за 1 с; вердикт спасён только тем, что `pnpm test` в package.json — `&&`-цепочка из трёх стадий и exit code 0 означает зелёность всех трёх.

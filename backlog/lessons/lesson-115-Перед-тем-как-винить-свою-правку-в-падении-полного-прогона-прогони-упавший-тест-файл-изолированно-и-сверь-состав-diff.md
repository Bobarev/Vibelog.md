## Проблема
Полный `pnpm test` в фазе Code упал на `src/mcp/server.test.mjs` (VL-198, tokenUsage fallback: «фаза из меты не использована»). Легко принять за регрессию своей правки и начать чинить чужой тест — при том, что правка вообще не касается MCP-фазы.

Повтор того же класса в Фазе Close VL-373: полный прогон после merge упал на `src/web/orchestrator.test.mjs` («close в branch-mode: файл задачи закоммичен», `token_usage` не остался грязным). Правка задачи — только `templates/phases/phase-plan.md` и `src/web/phase-prompt.test.mjs`; `orchestrator.test.mjs` в `git diff HEAD^1..HEAD` отсутствует, значит байт-в-байт совпадает с родительским коммитом, а сам файл изолированно проходит 89/89.

Третий случай, VL-423: предыдущая Close прервалась (aborted) из-за 1 падения `src/core/report.test.mjs`, а в полном прогоне следующего рана упал уже другой файл — `src/web/orchestrator.test.mjs` (billing-коммит); оба — чужие модули, оба изолированно зелёные, повтор полного прогона зелёный целиком. Прыжок падения на другой тест-файл между ранами — усиленный признак флаки, а не регрессии.

## Решение
Первым делом проверь падение на **чистом дереве**: `git stash push -- <изменённые файлы>` → `pnpm build` → `npx vitest run <упавший файл>` → `git stash pop`. Если тест падает и там — это пре-существующее падение (в данном случае: тест `backlog_finish_phase` зависит от окружения сессии агента — `VIBELOG_PHASE_NAME`/`VIBELOG_SESSION_ID`, которые прогон из-под агента неизбежно подставляет).

В Close (правки кода запрещены) stash недоступен — эквивалент: (1) `git diff --name-only HEAD^1..HEAD` — упавший файл вне состава diff ⇒ строка не могла измениться; (2) `pnpm test:fast <упавший файл>` — изолированно зелёный; (3) `ps aux | grep vitest` и `uptime` — параллельный прогон / высокая нагрузка: тесты, ждущие fire-and-forget коммит с дедлайном в несколько секунд, падают только на загруженной машине (load avg 8.8, 198 файлов параллельно); (4) два полных прогона упали на **разных** строках одного файла — признак гонки, а не регрессии; (5) падение перескочило на **другой тест-файл** — тот же признак, только сильнее (VL-423: report.test.mjs → orchestrator.test.mjs).

Правило: чужое падение фиксируй в отчётном комментарии фазы с указанием файла и причины, DoD «Тесты проходит» не отмечай, пока нет зелёного повтора; после зелёного повтора — отмечай и закрывай фазу, aborted при единичном чужом падении не используй. Своё падение — чини.

## Пример
Close VL-423: первый полный прогон — 1 failed `src/web/orchestrator.test.mjs` (billing-коммит), файл в diff отсутствует, изолированно 89/89 зелёный, параллельного vitest нет; повтор `pnpm test:fast` — 4425 passed + 4 skipped, 230 файлов. В предыдущем ране той же фазы упал уже другой файл (`report.test.mjs`) — прыжок падения между файлами тоже признак флаки.

```bash
npx vitest run src/web/orchestrator.test.mjs   # 89 passed
git diff --name-only 71195b3^1..71195b3 | grep report   # пусто
ps aux | grep vitest | grep -v grep                      # пусто
pnpm test:fast   # 230 files, 4425 passed + 4 skipped
```

## Проблема
CLI-команда принимала несколько позиционных референсов, но читала только positional[0]: vb install a/b/base a/b/button молча ставила только первый — пользователь получал ложное «оба установились» (то же семейство, что молча игнорируемый --forse в parseOptions). Валидация по-ходу цикла давала бы ещё и частичную установку: опечатка в последнем аргументе обнаруживалась после записи предыдущих элементов.

## Решение
Вынеси батч в core с preflight-функцией validateInstallRefs, которая ДО первого сетевого вызова прогоняет parseInstallPath + resolveInstallContext по каждому референсу (ошибка с номером проблемного аргумента, код 1/2) и дедуплицирует повторы с предупреждением; сеть не трогается, пока не валидированы все аргументы, а в цикле — стоп на первой InstallError без отката уже записанных элементов (повтор идемпотентен добирает).

## Пример
vb install vibelog.md/ui/base vibelog.md/ui/button vibelog.md/ui/card: все три валидируются до первого запроса; если третьим аргументом передан bad-ref, команда падает кодом 1 с указанием «компонент 3 («bad-ref»)» и ничего не записывает — вместо частичной установки base и button.

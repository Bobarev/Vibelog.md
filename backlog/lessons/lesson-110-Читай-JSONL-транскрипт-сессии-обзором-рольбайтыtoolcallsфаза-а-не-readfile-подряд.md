## Проблема

Разбор `.vibelog/agent-sessions/*.jsonl` читался `read_file` подряд: в транскрипте строки до 22–23 КБ (промпт фазы с блоком задачи дублируется в каждом resume), а лимит tool-вывода 8 КБ → за вызов видно 1–2 строки из 238. Вопросы «какая фаза была активна», «сколько ранов», «где гигантская строка» стоили ~15 чтений.

## Решение

1. Для транскрипта сначала бери обзор: `agent_session_outline` (агент) / `vibelog session outline <id>` (CLI) — по строке индекс, роль, байты, число и имена `tool_calls`, маркер рана/фазы, сниппет 80 символов; шапка называет строку максимального размера, отдельная секция «Раны» — фаза → строка.
2. Только после обзора читай целевые строки обычным `read_file "файл:N-M"`.
3. Неизменный блок «Задача (подставлена автоматически):» при `--resume` не дублируй: сравнивай хэш блока с прошлыми user-сообщениями и вставляй ссылку («без изменений с рана N»). Это одновременно уменьшает строки jsonl и сохраняет модели контекст.

## Пример

```
Сессия agent-smoke: 5 строк, 2 ранов, макс. строка 48.9 KB (строка 3)
Раны: 1 → стр. 2 (plan), 2 → стр. 5 (resume)
    2  user          141 B  ран 1 → plan  Ты — автоматический исполнитель …
    3  assistant   48.9 KB  xxxxx…
```

Обзор 5 строк (в т.ч. 50-КБ строки) — 519 байт вместо нескольких вызовов на 8 КБ.

Реализация: `src/agent/session-outline.ts` (`buildSessionOutline`/`formatSessionOutline`, чистый модуль, реюз маркеров из `session-summary.ts`), `src/agent/prompt-dedup.ts` (`findTaskBlock`/`hashBlock`/`dedupeResumePrompt`), подключение — `src/agent/tools.ts` (8-й локальный инструмент) и `src/agent/cli.ts` (resume).

## Проблема

Атомарная установка нескольких файлов: если писать их по одному прямо на целевые места, сбой на последнем (нет прав, диск полон) оставляет проект в полуустановленном состоянии — часть файлов новая, часть старая, lock не соответствует диску. Откат невозможен, если старые версии файлов не сохранены.

## Решение

Порядок «temp → бэкап → rename → lock»: (1) temp-каталог создавать **внутри проекта** (`.vibelog/tmp/install-<pid>-<rand>/`), а не в `os.tmpdir()` — `rename` между разными файловыми системами падает с `EXDEV`; (2) сначала записать все файлы в temp, сохраняя относительную структуру; (3) перед первым перемещением скопировать существующие целевые файлы в `temp/backup/`; (4) переместить все файлы; (5) только после успешных перемещений писать lock. Сбой на любом шаге — восстановить цели из бэкапа, удалить temp в `finally`, lock не трогать.

## Пример

VL-337, `applyInstallPlan` в `src/core/install.ts`. Тест на атомарность: элемент из трёх файлов, третий целевой каталог `chmod 555` → ни один файл не появился, ранее существовавший файл восстановлен из бэкапа побайтово, `installed.lock.json` не изменён, temp-каталог удалён. Проверять надо именно «файл был — стал прежним», а не только «файла нет»: без бэкапа откат частичных перемещений невозможен.

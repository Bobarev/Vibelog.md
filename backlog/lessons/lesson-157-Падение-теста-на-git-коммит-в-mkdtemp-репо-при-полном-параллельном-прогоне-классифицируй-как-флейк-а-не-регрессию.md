## Проблема

Полный `pnpm test` в фазе Close (VL-286, VL-284) падает на `src/web/orchestrator.test.mjs` — тест «файл задачи закоммичен после записи token_usage (VL-277/VL-93)»: `assert.match(log, /docs\(task\): VL-93/)` получает «init», то есть git-коммит в mkdtemp-репозитории не создался. Тот же файл изолированно зелёный (84/84), diff задачи `src/web/orchestrator*` не касается.

## Решение

Классифицируй до любых выводов о регрессии, в таком порядке:
1. Прогони упавший файл изолированно (`npx vitest run src/web/orchestrator.test.mjs`) — зелёный значит интерференция параллельного прогона.
2. Проверь, не идёт ли параллельный `vitest` в другом worktree: `ps aux | grep -c "[v]itest"` (>1 — чужая нагрузка на git/файловую систему).
3. Сверь с родительским коммитом `HEAD^1` при сомнении (см. lesson-115).

Признак флейка именно здесь: падает только тест, завязанный на реальный `git commit` в mkdtemp-репо, одиночный прогон зелёный, diff задачи не затрагивает ни `src/web/orchestrator.ts`, ни обвязку git. Тогда в отчётном комментарии фазы фиксируй файл, тест и причину («флейк параллельного прогона, изолированный прогон N/N зелёный») — на этом классификация закончена.

## Пример (VL-286)

Первый полный прогон: 2401 passed, 2 failed (оба в `src/web/orchestrator.test.mjs` на git-коммит-ассертах). Изолированно: 84/84 зелёные. `ps aux | grep -c "[v]itest"` → 2 (второй worktree). Повторный полный прогон — 2402 passed, 1 failed (тот же класс). Не регрессия задачи.

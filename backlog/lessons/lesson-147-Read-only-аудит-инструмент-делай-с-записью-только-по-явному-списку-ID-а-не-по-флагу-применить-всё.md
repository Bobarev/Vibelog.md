## Проблема

Аудит-инструмент, который находит проблемы, провоцирует соблазн дать ему флаг «исправить всё найденное» (`--fix`). Но находка аудита — это гипотеза: битый путь мог исчезнуть из-за рефакторинга, а сам урок остаётся верным по смыслу; протухший урок может быть свежим по факту. Массовая автозапись по эвристике необратимо портит корпус и превращает аудит в источник ошибок.

## Решение

Аудит по умолчанию **read-only** и возвращает структурированный отчёт (findings + сводка). Запись — только по явному перечислению ID (`verified: [...]`, `needsReview: [...]`, `--verify id,…`) и в двух видах: «проверено» (`last_verified=today`, `verified_by=auto`) и «на пересмотр» (новый статус `needs-review` вместо разрушительного `outdated`). Флага «записать всё найденное» не заводи — решение по каждой находке принимает человек или отдельная задача.

## Пример

VL-279: `lesson_audit` и `vibelog lesson audit` пишут только `--verify`/`--needs-review` с ID; `write: true` влияет лишь на файл отчёта `backlog/lessons/AUDIT.md`, не на сами уроки. Находка `missing_path` по умолчанию остаётся только finding'ом — открытый вопрос задачи решился именно так.

## Проблема
Команда печатает идентификатор в усечённом виде и тут же подсказывает команду-потребитель, а та сравнивает идентификатор точно — скопированный из вывода аргумент не работает, и пользователь обязан лезть в файл за полным значением. Второй разрез того же класса: аргумент принимается в произвольной форме (проверяется только непустота), и опечатка молча записывается в данные.

## Решение
Если вывод одной команды служит подсказкой для следующей, проверяй пару «что печатаю — что принимаю» на живом прогоне: печатаемый сокращённый id должен приниматься потребителем как префикс (git-стиль, минимум 4 символа, регистронезависимо), неоднозначный префикс — ошибка со списком кандидатов, а не выбор первого. Функции, которым нужна строгая идентичность (дедуп/идемпотентность), передавай явный режим `{ exact: true }`, чтобы расширение поиска не поменяло их семантику. Аргументы вида `--as <PREFIX>-<число>` валидируй регуляркой с нормализацией и примером в тексте ошибки, и явно документируй в коде, что существование связанной сущности проверить нельзя (нет доступа к чужому backlog) — иначе следующий агент попытается «доделать» непроверяемое.

## Пример
VL-388: `pull` печатал `report_id.slice(0, 8)` и подсказывал `ack <report_id>`, а `findReportById` сравнивал id точно (`===`) — скопированный из вывода id давал «не найден». Фикс: поиск по префиксу (>=4, регистронезависимо), неоднозначность — ошибка со списком кандидатов; `writeReport` оставлен с `{ exact: true }`, чтобы префикс не начал склеивать отчёты.

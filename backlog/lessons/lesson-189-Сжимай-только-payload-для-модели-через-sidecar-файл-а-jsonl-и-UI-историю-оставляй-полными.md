## Проблема

При сжатии контекста чата/агента соблазн «почистить» историю целиком: обрезать jsonl, убрать сообщения из ленты UI. Это ломает воспроизводимость, отладку и доверие пользователя — он видит, что его сообщения исчезли.

## Решение

Сжимай ТОЛЬКО payload, уходящий в модель. Источник истины (jsonl сессии, лента UI) остаётся полным всегда. Точка сжатия хранится отдельно — sidecar-файлом рядом с тредом (`<threadId>.compaction.json`: `fromIndex`, способ, дата, оценка токенов). Сброс сжатия = удаление sidecar, payload снова полный. В UI показывай плашку «контекст сжат: в модель уходит с N-го сообщения», чтобы пользователь понимал, что модель видит не всё.

## Пример

VL-314: `/trim` (детерминированное усечение) и `/compact` (LLM-саммари) в веб-чате пишут sidecar `backlog/chat/<threadId>.compaction.json`; `buildWireMessages` собирает payload с учётом точки, а `GET /api/chat/threads/:id` отдаёт поле `compaction` для плашки. Тот же паттерн уже был у агента фаз (VL-122) — переиспользован, а не изобретён заново.

## Почему не иначе

Инкрементальное саммари (prior-summary + только новые сообщения) переписывает саммари, а не накапливает старые — иначе промпт растёт линейно и сжатие теряет смысл. Орфан-гард (хвост не может начинаться с `tool` без парного `assistant(tool_calls)`) должен жить в ОДНОМ общем модуле (`src/agent/compact.ts`), иначе копии расходятся и провайдер отбивает payload.

## Проблема

doc-2 описывал патч-скрипты на Node.js как **единственный** путь правки файлов репозитория. Политика отменена (нативные `read_file`/`edit`/`write_file` стали основным путём), но документ остался в `backlog/docs/` с прежним текстом и прежним заголовком.

В Close-фазе VL-304 (сессия `.vibelog/agent-sessions/agent-1793634687751.jsonl`, строки 116–120) модель сделала `ls backlog/docs/`, увидела doc-2, прочитала его — и написала 12-килобайтный патч-скрипт `.vibelog/vl304-docs-patch.mjs`, которым правила `backlog/docs/doc-8`, `doc-10`, `README.md` и `CHANGELOG.md` **в обход MCP-инструментов**. Модель действовала строго по документации: документ был написан императивно и лежал в общем доступе как действующая политика.

## Решение

Отменяя политику, **не оставляй документ с прежним текстом** — переписывай его в заглушку с явной шапкой «⚠️ Документ устарел (дата, VL-N)»:

1. шапка-предупреждение в первых строках;
2. действующая политика вместо отменённой (что делать сейчас);
3. почему отменено (какой дефект среды исчез);
4. триггер пересмотра (задача + сессия + строки — чтобы контекст не потерялся);
5. что осталось полезным (сокращённый список), чтобы знание не потерялось;
6. изменить `title` и добавить тег `outdated` — по названию видно статус ещё до чтения.

Ссылки на отменённый документ из других документов помечать инлайном: «`doc-2` — **устарел, см. VL-N**».

## Пример

`backlog/docs/doc-2` → заголовок «Устарело: патч-скрипты на Node.js (см. VL-124)», шапка «⚠️ Документ устарел (2026-11-02, VL-124)», раздел «Действующая политика» (нативные инструменты; патч-скрипт — только для массовых/многоякорных/многофайловых правок), «Почему отменено» (qwen code: `read_file` падал с `params must be required property`; у vb-агента дефекта нет), «Триггер пересмотра» (VL-304), сохранённые 8 ловушек патч-скрипта, правило «файлы `backlog/` — только MCP-инструментами».

Проверка после правки: `grep -rn "Проверка якоря" templates/ src/` → пусто; `grep -n "устарел" backlog/docs/doc-*.md` → пометка на месте.

## Важно

Правки самих `backlog/docs/doc-*` — только через MCP `document_update` (не `edit`/`write_file` в worktree-копию и не скриптом): worktree-копия backlog попадает не в то хранилище и теряется при `worktree remove`. Изменённые через MCP документы остаются незакоммиченными в главном репозитории — это ловит `git status` в Close (см. lesson-165).

## Проблема

`vb install` (VL-338) должен запускать пакетный менеджер проекта (`pnpm add …`), но `spawnSync(..., { stdio: 'inherit' })` в тестах неудобен: подменять `child_process` целиком хрупко, а реальный запуск pnpm в тесте медленный и зависит от окружения. Отдельно: цепочка «зависимости реестра + сам элемент» должна быть атомарной, иначе сбой на зависимости оставляет частично установленный родитель.

## Решение

Запуск внешней команды выносить в функцию с инъекцией раннера (`runner` — параметр с дефолтом `spawnSync`), а не мокать модуль `child_process`. Для многошаговой установки — одна транзакция на всю цепочку: один temp-каталог, стейджинг всех файлов всех планов, затем бэкап, затем перемещения, один `writeLock` в конце; сбой откатывает все перемещения.

## Пример

`src/core/install-deps.ts`: `runDepsInstall(pm, packages, { cwd, runner = spawnSync })` — тест передаёт фейковый раннер и проверяет аргументы команды без реального pnpm; `ENOENT` от раннера → fallback на `npm` с предупреждением. `src/core/install.ts`: `applyInstallChain(plans)` — тест «сбой на зависимости» проверяет, что ни один файл родителя не появился и lock не изменился.

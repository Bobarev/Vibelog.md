## Проблема

Merge ветки задачи в master упал на конфликте в `src/mcp/tool-outcome-trace.test.mjs` — таблице-реестре `TRACE`, где обе стороны переписали одну и ту же структуру: master держал короткий формат `'VL-303': ['P1']` (ID → массив свойств P1..P5), ветка — расширенный `'VL-303': [['src/mcp/write-ack.test.mjs', 'AC1: …']]` (ID → пары «файл, имя теста»). Выбор «своей» версии наугад ломает тест: ниже в том же файле код обходит `Object.values(TRACE).flat()` и проверяет `id in PROPERTIES`, то есть ожидает именно массив строк-свойств.

Второй типовой случай — конфликт в блоке импортов/хелперов тест-файла: master и ветка добавили РАЗНЫЕ импорты и разные top-level константы (`clearPhaseEnv` из VL-374 против `INBOX_DIR`/`testSpawnEnv`/`cliPath` из VL-375). Здесь «выбрать сторону» нельзя вообще: обе стороны нужны, потому что ниже в файле есть кейсы, требующие и того, и другого.

## Решение

При разрешении конфликта в тест-файле не выбирай версию по принципу «наша/их» — прочитай код-потребитель ниже в файле (обход таблицы, `assert`-ы, счётчик `Object.keys(TRACE).length`, использование импортированных символов) и оставь формат, который этот код принимает. Второй сигнал — соседние задачи: если master-версия согласована с `PROPERTIES`/`PARTIAL_SCENARIOS` в других файлах, расширенный формат ветки потребовал бы править и их.

Для конфликта в импортах правило другое: **объединяй, а не выбирай** — оставь оба набора импортов и обе группы top-level констант, если каждый символ используется ниже в файле (проверяется `grep -n '<символ>' <файл>`). Дублирующийся импорт из одного модуля склеивается в одну строку (`import { clearPhaseEnv, testSpawnEnv } from '../test-env.mjs'`).

## Пример

VL-369: конфликт `TRACE` разрешён в формате HEAD (`'VL-303': ['P1']`), потому что строки 78-93 того же файла делают `for (const [task, ids] of Object.entries(TRACE))` и `new Set(Object.values(TRACE).flat())` — пары `[файл, тест]` дали бы `unknown` для каждого элемента. Проверка: `npx vitest run src/mcp/tool-outcome-trace.test.mjs` — 4 теста зелёные.

VL-375: конфликт в `src/mcp/upstream-tool.test.mjs` (строки 27-35) — master добавил `import { clearPhaseEnv } from '../test-env.mjs'` (VL-374), ветка — `import { INBOX_DIR } from '../../dist/core/upstream-git.js'`, `testSpawnEnv` и `__dirname`/`cliPath`. Оставлены оба набора, импорты из `test-env.mjs` склеены в один; проверка — `grep -n 'clearPhaseEnv\|testSpawnEnv\|INBOX_DIR\|cliPath'` показывает использование всех четырёх ниже в файле, прогон файла зелёный.

## Проблема

В VL-201 guard `checkShellCommandInProject` начал позиционный анализ («первый не-флаг-аргумент grep/rg/sed — паттерн, а не путь»), но токенизатор выбрасывал разделители shell (`|`, `&&`, `;`, `(`) молча — границы команд были для него невидимы. В `git log | grep "/auto"` токен `/auto` относился бы к `git` («команда сегмента» стартовала от `git`), и паттерн-позиция не сработала бы: слэш-паттерн снова отклонился бы как абсолютный путь.

## Решение

Как только валидация токена зависит от его позиции/контекста, токенизатор обязан сохранять разделители как отдельные токены (`[;|&()<>]` — последней альтернативой regex, после кавычечных и escape-веток), а цикл — сбрасывать контекст команды (`commandName`, флаг занятости паттерна, ожидание значения флага) на каждом разделителе. Сброс нужен и на `(`/`)`: подкоманда `(grep …)` — новая команда.

## Пример

```ts
// токенизатор: разделители — отдельные токены
command.match(/"(?:\\.|[^"\\])*"|'(?:\\.|[^'\\])*'|(?:\\[^\s]|[^\s;|&()<>])+|[;|&()<>]/g)
// цикл: на разделителе — полный сброс контекста
if (/^[;|&()<>]$/.test(token)) { commandName = null; patternSupplied = false; expect = 'none'; continue; }
```

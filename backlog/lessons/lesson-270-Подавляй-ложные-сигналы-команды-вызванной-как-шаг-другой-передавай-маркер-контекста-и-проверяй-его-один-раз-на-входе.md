## Проблема
Команда, которую вызывает другая команда как один из шагов (`vb init` внутри `vb create` через `postCreate`), ведёт себя как самостоятельная: проверяет предпосылки, которых ещё нет (каталог вне git — хотя `git init` идёт следующим шагом), и печатает финальную подсказку «Дальше: …», которая дублирует итог родительской команды. Пользователь видит «✗ Проект не в git: .env с секретами не защищён» за две строки до «✓ Git: репозиторий инициализирован» и читает это как ошибку, хотя установка прошла.

## Решение
Передавай от родителя к дочернему запуску маркер контекста в окружении (рядом с прочими env-каналами) и подавляй в дочерней команде именно те сигналы, которые станут неверными к концу родительской операции: предупреждения о недостающих предпосылках, финальные подсказки «что делать дальше» и сообщения «Пропущено:» для файлов, которые и не должны перезаписываться. Маркер держи в одном модуле констант, чтобы обе стороны импортировали имя, а не строковый литерал; проверяй его один раз на входе; поведение без маркера не меняй ни на строку.

## Пример
`vb create` пишет `VIBELOG_CREATE=1` (или `'no-git'` при `--no-git`) в env `postCreate`; `readCreateContext(env)` в `init` даёт три решения: подавить предупреждение VL-348 (git появится шагом позже), подавить финальную подсказку «Дальше: vibelog task create …», заменить `Пропущено: AGENTS.md (уже существует)` на нейтральное «AGENTS.md из шаблона сохранён». Значение одной переменной несёт смысл («git будет» / «git не будет»), а не два независимых флага: при `--no-git` предупреждение обязано остаться — репозитория правда не будет. Прямой `vb init` без маркера печатает всё как раньше (регрессионные тесты на оба пути).

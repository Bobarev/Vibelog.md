## Анализ (Фаза 2)

**Причина запросов macOS-доступа.** Журнал сессии `.vibelog/agent-sessions/agent-1791237959516.jsonl` показывает, что агент vb выполнил shell-команды `ls -la ~` и `find ~ -maxdepth 3 -iname '*vibelog*'`. Доступ к `~/Desktop`, `~/Pictures` (Фото), `~/Library/Calendar` (Календарь) — это защищённые macOS TCC-каталоги; первое обращение порождает системные запросы «Терминал запрашивает доступ к Фото/Календарю/Файлам на рабочем столе».

**Дыра в коде.** В `src/agent/tools.ts` функция `resolveInProject` (строки 76–94) ограничивает папкой проекта только аргументы-пути файловых инструментов (read_file/write_file/edit/grep) и аргумент `cwd` инструмента `run_shell_command`. Сама строка команды НЕ валидируется: `makeRunShellCommand` (строки 217–297) передаёт её в `execFile('/bin/bash', ['-lc', command])` как есть. Правило «работай только внутри cwd» в system-prompt (`src/agent/system-prompt.ts:34`) — только инструкция для модели, без технического ограничения.

**Как у qwen.** Оркестратор (`src/web/orchestrator.ts`, spawnQwenRun) запускает обоих агентов с `cwd` = корень проекта. У qwen инструментальная среда (файловые инструменты + промпт шаблонов фаз) держит его в workspace; у vb файловые инструменты ограничены, а shell — нет. Решение: ввести для vb ограничение на уровне исполнения (валидация команды в инструменте), а не только на уровне промпта.

## План реализации

### 1. `src/agent/tools.ts`
- Добавить экспортируемую функцию `checkShellCommandInProject(command: string, cwd: string): ValidateResult` (null — ок, иначе текст для модели). Проверки:
  1. Токен `~` или `~/...` в позиции пути (regex `(^|[\s;|&=(])~([/\s;|&)]|$)`) → отказ.
  2. `$HOME` / `${HOME}` → отказ.
  3. Токенизация команды (split по пробелам/кавычкам/`;|&()<>`): для токенов, начинающихся с `/`, — `resolve(token)` и проверка `relative(cwd, abs)` не начинается с `..`; для относительных токенов с сегментами `..` — аналогично (резолв от cwd). Отклонить, если путь вне проекта.
  4. Текст отказа (русский): «Команда отклонена: обращение к путям вне проекта (<путь>). Разрешены только пути внутри <cwd>».
- В `makeRunShellCommand`: перед `execFile` вызвать проверку; при отказе — `resolvePromise(текст)` без запуска (путь уже обработан: сначала валидация `cwd`-аргумента, затем команды).
- Обновить JSDoc/шапку файла (shell-команды теперь тоже валидируются).

### 2. `src/agent/system-prompt.ts`
- Усилить правило границ (~строка 34): явный запрет `~`, `$HOME`, абсолютных путей вне cwd в shell-командах; указать, что такие команды инструмент отклоняет.

### 3. `src/agent/tools.test.mjs`
- Новые тесты `checkShellCommandInProject`:
  - отклоняет: `ls ~`, `ls -la ~`, `find ~ -maxdepth 3`, `cat $HOME/.zshrc`, `ls /Users/bob/Desktop`, `sed -n '1,5p' /etc/hosts`, `cd ../.. && ls`, `ls ../../..`;
  - пропускает: `ls -la`, `git status`, `sed -n '1,10p' src/agent/tools.ts`, `grep -rn foo src`, `ls node_modules`, `cd src && ls`.
- Тест handler'а: `run_shell_command` с `ls ~` возвращает текст отказа, процесс не запускается.

### 4. `docs/agent.md`
- В разделе ограничений (~строки 204–205) описать: команда shell-инструмента валидируется на обращения вне проекта (`~`, `$HOME`, абсолютные/`..`-пути вне cwd) — с примером текста отказа.

## Порядок действий

## Проверка
- `pnpm build` (tsc strict, без ошибок).
- `pnpm test` (build + `node --test src`) — все тесты, включая новые, зелёные.
- Смоук: `node bin/vibelog-agent.mjs "выполни ls ~"` с тестовым LLM-ключом — агент должен получить текст отказа инструмента, а не выполнить команду (в тестах покрыто на уровне handler'а).

## Риски
- **Лексическая проверка неполна:** динамическое построение путей (`$(echo ~/x)`, конкатенация, base64) обходит фильтр — остаточный риск; минимизируется правилом в system-prompt. Полный sandbox (macOS `sandbox-exec`/seatbelt) вне scope: платформенный, хрупкий на новых macOS.
- **False positives:** токены вида `https://...` не начинаются с `/` — ок; команды с легитимными путями вне проекта (например `cat /etc/hosts`) будут отклонены — это соответствует цели задачи.
- Параллельные фазы, затрагивающие tools.ts/system-prompt.ts (VL-90/93) — при merge-конфликтах согласовывать с их изменениями.

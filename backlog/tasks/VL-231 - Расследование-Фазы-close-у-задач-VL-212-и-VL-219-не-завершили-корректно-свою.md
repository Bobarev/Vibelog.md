Фаза Investigate выполнена (worktree/главный каталог — чтение). Документ: doc-18 «Расследование VL-231: close-фаза прерывалась и не завершала работу, но статус Done выставлялся».
**Механизм (2 независимых канала):**
1. `finalizePhaseStatus` (`src/core/phase-transient.ts:191-235`) определяет успех фазы по `exitCode === 0 && !is_error`, а exit code ран задаётся как `is_error ? 1 : 0` (`src/agent/cli.ts:782`). Аварийные ветки промпта close («конфликт merge / чужой MERGE_HEAD / красные тесты — отчитайся и завершай») заканчиваются обычным текстом → exit 0 → success-ветка применяет `Review --close--> Done` (`src/core/workflow.ts:91`) молча, без комментария. Свидетельство: close VL-219 в 23:43 отчиталась «Статус и DoD не изменены» (`agent-1793306581810.jsonl`, 11 строк), а стартовавшая в 00:01 следующая фаза Comment уже видела в подставленном блоке «ID: VL-219; … статус: Done» (`agent-1793307529535.jsonl`, промпт строки 1).
2. `backlog_finish_phase` (`src/mcp/tools.ts:1156`) валидирует статус только по `config.statuses` — ни фаза вызывающего, ни переход workflow не проверяются, поэтому служебная фаза `comment` (по контракту статус не меняет, `SERVICE_PHASES`) выставила финальный Done у VL-219 (`backlog_finish_phase {status: Done, dodChecks: [1,2,3]}`, строка 208 того же jsonl). Там же фактически и была выполнена вся работа Close (merge `c589e7c`, docs `30e7690`, `34148a1`) — после ручного «Разреши конфликт и сделай коммит».
**VL-212:** close #1 не смогла начать merge (чужой незавершённый merge VL-219, `MERGE_HEAD 532c590`, `UU CHANGELOG.md`), аварийная ветка промпта сработала корректно (отчёт без status), но затем пользовательское сообщение «VL-219 закончила работу. Заверши фазу.» продолжило уже прерванную фазу, и финал (`status: Done`, `dodChecks: [1,2,3]`) пришёл на строке 126 (`agent-1793306598743.jsonl`) — вне штатного жизненного цикла, при полном прогоне `24 failed` в `src/agent/llm.test.mjs`.
**Повторяемость:** детерминированная, не флак — любая close-фаза, ушедшая в аварийную ветку, получает Done. Кандидат на тот же исход уже есть: close VL-230 стартовала в 22:02 (`phase-in-progress.json`), т.е. риск актуален.
**Предложено задач: 6.** №1 — Close: не применять produces_status, если фаза отчиталась о прерывании (`aborted`-флаг + откат в finalizePhaseStatus, High); №2 — backlog_finish_phase: отклонять смену статуса фазой, которой workflow не разрешает переход (High); №3 — сериализовать Close в главном репо: предпроверка MERGE_HEAD + очередь (Medium); №4 — промпты close: аварийные ветки оформляют провал явным сигналом (Medium); №5 — не ставить терминальный статус при невыполненном DoD (Medium); №6 — уборка worktree только из главного cwd, запрет удаления собственного cwd (Low).
Статус: Review.

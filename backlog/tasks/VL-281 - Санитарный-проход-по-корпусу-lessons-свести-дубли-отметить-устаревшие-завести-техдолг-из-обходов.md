## Контекст

В `backlog/lessons/` 141 файл, и никто ни разу не проводил ревизию. Даже после появления аудита (VL-279) и классификации workaround'ов (VL-280) корпус остаётся грязным: дубли, устаревшие утверждения о коде, обходы, зафиксированные как норма поведения, ссылки на давно исчезнувшие пути и задачи.

Эта задача — **разовый санитарный проход** по текущему корпусу, который приводит его в состояние, дальше поддерживаемое аудитом. Без неё инструменты из VL-279/280 просто описывают долг, не уменьшая его.

## Объём

1. Прогнать `lesson audit` по всему корпусу, зафиксировать исходный отчёт (AUDIT.md) и цифры «до».
2. Свести дубли через `supersede` (не удалением файлов — история урока нужна): известный пример — три урока про «не вставляй ID задач VL-N в templates» (lesson-107, lesson-140, lesson-29); остальные пары — по отчёту аудита.
3. Пометить `outdated` уроки, чьё утверждение больше не верно, с честной причиной в теле.
4. Для подтверждённых `kind=workaround` — завести задачи техдолга (VL-280), связать с уроками, в теле урока — ссылка «устранение: VL-N».
5. Дать итоговую разбивку статусов «до/после» и список принятых решений по дублям.
6. Зафиксировать в документации процесс поддержки: как часто гонять аудит, что значит `needs-review`, как оформлять supersede/outdated, куда идут workaround'ы.

## Границы

- Ничего не удаляем: только `superseded`/`outdated` с причинами — корпус остаётся полным.
- Решения по каждому уроку принимает агент под проверку человеком (это чистка смыслов, а не механика): уроки, где причина неясна, уходят в `needs-review`, а не в `outdated` наугад.
- Объём — только lessons; правки кода из workaround'ов делаются в отдельных задачах техдолга, а не здесь.

## Зависимость

Требует VL-279 (аудит, статус `needs-review`, `kind`) и VL-280 (создание задач техдолга из workaround).

## Открытые вопросы

- Делать проход одним ран-ом или разбить по тематическим блокам (тесты, web, agent, worktree, billing) — при 141 уроке один ран может съесть контекст; вероятно, разбить на несколько запусков по tags.
- Что делать с уроками, чей source-task закрыт, а `linked_tasks` пуст, но урок полезен: обновить `last_verified` (verified_by=agent) — да, но требует содержательной проверки, а не простановки даты.

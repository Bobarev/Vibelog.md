## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
## Контекст

MCP-инструмент `git_commit` (`src/mcp/git-commit.ts`, VL-311) отказывает с ошибкой «в индексе уже есть посторонние файлы», если среди staged-файлов есть пути с не-ASCII символами (кириллица в именах задач/уроков/референсов). Коммит невозможен, хотя индекс корректен; повтор с теми же путями даёт ту же ошибку — выйти из состояния нельзя.

## Воспроизведение

1. В репозитории с `backlog/` создать файл с кириллическим именем, например `backlog/lessons/lesson-1-Коммить-сгенерированный-артефакт-вместе-с-тестом-checkSync-иначе-реестр-отстаёт-от-исходников.md`.
2. `git add` его — файл попадает в индекс.
3. Вызвать `git_commit` с `paths`, включающими этот файл.
4. Ошибка: `git_commit: в индексе уже есть посторонние файлы: "backlog/lessons/lesson-1-\320\232\320\276\320\274..."`.
5. Повтор с теми же путями — та же ошибка.

## Причина (подтверждена в коде)

- `src/mcp/git-commit.ts:88` — локальный `git()` запускает git БЕЗ `-c core.quotepath=false`, в отличие от `src/core/git.ts:225` и `src/core/status.ts:257`, где флаг уже стоит (урок VL-88: без него кириллица приходит в octal-экранировании).
- `src/mcp/git-commit.ts:240` — `stagingOutsiders()` сравнивает сырые строки `git diff --cached --name-only` с `relPaths` как обычные строки: `"\320\232..."` ≠ `К...` → файл считается «посторонним».
- `src/mcp/git-commit.ts:322-334` — проверка «индекс должен содержать ровно переданные пути» слишком строгая: `git commit -m` коммитит весь индекс, поэтому проверка защищает от захвата чужой работы, но ломает сценарий «закоммитить всё, что не закоммичено» и не даёт выйти из состояния.

## Ожидаемое поведение

- Пути из `git diff --cached` нормализуются (unquote C-style escaped строк и/или вызов git с `-c core.quotepath=false`) перед сравнением с `paths`.
- Сравнение устойчиво к юникоду и к вариантам разделителей путей.
- Ошибка «посторонние файлы в индексе» либо не срабатывает на файлы, которые просто уже staged и не входят в `paths` (они не мешают коммиту явными путями), либо содержит понятную подсказку и не блокирует повтор.

## Затронутые файлы

`src/mcp/git-commit.ts`, `src/mcp/git-commit.test.mjs` (существующий кейс «AC2: посторонний staged-файл → отказ», строки ~241-253, придётся переписать под новое поведение), `CHANGELOG.md`, doc-8.

## Implementation Plan
<!-- SECTION:PLAN:BEGIN -->
## План

### 1. Нормализация путей из индекса (`src/mcp/git-commit.ts`)

- Локальный `git()` (строка ~88) — добавить `-c core.quotepath=false` в начало argv для ВСЕХ вызовов инструмента (единый стиль с `src/core/git.ts:225` и `src/core/status.ts:257`). Это снимает octal-экранирование кириллицы в `git diff --cached --name-only`, `git add`, `git log`.
- Дополнительно (защита от чужого `core.quotepath=true` в конфиге репозитория/`-c` в env): вынести чистую функцию `unquoteGitPath(raw: string): string` — снимает обрамляющие `"` и раскрывает C-style escape-последовательности (`\ooo` octal → байты → UTF-8, `\n`, `\t`, `\\`, `\"`, `\a\b\f\v\r`). Применять её к каждой строке вывода `git diff --cached --name-only` ПЕРЕД сравнением. Функция чистая → тестируется без git.
- `stagingOutsiders()` (строка ~240): нормализовать обе стороны одинаково — `unquoteGitPath` + `replaceAll('\\','/')` + снятие ведущего `./`; сравнение по нормализованным значениям, в сообщение об ошибке выводить уже нормализованные (читаемые) пути.

### 2. Поведение при staged-файлах вне `paths`

Сейчас `git commit -m` коммитит ВЕСЬ индекс, поэтому проверка «ровно переданные пути» защищает от захвата чужой работы. Два варианта:

- **A (предпочтительный):** коммитить только переданные пути — `git commit --only -- <paths>` (или `--only` + pathspec). Тогда staged-файлы вне `paths` физически не попадают в коммит, проверка `stagingOutsiders` становится не нужна как блокер: оставить её как `applied.warnings` («в индексе остались staged-файлы вне paths — они не вошли в коммит»). Это чинит и сценарий «закоммитить всё, что не закоммичено» без ругани.
- **B (минимальный):** оставить отказ, но с actionable-текстом: перечислить нормализованные пути + готовое исправление (`retryWith`/`hint` по паттерну VL-353) и не блокировать повтор.

Решить в фазе Plan/Code по результатам проверки: `git commit --only -- <paths>` при пустом индексе по этим путям ведёт себя как noop — проверить, что `ackNoop` (VL-310) сохраняется.

### 3. Тесты (`src/mcp/git-commit.test.mjs`)

- Регрессия: файл `backlog/lessons/lesson-1-Коммить-сгенерированный-артефакт-....md` (кириллица) → `git add` → `commitFiles(root, { paths: [этот файл], message })` → `ok: true`, коммит создан, `applied.paths` содержит читаемый путь. Явно выставить `git config core.quotepath true` в тестовом репозитории, чтобы кейс не зависел от глобального конфига.
- Юнит-тесты `unquoteGitPath`: `"\320\232..."` → `К...`, путь с пробелами в кавычках, путь с `\"` и `\\`, обычный ASCII-путь без кавычек (идемпотентность).
- Сценарий «staged-файл вне paths»: переписать существующий кейс `AC2: посторонний staged-файл → отказ` (строки ~241-253) под выбранное поведение (A: коммит создан, чужой файл остался staged и не в коммите; B: отказ с читаемыми путями).
- Проверить, что при `core.quotepath=false` поведение не изменилось (второй прогон того же кейса с явным `false`).

### 4. Документация

- `CHANGELOG.md` — запись о фиксе.
- doc-8 (§`git_commit`) — уточнить: пути нормализуются, staged-файлы вне `paths` не блокируют коммит (или блокируют с actionable-ошибкой — по итогу реализации).

`pnpm build && pnpm test` (полный прогон, AGENTS.md), плюс ручная проверка на репозитории с кириллическим именем файла.

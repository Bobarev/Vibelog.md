## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
УТОЧНЕНИЕ 2026-10-13: массив индексов УЖЕ поддержан кодом (схема anyOf array + tools.ts:614 Array.isArray) — расширение пришло с фиксом VL-120. Остаётся: строка «all», тесты (массив/scalar/all), документирование.

После фикса VL-120 (валидация индекса) модель продолжает слать manage_ac/manage_dod массив-строку "[1, 2, 3]" — она хочет отметить НЕСКОЛЬКО пунктов за один вызов (сессия VL-121 code, 2026-10-12: пары падающих вызовов ac+dod подряд; ошибки теперь понятные, но вызов всё равно падает и тратит ход на повтор). Отсутствующая функция, а не ошибка валидации.

Решение: батч-отметка — index принимает: целое число (как сейчас), строку-число, МАССИВ индексов [1,2,3] (отметить/снять все перечисленные), строку «all» (все пункты списка). Результат: «Отмечено пунктов: 3 (1, 2, 3)». Валидация: каждый элемент массива — целое >=1 и <= длины; иначе ошибка со списком доступных (сохранить подсказку VL-120). Учить батчу и add (списки создаются добавлением — batch-add уже работает через массив строк, симметрия).

## Контекст (проверено по коду)

- `parseChecklistIndexes` (src/mcp/tools.ts:613-637) уже принимает массив ИНДЕКСОВ (VL-15/VL-120) — но НЕ строку `"[1, 2, 3]"` и НЕ `"all"`: обе дают «Неверный индекс» (проверено прогоном на dist).
- Схема `index` (src/mcp/tools.ts:161, :175) — anyOf number|string|array; строка-массив формально проходит схему, но падает в рантайме.
- **Расхождение с описанием**: batch-add УЖЕ НЕ работает — `manage_ac {action:'add', text:['B1','B2']}` создаёт ОДИН критерий «B1,B2» (проверено: в файл уходит `- [ ] #1 B1,B2`). Нужно реализовать, а не только «учить».
- Формат ответа сейчас: check/uncheck → `Отмечены критерии #1, #3` (tools.ts:674-677); scalar-тест server.test.mjs:226 ассертит `includes('#2')` — менять scalar-формат нельзя (AC2).

## Изменения по шагам

### Шаг 1. src/mcp/tools.ts — parseChecklistIndexes (строки 613-637)

Расширить нормализацию `raw` ПЕРЕД существующей цикловой валидацией (сохранить подсказку VL-120 нетронутой):

1. `raw` — строка, `trim() === 'all'` → вернуть `[1..listLength]`. Если `listLength === 0` — существующий `hint` («текущих пунктов чек-листа: 0»).
2. `raw` — строка, после trim начинается с `[` → `JSON.parse` в try/catch; успех → `raw = parsedArray` и прогнать каждый элемент через СУЩЕСТВУЮЩУЮ валидацию (целое/строка-число, 1..length); catch → бросить `hint(raw)` с оригинальной строкой (не пропускать SyntaxError наружу).
3. Дедупликация индексов после сбора (`[...new Set(indexes)]`) — иначе `remove` с `[2,2]` сдвинет позиции дважды.

Сигнатура не меняется; ошибки NaN/дробь/пустая строка — ровно те же тексты (AC3).

### Шаг 2. src/mcp/tools.ts — manageChecklist, case 'add' (строки 661-666)

- `Array.isArray(args.text)` → валидация: каждый элемент — непустая строка (иначе `Error('Для action=add text — строка или массив непустых строк.')`); push каждого как `{text, checked:false}`.
- Scalar-ветка — без изменений.
- Ответ батча: `Добавлено критериев: 2 (B1, B2)`; scalar-ответ `Добавлен критерий #N: ...` не трогать.
- Схема `text` (строки 160, 174): `anyOf: [{type:'string'}, {type:'array', items:{type:'string'}}]`, description += «или массив строк — несколько за один вызов».

### Шаг 3. src/mcp/tools.ts — case check/uncheck/remove (строки 668-690)

- Батч = `Array.isArray(args.index)` ИЛИ строка-массив ИЛИ `'all'` (после нормализации — флаг: например, `const batch = Array.isArray(args.index) || (typeof args.index==='string' && !/^\d+$/.test(args.index.trim()))`). Scalar (`2`, `"2"`) → флаг false.
- Scalar → СТАРЫЙ формат без изменений: `Отмечены критерии #2` / `Сняты отметки с критериев #2` / `Удалены критерии #2` (AC2, регрессия server.test.mjs:226).
- Батч → новый формат (по образцу из задачи):
  - check: `Отмечено пунктов: 3 (1, 2, 3)`
  - uncheck: `Снято пунктов: 3 (1, 2, 3)`
  - remove: `Удалено пунктов: 3 (1, 2, 3)`

### Шаг 4. Схемы index (строки 161, 175) — «учим» модель

description обоих инструментов: `Номер(а) критерия с 1; строка-число ("3"); массив [1,2,3] — несколько; "all" — все пункты; строка-массив "[1, 2]" тоже принимается`.

### Шаг 5. Тесты

**src/mcp/server.test.mjs** (после блока VL-120, ~строка 229) — один новый `it` «батч-отметка (VL-135)» в стиле существующего JSON-RPC-теста (create → add ×3 → вызовы):
- `check index:[1,3]` → успех, ответ содержит `Отмечено пунктов: 2 (1, 3)`, оба пункта отмечены (проверка list);
- `check index:'all'` → `Отмечено пунктов: 3 (1, 2, 3)`;
- `check index:'[2]'` (строка-массив) → успех;
- прежний scalar `index:'2'` → ответ содержит `#2` (существующий тест VL-120 не трогать — он остаётся);
- `index:'NaN'` и `index:'2.5'` → isError, тексты `целое число, начиная с 1` и `пунктов чек-листа:` на месте (AC3).

**src/agent/mcp-client.test.mjs** (после it VL-120, ~строка 100):
- `manage_dod {action:'check', index:[1,2]}` → текст без `Ошибка MCP-инструмента`, содержит `Отмечено пунктов: 2`;
- `index:'all'` → `Отмечено пунктов:`;
- batch-add: `{action:'add', text:['D1','D2']}` → 2 пункта в list.

**src/cli/batch-checklist.test.mjs** (секция MCP, ~136):
- `text:['X1','X2']` → 2 отдельных критерия (регресс-ловилка на слияние «X1,X2»);
- `check index:'all'` на 3 пунктах → все checked;
- `check index:'[1, 3]'` (строка-массив) → 1 и 3 checked;
- `remove index:[2,2]` (дубль) → оставшиеся корректны (дедуп).

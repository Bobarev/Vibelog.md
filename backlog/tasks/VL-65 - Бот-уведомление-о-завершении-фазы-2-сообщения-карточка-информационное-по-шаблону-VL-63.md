## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
Сейчас после завершения фазы (spec, plan, code, comment, close) в чат Telegram-бота приходят 3 сообщения: 1) статус («✅ Фаза Comment завершена»), 2) сырой консольный лог qwen в code-блоке (JSON --output-format), 3) карточка задачи. JSON-вывод нечитаем, а статус дублирует строку фазы в карточке.

Цель (VL-63): сократить до 2 сообщений:
1. Карточка задачи (sendTaskView, как и была — с учётом свежих изменений файла задачи).
2. Информационное сообщение из последней JSON-строки result (парсер из VL-64) по шаблону:
   Фаза <phase>: завершена (код 0)
   %result%
   Входные токены: %input_tokens%
   Сгенерированные токены: %output_tokens%
   Кэш токены: %cache_read_input_tokens%
   Всего токенов: %total_tokens%
   Общее время: %duration_ms% (api: %duration_api_ms%)
   Количество запросов: %num_turns%
   %session_id%

Что сделать:
1. src/bot/formatting.ts: чистая функция formatPhaseResult(run: PhaseRun): string — рендер шаблона (MarkdownV2-экранирование динамических полей, обрезка %result% до лимита ~3000 символов); фолбэк без run.result: «Фаза X: ошибка (код N)» + обрезанный logTail.
2. src/bot/handlers.ts: в пяти onExit-колбэках (comment/spec/plan/code/close) вместо head+tail+карточка отправлять: карточка → информационное сообщение; вынести общий хелпер уведомления, чтобы формат менялся в одном месте.
3. Юнит-тесты formatPhaseResult в src/bot/formatting.test.mjs; pnpm test зелёный.
4. CHANGELOG.md и docs/user-guide.md — новое поведение уведомлений.

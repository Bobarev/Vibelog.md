## Контекст

Аудит набора тестов класса «модель крутится на повторах» показал: значительная часть тестов закрепляет **снимок текущего состояния**, а не требование. Это делает любую правку текста ломающей и вынуждает все фиксы идти аддитивно — что и породило накопленную совместимость с ошибочными решениями (см. VL-369).

### Найдено при аудите

**1. Шесть независимых копий порога размера директивы.**

| Файл:строка | Проверка |
|---|---|
| `src/agent/loop.test.mjs:734` | `byteLength(text) < 1200` |
| `src/agent/loop.test.mjs:823` | `String(d.content).length < 400` |
| `src/agent/loop.test.mjs:2638` | `byteLength(d) < 400` |
| `src/agent/loop.test.mjs:2801` | `byteLength(directive) < 400` |
| `src/agent/loop.test.mjs:2862` | `byteLength(content) < 400` |
| `src/agent/loop.test.mjs:2972` | `byteLength(content) < 400` |
| `src/agent/repeat-tracker-vl357.test.mjs:79` | `byteLength(text) < 400` («инвариант VL-310») |

Порог поднимался с 400 до 1200 в одной точке, но остался в шести других. Это тест на **размер строки**, а не на отсутствие зацикливания.

**2. Проверки точных формулировок.**

- `src/agent/loop.test.mjs:729` — `assert.match(text, /НЕ исполнен/)`. Перефразировка директивы → красный тест при неизменном поведении.
- `src/agent/loop.test.mjs:738` — `assert.deepEqual(parsed.missing, [{field:'content', reason:'тело урока пустое — не заполнено'}])`. **Точная строка** `reason`.
- `src/agent/auto-report.test.mjs:72-76, 159-161` — `/авто-отчёт/`, `/AC отмечено: 0 из 2/`, `/Статус не изменён/`, `/backlog_finish_phase с dodOverride или aborted/`.

**3. Регресс-тесты на сессии вместо инвариантов.** Около 20 тестов названы по ID сессии (`agent-1794045441657`, `agent-1794053090709`, `agent-1794064942811`, `agent-1794067677112`, `agent-1793712738536`, `agent-1794054631174`, `agent-1794050949211`, `agent-1794047067509`, `agent-1793705489953`, `agent-1793720932286`, `agent-1793637056809`, `agent-1793634687751`, `agent-1793647788155`, `agent-1794052713009`). Каждый воспроизводит конкретный транскрипт. Свойство «тупик в необязательном шаге не роняет ран» не проверяется ни одним тестом — проверяются 20 частных случаев.

**4. Матрица `src/mcp/tool-outcome-trace.test.mjs:33-80`** — таблица `задача → [файл, подстрока имени it(...)]` для 14 задач, ~30 пар. Тест падает, если тест **переименовали**. Идея верная (защита от молчаливой потери регресса), но матрица закрепляет имена, а не смысл: при рефакторинге придётся править 30 строк вручную.

## Что заменить

**Порог размера → свойство «не растёт линейно».** Вместо абсолютного числа байт: директива на десятом повторе не длиннее, чем на первом (с допуском). Это проверяет то, что действительно важно — payload не раздувается по числу повторов, — и не ломается при изменении формулировки.

**Точные строки → машиночитаемые поля.** Вместо `/НЕ исполнен/` — проверка `outcome === 'noop'` в JSON. Вместо `deepEqual` на точный `reason` — проверка `field === 'content'` без текста. Текст остаётся свободным.

**Регрессы на сессии → инварианты.** Вместо 20 тестов «эта сессия больше не падает» — набор свойств:
- вызов с корректными аргументами на неполной сущности не даёт отказа (см. VL-369);
- серия повторов не роняет ран, если работа в ране выполнена;
- отказ всегда несёт готовый следующий шаг;
- необязательный шаг фазы (уроки) не роняет фазу.

Конкретные сессии остаются как **примеры** внутри этих тестов, но проверяется свойство, а не транскрипт.

**Матрица трассировки** — сохранить как идею, но привязать к **свойствам**, а не к именам тестов: «для каждого свойства класса есть хотя бы один тест». Либо оставить как есть и обновить при рефакторинге осознанно.

## Что НЕ трогать

- `src/mcp/write-ack.test.mjs:368` — проверка `linked_tasks` **чтением файла**, а не по `applied`. Образец правильного теста.
- `src/agent/loop-repeat-cap.test.mjs` — проверяет исход рана, а не текст.

## Дефект, вскрытый при проверке плана (важно)

Первая редакция плана предлагала заменить `/Статус не изменён/` на `reportFields(text).get('Статус') === 'Review'`. **Это утверждение упало бы.** Фактический код `src/agent/auto-report.ts:100`:

```ts
let report = buildAutoReport(task, {
  status: nextStatus ?? task.status,   // ← ЦЕЛЕВОЙ статус ('Done')
  ...
});
if (terminalAtRisk) {
  effectiveStatus = prevStatus;
  report += `\n${gate.reason ?? ''}`;   // ← сюда дописывается «Статус не изменён…»
}
```

Строка `Статус:` в отчёте содержит **целевой** статус (`Done`), а фактический (`Review`) появляется только внутри `gate.reason`. То есть отчёт одновременно говорит «Статус: Done» и «Статус не изменён… Задача оставлена в «Review»» — **противоречие внутри одного комментария**, которое сейчас ничем не проверяется.

**Решение в этой задаче:** тест фиксирует текущее поведение (`Статус` = `Done`) и **не** закрепляет противоречие как желаемое — в комментарии теста явно написано, что это известный дефект, а исправление вынесено отдельной задачей (создаётся по итогам этой задачи, не входит в её объём).

## Граница пересмотра (осознанное ограничение)

Прозаические утверждения в 13 регресс-тестах по ID сессий (`assert.match(res.result, /повторила вызов/)`, `/Кап повторов исчерпан/`, `/Работа в ране выполнена/` и подобные) **остаются без изменений**. Причина: эти тесты проверяют **исход рана** (`is_error`, `result`, `progress`) и дополнительно — что текст результата содержит маркер причины; маркер нужен человеку, читающему лог, и его изменение — осознанное решение, а не рефакторинг. Замена их на машиночитаемые поля потребовала бы менять формат `LoopResult.result`, что выходит за объём этой задачи.

Итог: цель «текст остаётся свободным» достигается в 6 местах (директивы и отчёт), а не во всём наборе. Это записано явно, чтобы не создавать иллюзию полного пересмотра.

### 1. `src/agent/directive-size-property.test.mjs` (новый, P5)

Импорт: `runLoop` из `dist/agent/loop.js`, `DIRECTIVE_MAX_BYTES` и `retryDirective` из `dist/agent/repeat-tracker.js`. Локальные `fakeLlm`/`USER_MSG` — копия из `loop.test.mjs:20-63` (тест-файлы самодостаточны, как в `loop-repeat-cap.test.mjs`).

Хелпер (в этом же файле):

```js
const TOLERANCE_BYTES = 64; // директивы одной серии могут отличаться на длину имени инструмента
function assertNotGrowing(directives) {
  assert.ok(directives.length >= 3, `серия состоялась (${directives.length})`);
  const sizes = directives.map((d) => Buffer.byteLength(String(d), 'utf8'));
  const first = sizes[0];
  const last = sizes[sizes.length - 1];
  assert.ok(last <= first + TOLERANCE_BYTES, `директива не растёт по числу повторов: ${first} → ${last}`);
  for (const size of sizes) {
    assert.ok(size <= 2 * DIRECTIVE_MAX_BYTES, `директива ограничена (${size} ≤ ${2 * DIRECTIVE_MAX_BYTES})`);
  }
}
```

Три теста (имена начинаются с `P5:`):
1. `P5: серия noop-повторов — директивы не растут` — 10 повторов `backlog_update_task` с noop-ack; собрать tool-сообщения с `noop_repeat`/`applied_repeat`, вызвать `assertNotGrowing`. **Оговорка в комментарии теста:** директивы noop-повторов собираются из `serializeAck` с постоянным набором полей, поэтому «не растёт» здесь выполняется почти по построению — тест страхует от появления переменной части (например, накопления истории), но основную нагрузку несут тесты 2 и 3.
2. `P5: серия повторов ackError с длинным текстом ошибки — директивы не растут` — заглушка `git_commit` с `error` из 12 повторов фразы + `hint`; собрать директивы с `Loop detection`, `assertNotGrowing`. **Основной тест свойства.**
3. `P5: retryDirective с длинными кириллическими путями укладывается в DIRECTIVE_MAX_BYTES` — прямой вызов `retryDirective('git_commit', {allowForeign:true}, {paths:[3 длинных кириллических пути], message})`; `assert.ok(byteLength(text) <= DIRECTIVE_MAX_BYTES)`. **Проверяет реальное усечение** (`retryDirective` перебирает варианты, `src/agent/repeat-tracker.ts:750`).

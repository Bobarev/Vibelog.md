## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
Сквозная приёмка прошла успешно (`✓ Установлены компоненты: vibelog.md/ui/button`, git-коммит создан), но вывод содержал **два ложных сигнала**, которые вводят в заблуждение.

**Симптом из прогона:**
```
ℹ Пропущено: AGENTS.md (уже существует)
...
Git: нет (проект не в git)
✗ Проект не в git: .env с секретами не защищён. Запустите vibelog init --git-init или git init вручную
ℹ Дальше: vibelog task create "Название" — или vibelog browser для веб-интерфейса

Проект создан: /Users/bob/Dev/@vb/tmp/accept/testapp
...
✓ Git: репозиторий инициализирован, создан первый коммит
```

**Проблема 1 — ложное предупреждение про git.** `postCreate` вызывает `vb init --components --yes` **до** того, как `vb create` выполнит `git init` (шаг 13 против шага 11 в doc-25 §4.1). `init` видит каталог вне git и печатает предупреждение VL-348 «Проект не в git: .env с секретами не защищён» — хотя через две строки `vb create` создаст репозиторий. Пользователь читает это как ошибку.

**Проблема 2 — дубль финальной подсказки.** `init` печатает «Дальше: vibelog task create "Название" — или vibelog browser», и сразу за ним `vb create` печатает свой итог «Проект создан: …», «Дальше: cd …». Две разные «дальнейшие инструкции» подряд.

Плюс мелочь из того же лога: `ℹ Пропущено: AGENTS.md (уже существует)` — шаблон содержит `AGENTS.md`, и `init` честно сообщает, что не перезаписал его. Это правильно, но в контексте создания проекта читается как «что-то не сделалось».

**Корень.** `postCreate` — это шаг **внутри** более крупной операции (`vb create`), но `init` об этом не знает и ведёт себя как самостоятельная команда: проверяет предпосылки, которых ещё нет, и даёт советы, которые сейчас неуместны.

**Решение.** `vb create` передаёт в окружение `postCreate` маркер (рядом с `VIBELOG_BIN` из VL-386). `init` при наличии маркера:
- подавляет предупреждение «проект не в git», если `vb create` сам сделает git (то есть не `--no-git`);
- подавляет финальную подсказку «Дальше: …» — её печатает `vb create`;
- предупреждение «AGENTS.md уже существует» превращает в `skipped` без акцента либо оставляет, но без «Пропущено:» в контексте создания.

**Границы.** Не меняет поведение `init` при прямом запуске пользователем. Не трогает логику git-шага (VL-348) и `postCreate` (VL-386, VL-339) — только вывод и подавление ложных предупреждений.

**Связанное:** VL-348 (предупреждение «проект не в git»), VL-386 (`VIBELOG_BIN` и env для `postCreate` — маркер передаётся тем же способом), VL-339 (`vb create`, порядок шагов), doc-25 §4.1 шаги 11–13 (порядок `postCreate` → компоненты → `git init`).

## Implementation Plan
<!-- SECTION:PLAN:BEGIN -->
**Файлы.** `src/core/create.ts` (передать маркер), `src/cli/commands/init.ts` (подавление по маркеру), `src/cli/commands/init.test.mjs` / `create.test.mjs` (тесты).

**Шаг 1. Маркер в окружении.**

1. В `createProject` рядом с `VIBELOG_BIN` (VL-386) добавить `VIBELOG_CREATE: '1'` — передаётся в env того же `depsRunner` при вызове `postCreate`.
2. Если `options.noGit === true` — вместо `'1'` положить `VIBELOG_CREATE_NO_GIT: '1'` (или `VIBELOG_CREATE: 'no-git'`). Выбрать одну форму и задокументировать в комментарии: значение несёт смысл «git будет / git не будет».
3. Константы вынести в `src/core/env-markers.ts` (новый, 10 строк) или в `create.ts` с экспортом — чтобы `init.ts` импортировал имя, а не строковый литерал в двух местах.

**Шаг 2. Подавление в init.**

4. В `runInit` прочитать маркер один раз: `const fromCreate = process.env.VIBELOG_CREATE !== undefined;`
5. Предупреждение про git (строка ~195) печатать только если `!fromCreate` **или** маркер говорит `no-git`. То есть:
   ```ts
   const gitWillBeInitialized = process.env.VIBELOG_CREATE === '1';
   if (!state.git.inRepo && answers.git?.init !== true && !gitWillBeInitialized) { … }
   ```
6. Финальную подсказку `printInfo('Дальше: vibelog task create …')` не печатать при `fromCreate` — её место занимает итоговый блок `vb create`.
7. Строку `Режим: fresh. Агенты: нет. Шлюз: —…` (`formatSetupLog`) при `fromCreate` можно оставить: это полезная сводка. Решить по вкусу, но не убирать — она не ложная.
8. `Пропущено: AGENTS.md (уже существует)` — при `fromCreate` печатать как `printInfo('AGENTS.md из шаблона сохранён')`, а не через общий цикл «Пропущено:». Проверить, откуда идёт запись в `result.skipped` (шаг записи AGENTS.md в `applySetup`), и добавить условие.

**Шаг 3. Тесты.**

9. `create.test.mjs`: перехватить `depsRunner`, проверить `env.VIBELOG_CREATE === '1'` при обычном запуске и `no-git`-значение при `--no-git`.
10. `init.test.mjs` (spawn или прямой вызов с env): `VIBELOG_CREATE=1` + каталог вне git → предупреждения «проект не в git» нет, подсказки «Дальше: vibelog task create» нет, код 0.
11. Без маркера, каталог вне git → предупреждение есть (регрессия VL-348 не сломана).
12. `VIBELOG_CREATE=no-git` (или соответствующее значение) → предупреждение **есть**.
13. `--git-init` явно + маркер → предупреждения нет (как и раньше).

**Шаг 4. Документация.**

14. doc-25 §4.1 шаг 11: «`postCreate` вызывается с `VIBELOG_BIN` и `VIBELOG_CREATE`; `init` в этом режиме не печатает предупреждение о git и финальную подсказку».
15. `CHANGELOG.md`.

**Риски.**
- Маркер — глобальная переменная окружения: если `postCreate` запустит что-то ещё, оно унаследует флаг. Риск мал (внутри `postCreate` вызывается `vb init`), но стоит назвать переменную специфично (`VIBELOG_CREATE`) и не полагаться на неё в других местах.
- Пользователь может сам выставить `VIBELOG_CREATE=1` и удивиться отсутствию предупреждения. Приемлемо: переменная недокументирована, внутренняя.
- Подавление подсказки «Дальше» в `init` ломает существующие spawn-тесты, которые проверяют её наличие (VL-206/VL-320) — проверить и поправить условия тестов (они запускают `init` без маркера, так что должны остаться зелёными).
- `result.skipped` для AGENTS.md формируется в `applySetup`, а не в CLI — правка пойдёт в ядро; при этом прямой запуск `init` в проекте с существующим `AGENTS.md` должен по-прежнему сообщать о пропуске.

**Проверка.** `pnpm typecheck && pnpm test`; вручную — `vibelog create testapp --template vibelog.md/templates/svelte-minimal` в пустом каталоге: в выводе нет «Проект не в git», нет двух «Дальше», завершается `✓ Git: репозиторий инициализирован, создан первый коммит`; затем `vibelog init` напрямую вне git — предупреждение на месте.

## Шаг 1 (VL-64): модуль `src/web/qwen-result.ts` (новый)

```ts
export interface QwenResult {
  result: string;          // message.result — финальный ответ агента
  is_error: boolean;
  num_turns: number;
  duration_ms: number;
  duration_api_ms: number;
  session_id: string;
  usage: {
    input_tokens: number;
    output_tokens: number;
    cache_read_input_tokens: number;
    total_tokens: number;
  };
}
export function parseQwenResult(log: string): QwenResult | null
```

Алгоритм: `log.split('\n')` → обойти строки **с конца** → `JSON.parse` в try/catch (битые строки пропускаем) → принять строку с `type === 'result'` → собрать `QwenResult` через optional chaining с дефолтами (0 / '' / false), лишние поля игнорировать → `return null`, если валидной result-строки нет. Пустой лог → null. Контракт: чистая функция без I/O, комментарии — на русском («почему»: обход с конца, т.к. stdout может содержать несколько сессий/шум, актуален только последний результат).

## Риски

1. **MarkdownV2 4096 символов:** экранирование удваивает длину динамического текста → result обрезается до 1500 символов; `sendText` (строки 62-73 handlers.ts) имеет фолбэк plain — сообщение не потеряется.
2. **Отсутствие result-строки** (ENOENT, обрыв, крах qwen) → `parseQwenResult` возвращает null → фолбэк «статус + logTail 800 символов». Обрабатывается тестами.
3. **Изменение формата JSON у qwen** (новые имена полей) → парсер читает только известные поля через optional chaining с дефолтами, лишнее игнорируется; тест с «дырявым» usage защищает.
4. **Дублирование статуса** (строка фазы VL-43 в карточке `/task` + статус в информационном сообщении) → в пути уведомления `phaseRun` в `sendTaskView` не передаётся; `/task` не меняется.
5. **Карточка может быть нескольких сообщений** при длинной задаче (`chunkRich`, rich.ts) — «2 сообщения» = 2 логических блока; Telegram-лимиты не новы и не меняются.
6. **Существующие тесты оркестратора** печатают не-JSON стабом → `result` не заполняется, assert на `logTail` проходят как раньше — регрессий нет (защищено шагом 5).
7. **Веб-интерфейс без бота:** `PhaseRun.result` обогащается всегда, поле опциональное — API `/api/tasks/:id` (api.ts) и доска не ломаются.

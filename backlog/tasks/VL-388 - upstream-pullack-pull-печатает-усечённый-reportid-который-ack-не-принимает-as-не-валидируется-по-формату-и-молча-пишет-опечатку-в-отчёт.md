## Симптом

Живой прогон mesh 2026-11-09 (VL-375, VL-387). Два дефекта CLI, оба всплыли при обычной работе, оба одного класса — «аргумент команды принимается не в том виде, в котором его показывает предыдущая команда».

## Дефект 1: `pull` печатает усечённый `report_id`, `ack` требует полный

```
$ vibelog upstream pull
Входящих отчётов: 1
  2026-11-09  82170b4f  UI-1 — Проверка mesh: отчёт из ui в vl
Подтвердить: vibelog upstream ack <report_id> --as <ID задачи>

$ vibelog upstream ack 82170b4f --as VL-388
Ошибка: отчёт с report_id «82170b4f» не найден в инбоксе
```

Корень:

- `src/cli/commands/upstream.ts:258` — печать: `${report.report_id.slice(0, 8)}`;
- `src/core/upstream-git.ts:445` — поиск: `if (parsed.report_id === id) return rel;` — **точное сравнение**.

CLI показывает 8 символов и тут же предлагает «Подтвердить: vibelog upstream ack <report_id>». Скопировал показанное → ошибка. Пользователь обязан открыть файл и взять полный sha1.

## Дефект 2: `--as` не валидируется по формату

```
$ vibelog upstream ack 7f6b1cb2… --as UI-444
Отчёт подтверждён
```

Задачи `UI-444` не существовало — подставлено вручную. Код (`upstream-git.ts`, `ackReport`) проверяет только непустоту:

```ts
if (acceptedAs.trim() === '') throw new UpstreamGitError('не указан --as …', 'config');
```

Существование задачи проверить **нельзя** — CLI в дочернем проекте не имеет доступа к backlog получателя. Это архитектурное ограничение, не дефект.

Но **формат** проверить можно и нужно: сейчас проходит `--as что-угодно`, и опечатка (`VL_388`, `VL388`, `vl 388`) молча запишется в фронтматтер отчёта. Поймать её потом можно только глазами — CI структуру `accepted_as` не проверяет.

## Почему одна задача

Оба дефекта — про разрыв между тем, что CLI показывает/принимает, и тем, что ожидает протокол. Фикс в одних и тех же двух файлах, тесты пересекаются.

## План

### 1. Поиск по префиксу `report_id` — `src/core/upstream-git.ts`

Текущий `findReportById` (строки 430–451) сравнивает точно:

```ts
if (parsed.report_id === id) return rel;
```

Меняем на два прохода:

```ts
/**
 * Находит файл отчёта по id.
 *
 * Принимает полный sha1 ИЛИ уникальный префикс (>=4 символов, git-стиль) —
 * `pull` печатает первые 8, пользователь копирует их в `ack`.
 * Неоднозначный префикс — ошибка со списком кандидатов, а не «не найден»:
 * молчаливый выбор первого совпадения привёл бы к ack не того отчёта.
 *
 * @throws UpstreamGitError kind:'config' — префикс совпал с несколькими отчётами
 */
function findReportById(cwd: string, id: string): string | undefined {
  const needle = id.trim().toLowerCase();
  if (needle === '') return undefined;
  const matches: Array<{ rel: string; report: UpstreamReport }> = [];
  // ... обход reports/*/*.md, для каждого parseReport (битые — пропуск)
  //     сравнение: report.report_id.toLowerCase().startsWith(needle)
  if (matches.length === 0) return undefined;
  if (matches.length === 1) return matches[0].rel;
  // >1 — только если needle короче полного id (полный sha1 уникален по построению)
  throw new UpstreamGitError(
    `префикс «${id.trim()}» совпал с ${matches.length} отчётами — уточни id: ` +
      matches.map((m) => `${m.report.report_id} (${m.report.source_task})`).join(', '),
    'config',
  );
}
```

Ключевые свойства:
- **Полный id работает как раньше** — `startsWith(полный)` даёт одно совпадение (sha1 уникален).
- **Минимальная длина** префикса — 4 символа (не 1: `a` совпадёт со многими; 4 — компромисс, как у `git`).
- **Неоднозначность — ошибка**, не угадывание.
- `writeReport` продолжает вызывать `findReportById` с полным `report.report_id` — идемпотентность не меняется (полный sha1 → ровно одно совпадение).

### 2. Валидация `--as` — `ackReport`, `src/core/upstream-git.ts`

Добавить проверку формата перед записью:

```ts
/** Формат ID задачи получателя: <PREFIX>-<число>, регистр префикса не важен. */
const ACCEPTED_AS_RE = /^[A-Za-z][A-Za-z0-9]*-[0-9]+$/;

function normalizeAcceptedAs(value: string): string {
  const trimmed = value.trim();
  if (trimmed === '') {
    throw new UpstreamGitError('не указан --as: укажи ID задачи получателя, например --as VL-367', 'config');
  }
  if (!ACCEPTED_AS_RE.test(trimmed)) {
    throw new UpstreamGitError(
      `--as «${trimmed}»: ожидался ID задачи вида <PREFIX>-<номер>, например VL-367`,
      'config',
    );
  }
  // Нормализация: префикс в верхний регистр, номер как есть
  const [prefix, num] = trimmed.split('-');
  return `${prefix.toUpperCase()}-${num}`;
}
```

Применяется в `ackReport` вместо текущей проверки на пустоту (строки ~540).

**Важно — чего НЕ делаем:** не проверяем существование задачи. CLI в дочернем проекте не имеет доступа к backlog получателя, это архитектурное ограничение (документируется комментарием в коде).

**Отдельно решить:** код выхода. Формат — ошибка *использования*, логичнее `1`, а не `2` (`config`). Но `UpstreamGitError` маппит `config` → 2. Варианты: (а) оставить 2 — проще, `kind: 'config'` уже означает «неверный аргумент»; (б) добавить `kind: 'usage'` с кодом 1. Рекомендую (а): новый `kind` потребует правки в `EXIT_CODES` и в CLI-обработчике ради косметики. AC сформулирован на 1 — если остаёмся на 2, AC надо поправить; согласовать при реализации.

### Риски

- **Слишком короткий префикс.** 4 символа — минимум; при большом инбоксе возможны коллизии. Обрабатываются ошибкой «уточни id», не молчаливым выбором.
- **Регистр hex.** `report_id` — sha1 в нижнем регистре; сравнение через `toLowerCase()` обеих сторон, чтобы `82170B4F` тоже работал.
- **Идемпотентность `writeReport`.** Использует полный `report_id` в `reportId()` — `startsWith` полного sha1 даёт одно совпадение; ложных «уже есть» не возникнет.

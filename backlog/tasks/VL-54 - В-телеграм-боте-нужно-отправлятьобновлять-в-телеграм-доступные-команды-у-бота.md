## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
При запуске `vibelog bot` синхронизировать список доступных команд с Telegram через Bot API `setMyCommands`, чтобы меню команд в клиенте Telegram было постоянно актуальным.

Контекст: бот (grammy) регистрирует 10 команд в `src/bot/handlers.ts` (start, tasks, task, board, create, status, comment, spec, plan, code), но `setMyCommands` нигде не вызывается — у бота нет меню команд в Telegram. Help-тексты со списком команд захардкожены в двух местах handlers.ts (строки 124 и 398) и при добавлении новой команды рассинхронизируются.

Реализация:
- Единый источник правды: реестр команд (имя + описание) в одном модуле (например, `src/bot/registry.ts`); из него генерируются и `setMyCommands`, и help-тексты /start (убрать хардкод в handlers.ts).
- Вызов `bot.api.setMyCommands(...)` при старте в `runBot` (`src/cli/commands/bot.ts`) после `registerHandlers`; ошибки сети/API не должны ронять бота — логируем и продолжаем polling (паттерн sendText/sendMd).
- Ограничения Telegram: имя команды ≤32 симв., описание ≤256 симв., до 100 команд — все 10 команд укладываются.
- Тесты (`*.test.mjs`, импорт из dist): реестр покрывает все команды, зарегистрированные в handlers.ts; syncCommands вызывает setMyCommands с полным списком и не бросает при ошибке сети.
<!-- SECTION:DESCRIPTION:END -->

### 1. `src/bot/registry.ts` (новый)

```ts
// Тип команды; структурно совместим с BotCommand из grammy
export interface RegistryCommand {
  command: string;     // имя без слэша, ≤32 симв.
  description: string; // русское описание, ≤256 симв.
  usage?: string;       // представление в help-строке (для /task — '/task <id>')
}

export const BOT_COMMANDS: RegistryCommand[] = [
  { command: 'start',   description: 'Привязать чат: введите код из консоли' },
  { command: 'tasks',   description: 'Список невыполненных задач' },
  { command: 'task',    description: 'Детали задачи: /task VL-1', usage: '/task <id>' },
  { command: 'board',   description: 'Канбан-доска задач' },
  { command: 'create',  description: 'Создать задачу' },
  { command: 'status',  description: 'Сменить статус задачи' },
  { command: 'comment', description: 'Добавить комментарий к задаче' },
  { command: 'spec',    description: 'Запустить Фазу 1 (Spec) через qwen' },
  { command: 'plan',    description: 'Запустить Фазу 2 (Plan) через qwen' },
  { command: 'code',    description: 'Запустить Фазу 3 (Code) через qwen' },
];

/** Help-строка для /start: команды после /start, формат текущего хардкода. */
export function commandsHelp(): string {
  return BOT_COMMANDS
    .filter((c) => c.command !== 'start')
    .map((c) => c.usage ?? '/' + c.command)
    .join(', ');
}

/** Синхронизация меню команд в Telegram; ошибки API не роняют бота. */
export async function syncCommands(bot: Bot): Promise<void> {
  try {
    await bot.api.setMyCommands(BOT_COMMANDS);
  } catch (err) {
    // Паттерн sendText/sendMd: сетевой сбой не должен блокировать polling
    console.error('Не удалось синхронизировать команды с Telegram:', err instanceof Error ? err.message : String(err));
  }
}
```

Комментарии — на русском (правило проекта). `commandsHelp()` обязан вернуть строку, идентичную текущему хардкоду: `/tasks, /task <id>, /board, /create, /status, /comment, /spec, /plan, /code`.

### Риски

1. **Типы grammy**: передаём собственный `RegistryCommand`; структурная совместимость с `BotCommand` подтвердится компиляцией tsc.
2. **Недоступность API**: при сетевом сбое меню команд не появится, но бот работает (по ТЗ); повторная синхронизация не предусмотрена — при необходимости можно позже добавить retry.
3. **Хрупкость regex-сверки**: тест читает исходник handlers.ts и ищет `bot.command('...')` — смена стиля регистрации команд потребует правки теста. Осознанный компромисс: ловит именно рассинхрон реестра и регистрации.
4. **MarkdownV2**: help-строка генерируется идентичной текущему хардкоду (та же форма `/task <id>`, разделители) — поведение отправки не меняется.
5. **Лимиты Telegram**: тест проверяет ≤32/≤256/≤100 — защита от будущего перерасширения реестра.

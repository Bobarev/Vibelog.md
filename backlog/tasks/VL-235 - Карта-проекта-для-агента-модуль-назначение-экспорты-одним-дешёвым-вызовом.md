## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
## Контекст

Даже с листингом каталогов (VL-233) и grep (VL-234) агенту нужно несколько вызовов, чтобы понять «что вообще есть в проекте» и выбрать правильный модуль. В разобранном чате это вылилось в угадывание путей: `src/agent/orchestrator.ts` вместо `src/web/orchestrator.ts`, поиск `auto-runner.ts` в `src/core/` и т.п.

## Цель

Дать агенту «карту проекта» за один вызов: список модулей `src/` с их назначением (первая строка JSDoc/шапки файла) и экспортами. Проект уже держит подробные шапки-комментарии в каждом модуле — это готовый источник описаний, ничего дописывать не нужно.

## Предлагаемое решение

Новый read-only инструмент (имя на выбор: `project_map`, `list_modules`) либо CLI-команда `vibelog map` + MCP-обёртка.

Формат выдачи (markdown, ≤ ~150 модулей):
```
src/agent/
  cli.ts — CLI vibelog-agent: headless-исполнитель фаз [runCli, main]
  llm.ts — LLM-клиент Cloud.ru: tool-calling + SSE [createLlmClient, streamChat]
src/core/
  reference-cache.ts — markdown-кэш references [cacheReference, htmlToMarkdown]
```

Источник данных:
- обход `src/**/*.ts` (исключая `*.test.mjs`, `*.d.ts` по выбору);
- описание = первая строка из блока `/** … */` в шапке файла (обрезать до ~80 символов);
- экспорты = имена из `export function|const|interface|type|class` (регулярка, без полноценного парсинга TS — прагматично и без зависимостей).

## Известные риски

- Регулярка по экспортам может пропустить `export { a, b }` списком или `export type` — не критично, описание полезнее списка; зафиксировать в Plan допущение.
- Бюджет ответа: карта на 150 модулей ≈ 8–12 КБ — нужно усечение/сжатие, чтобы не раздувать wire-payload (в проекте уже есть guard VL-230 по payload_bytes).
- Актуальность: карта читает файлы на момент вызова, кэш не нужен (генерация дешёвая).

## Входные данные

Чат-диагностика VL-232: чтобы найти `htmlToMarkdown` и место создания LLM-клиента, потребовалось ~6 неудачных `read_file`. Со связанными VL-233/VL-234 карта закрывает этап «сориентироваться в проекте» одним вызовом.

## Решение

Одна генерация в ядре + две тонкие обёртки (CLI `vibelog map`, MCP `project_map`). Агент получает карту через MCP (он уже видит все MCP-инструменты — src/agent/cli.ts:473 `toolsAsSpecs(mcp, await mcp.listTools())`), веб-чат — через тот же реестр (src/web/tool-policy.ts:216 `chatToolDefs`).

Измерено на текущем `src/` (88 модулей, `.ts` без `*.test.*` и `*.d.ts`): карта «путь + описание ≤60 симв.» = **8.5 КБ**, «+ экспорты» = 12–14 КБ → бюджет 8 КБ достижим только без экспортов, поэтому режим двухуровневый: по умолчанию компакт (описания, до 4 экспортов только если влезает), с `query` — узкая выборка с полными описаниями и всеми экспортами (это и закрывает AC6: `project_map {"query":"htmlToMarkdown"}` → одна строка `core/reference-cache.ts — … [htmlToMarkdown, …]`).

## Файлы и правки

### 1. `src/core/project-map.ts` (новый, ~180 строк)
Чистый синхронный модуль без сети и зависимостей от agent/:
- `export interface ProjectMapOptions { root?: string; query?: string; exports?: boolean; limit?: number; maxBytes?: number }`
- `export interface ProjectMapResult { text: string; modules: number; shown: number; compacted: 0|1|2|3; truncated: boolean }`
- `export const PROJECT_MAP_DEFAULT_DIR = 'src'`, `PROJECT_MAP_DESC_MAX = 60`, `PROJECT_MAP_MODULE_LIMIT = 150`, `PROJECT_MAP_LINE_LIMIT = 150`, `PROJECT_MAP_MAX_BYTES = 8 * 1024`.
- `walkTsFiles(root)`: рекурсивный `readdirSync` с `SKIP_DIRS = new Set(['node_modules','.git','dist'])`; фильтр — `endsWith('.ts') && !includes('.test.') && !endsWith('.d.ts')`; результат сортируется (`localeCompare(a,b,'en')` — детерминизм, как в `formatDirListing`).
- Описание: регулярка `^\s*\/\*\*([\s\S]*?)\*\//` по шапке, первая непустая строка, снять `^\s*\*\s?`, схлопнуть пробелы, обрезать до `PROJECT_MAP_DESC_MAX` с `…`. Блок `/** */` не в шапке (первый матч в файле) — допустимо; пусто → строка без описания.
- Экспорты: `^\s*export\s+(?:default\s+)?(?:async\s+)?(?:function|const|let|class)\s+([A-Za-z0-9_$]+)` (multiline, g). Допущение фиксируется в шапке файла: `export { a, b }`, `export type`, `export interface` не собираются — список экспортов вспомогателен, описание и путь важнее (риск из задачи).
- Сборка: группировка по каталогу (`src/agent/`), каталоги и файлы отсортированы; строки `  <basename> — <desc> [<exports>]`.
- Бюджет (AC4): собрать полный текст → если `Buffer.byteLength(text,'utf8') > maxBytes`, ступенчатая деградация: (1) убрать блоки экспортов; (2) описание до 40 симв.; (3) только имена модулей. В конце — маркер `…[карта сжата: экспорты/описания опущены, N модулей]`. Усечение по `limit` (default 150) — отдельный маркер `…[карта усечена: показано X из Y модулей; уточните dir/query]` (AC2). `query` фильтрует по path+desc+exports, лимит строк для query — 40, при query бюджет не режет (выборка мала).
- Нет каталога `src/` → `text: 'Каталог src/ не найден — карта не построена (укажите dir)'`, `modules: 0`, без исключения (AC5).
- JSDoc-шапка по-русски: зачем (VL-232: 6 холостых read_file), почему регулярки вместо парсера, почему без кэша.

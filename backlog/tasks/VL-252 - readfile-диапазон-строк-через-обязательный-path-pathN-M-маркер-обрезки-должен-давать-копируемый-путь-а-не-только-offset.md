## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
## Контекст

VL-250 починила бюджет вывода: `formatFileSlice` режет 8192 символа по **выбранным** строкам и печатает маркер «показаны строки 1–171 из 1864; продолжение — offset=171». Проверено на практике — работает.

Но чтение файлов больше лимита в веб-чате по-прежнему невозможно. Наблюдение (диалог разбора VL-250/VL-251): модель ~25 раз подряд вызвала `read_file` с аргументами **без `offset`** (только `{path}`) и каждый раз получала одну и ту же первую порцию «строки 1–171», хотя в маркере был указан следующий `offset=171`.

## Причина

`offset` и `limit` — **необязательные** поля схемы (иначе обычное чтение файла их не требует). При генерации tool-вызова модель заполняет обязательные поля и опускает необязательные, когда считает, что «читать с начала». Инструмент не может отличить «offset намеренно не передан» от «offset не удалось передать» — оба случая выглядят как `undefined`, и он корректно читает с начала.

Итог: маркер сообщает следующее смещение в виде **числового поля**, которое и есть ненадёжная часть контракта. Получается замкнутый круг: маркер → модель формирует вызов без offset → тот же результат.

Это НЕ баг реализации VL-250 (`args.offset` читается в handler'ах `src/agent/tools.ts:282-286` и `src/web/tool-policy.ts:147-154`) — это дефект контракта инструмента.

## Цель

Сделать следующий диапазон копируемым через **обязательный** параметр `path`, который модель передаёт всегда.

## Решение

Синтаксис диапазона в `path` (совместим с привычной записью `file:line`, работает в редакторах и терминалах):

- `src/mcp/tools.ts:171-340` — строки с 171 по 340 (1-based, включительно);
- `src/mcp/tools.ts:171` — с 171-й до конца файла;
- обычный путь без суффикса — прежнее поведение (строки 1.., лимит по бюджету).

Правила разбора: суффикс распознаётся только если после **последнего** `:` идут цифры или `цифры-цифры` (важно: в путях macOS `:` в имени файла допустим, поэтому проверка «последний `:` + цифры + конец», а при неоднозначности — сначала пробуем как обычный путь, потом как диапазон).

Если суффикс задан, он **переопределяет** `offset`/`limit` из аргументов (явный диапазон в пути приоритетнее).

Маркер обрезки в `formatFileSlice` печатать готовым к копированию в `path`:
`…[вывод обрезан: показаны строки 1–171 из 1864; продолжение — path="src/mcp/tools.ts:171-341"]`
(имя файла в маркере — относительный путь, чтобы строка копировалась в следующий вызов без правок). Обратная совместимость подстроки `…[вывод обрезан` обязательна — на неё матчат тесты (`src/agent/tools.test.mjs:412`, lesson-76).

## Решение (контракт)

Следующий диапазон передаётся через **обязательный** `path` — суффикс `:N-M` / `:N` (и алиас `#L N-L M` в стиле GitHub). `path` модель заполняет всегда, поэтому маркер обрезки с готовым `path=…` замыкает цикл без ненадёжного числового поля `offset`.

**Один общий хелпер** (lesson-37: не копия): `parseReadPath` — экспорт из `src/agent/tools.ts`, импортируется в `src/web/tool-policy.ts` (там на стр. 31 уже импортируются `resolveInProject`/`formatFileSlice`).

```ts
export function parseReadPath(cwd: string, rawPath: string):
  | { ok: true; path: string; offset?: number; limit?: number; rangeRel?: string }
  | { ok: false; error: string };
```

Алгоритм — порядок важен, в путях macOS `:` допустим в имени файла:
1. `existsSync(resolve(cwd, rawPath))` → `{ ok: true, path: rawPath }` — без диапазона (существующий файл `a:1-2.md` читается как файл, offset/limit из аргументов работают как раньше).
2. Суффикс: `/^(.*):(\d+)(?:-(\d+))?$/s` — только если после **последнего** `:` идут цифры и конец строки; алиас `/^(.*)#L(\d+)(?:-L(\d+))?$/`.
   - `base` пустой (`:171`) → `{ ok: false, error: 'Путь не задан' }`.
   - `start < 1 || (end !== undefined && end < start)` → `{ ok: false, error: 'Некорректный диапазон строк в path: "<raw>". Формат: путь:НАЧАЛО-КОНЕЦ или путь:НАЧАЛО (1-based, включительно)' }`.
3. Иначе `{ ok: true, path: base, offset: start - 1, limit: end ? end - start + 1 : undefined, rangeRel: rawPath }`.
4. Суффикс не распознан (`файл:abc`) → `{ ok: true, path: rawPath }` и штатная ошибка «Файл не найден» из handler'а.

Диапазон из `path` **переопределяет** `args.offset`/`args.limit` (явный диапазон приоритетнее). В обоих handler'ах: `const parsed = parseReadPath(cwd, rawPath); if (!parsed.ok) return parsed.error;` далее `resolveInProject(cwd, parsed.path, { allowRoot: true })`; `offset = parsed.offset ?? args.offset`, `limit = parsed.limit ?? args.limit`.

## Маркер обрезки в `formatFileSlice`

Расширить сигнатуру: `formatFileSlice(content, offsetRaw, limitRaw, pathLabel?: string)` (4-й необязательный параметр, `src/agent/tools.ts:100`). Логика резерва (`:115`) меняется с фиксированного шаблона на **динамический** — хвост строится до подсчёта бюджета, с 6-значными числами в шаблоне:

```
…[вывод обрезан: показаны строки 1–171 из 1864; продолжение — path="src/agent/tools.ts:172-342" (offset=172)]
```

- `reserve = buildTail(1_000_000-шаблон).length` — функция `buildTail(from, to, total, lastShown, pathLabel, truncated=false)`, вызываемая дважды (для резерва и для реального хвоста). Длина `pathLabel` известна на входе → резерв точный, инвариант ≤ 8192 (AC2 VL-250) держится.
- `end` следующего диапазона = `min(lastShown + parts.length, lines.length)` (чанк того же размера, что показан).
- Без `pathLabel` — прежний хвост с одним `offset=` (чистая функция не ломает `tools.test.mjs:578`).
- Подстроки `…[вывод обрезан` и `продолжение — offset=` сохраняем в обоих вариантах — на них матчат `tools.test.mjs:412` и `:575` (lesson-76). Строку про усечённую строку (`:573-575`) не трогаем.

## Риски и тонкие места

- **Инвариант «ответ ≤ 8 КБ»**: динамический резерв по фактическому `pathLabel` не сужает бюджет сильнее необходимого; при очень длинном `pathLabel` (>~500 симв.) бюджет схлопнется — ограничить вклад пути в резерв разумным max и в этом случае печатать хвост без `path=` (только `offset=`), сохраняя подстроку совместимости.
- **Существующие тесты**: `tools.test.mjs:412` (`…[вывод обрезан`), `:575` (`продолжение — offset=\d+`), `:565/568` (длина) — все три подстроки/инварианта сохраняем; правки чужих тестов не нужны (AC4).
- **`:` в именах файлов macOS**: дизамбигуация — п.1 (`existsSync` раньше регэкспа) решает существующий `a:1-2.md`; несуществующий `a:1-2.md` трактуется как диапазон файла `a` — это осознанный компромисс, отдельного теста не требуем.
- **Каталоги**: `parseReadPath` вернёт диапазон и для каталога, но `isDirectory`-ветка срабатывает до чтения — листинг диапазон игнорирует (тест VL-233 остаётся зелёным).
- **Абсолютные пути**: `resolveInProject` получает уже обрезанный `parsed.path`; проверка выхода за проект не меняется.
- **Дублирование** (AC5): вся разбор-логика только в `parseReadPath`, в `tool-policy.ts` — импорт.

## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
Контекст (обсуждение roadmap 2026-11-09, пункт «Agent memory» → память персоны).

Сейчас персоны настраиваются только руками: секция `chat_personas` в `.vibelog/settings.json` + файлы промптов в `.vibelog/prompts/personas/`. Память персоны (VL-401) добавляет ещё один файл рядом. Пользователь не видит ни того, ни другого в интерфейсе — значит не контролирует. Это ровно та проблема, из-за которой Qwen auto-memory была названа неконтролируемой: запись есть, а посмотреть и поправить негде.

Страница должна закрыть три вещи: увидеть все роли, отредактировать промпт и память, создать свою роль (например «Психолог» или «Бизнес-наставник» для проекта личных дел — сценарий, названный пользователем).

Зависимости: VL-401 (память персоны — путь, лимит, формат). VL-402 (запись памяти) не блокирует: страница может редактировать память как текст и без инструмента.

Связанные: VL-401, VL-402, VL-265 (реестр персон), VL-316 (страница «Модели» — образец страницы с CRUD), VL-165 (страница «Конфиг проекта» — образец read-modify-write settings).

## Шаги

1. **Роуты** — `web/src/lib/use-hash-route.ts`:
   - `Route` += `'personas' | 'persona'`.
   - `parseHash`: `path === 'personas'` → `'personas'` (точным совпадением ДО префикса), `path.startsWith('persona/')` → `'persona'`. Порядок важен: `'personas'` не начинается с `'persona/'`, но фиксируем явно (паттерн `documents`/`document`, lesson-22).
   - `usePersonaId()` — по образцу `useLessonId`.

2. **Сайдбар** — `web/src/components/layout/app-sidebar.tsx`: в `subItems` группы «Настройки» добавить `{ id: 'personas', title: 'Персоны', url: 'personas', icon: Users }` (иконка из lucide, проверить наличие — lesson-15 про удалённые иконки).

3. **API — `src/web/personas-api.ts`** (новый модуль, по образцу `src/web/models-crud-api.ts`):
   - `GET /api/personas/:id` → `{persona: {id, label, description, prompt, defaultStatus, allowTools, builtin}, promptText, memoryText, memory: {chars, limit, truncated}}`. Текст промпта и памяти отдаётся ТОЛЬКО здесь (в списке — нет, как сейчас).
   - `PUT /api/personas/:id` → `{label?, description?, defaultStatus?, allowTools?, promptText?, memoryText?}`. Валидация до записи: пустой label, неизвестный `default_status` (сверка со `statuses` из `backlog/config.yml`), `allow_tools` — только известные имена инструментов, `memoryText` длиннее лимита → 400 без записи.
   - `POST /api/personas` → создание проектной: `{id, label, description?, promptText, defaultStatus?}`. Дубль id (включая встроенные и `RETIRED_PERSONA_IDS`) → 400. Пишет запись в `chat_personas` (read-modify-write через `loadSettings`/`saveSettings`, чужие секции целы) + файл `.vibelog/prompts/personas/<id>.md`.
   - `DELETE /api/personas/:id` → только проектные; встроенные → 400 с причиной. Удаляет запись из `chat_personas`; файлы промпта и памяти не трогает, возвращает их пути в ответе (UI показывает в подтверждении).
   - Запись файлов — атомарно (temp + rename), путь валидируется внутри `.vibelog/prompts/personas/` (никаких `..`).

4. **Страница списка** — `web/src/components/personas/personas-page.tsx`:
   - Таблица: label, id, встроенная/проектная (Badge), description, память (размер/лимит, предупреждение при `truncated`).
   - Кнопка «Создать персону» → Dialog с полями (id, label, description, промпт, default_status).
   - Клик по строке → `#/persona/<id>`.

5. **Детальная страница** — `web/src/components/personas/persona-detail.tsx`:
   - Секция «Основное»: label, description, default_status (Select из статусов конфига), allow_tools (мультиселект из `listTools()`).
   - Секция «Промпт роли»: `Textarea` с текстом, счётчик символов, кнопка «Сохранить».
   - Секция «Память»: `Textarea` с текстом памяти, счётчик `N / лимит`, предупреждение при превышении, кнопка «Сохранить» (при превышении — ошибка, не обрезка).
   - Для встроенной роли: пометка «встроенная — изменения сохраняются как переопределение», кнопки удаления нет.

6. **Клиентский API** — `web/src/components/personas/api.ts` (по образцу `web/src/components/models/api.ts`).

7. **Пересборка `web/dist`** и коммит (lesson-150: после правок `web/src` пересобирать и коммитить бандл, иначе master получит старый).

## Как проверить

- `pnpm build && pnpm test` + `cd web && npm run build && npm run lint`.
- Ручной кейс: `#/personas` → список из 4 встроенных ролей; создать «Психолог» с промптом → появляется в списке и в пикере чата; открыть детальную, добавить строку в память, сохранить → в новом треде чата под этой ролью блок памяти присутствует.
- Встроенная роль: изменить label → сохраняется как переопределение в `chat_personas`, кнопки удаления нет.
- Ошибки: пустой label, дубль id, память сверх лимита → 400, файл не меняется (проверить `git diff` до/после).
- Чужие секции `settings.json` (models, workflows, mcpServers) после сохранения персоны не изменились.

## Риски

- **Порядок в `parseHash`.** `'personas'` и `'persona/<id>'` рядом — при неверном порядке список уедет на детальную страницу с пустым id (инцидент-паттерн lesson-22). Тест на оба маршрута обязателен.
- **Запись в `settings.json` из веба.** Read-modify-write легко затирает чужие секции, если читать не через `loadSettings`. Тест «чужие ключи целы» — обязательный.
- **Файлы промптов вне git.** `.vibelog/prompts/` коммитится (VL-329), а `*.memory.md` — нет (VL-401). Страница должна это отражать: правка промпта попадёт в git, правка памяти — нет. В UI — подпись под секцией памяти.
- **Удаление персоны.** Удаление записи из `chat_personas` при существующем файле промпта оставляет «сироту» — файл, который никто не читает. Поэтому файлы не удаляются автоматически, а показываются в подтверждении: пользователь решает.
- **Совместимость с VL-401.** Если VL-401 не смержена — нет `memoryText` и лимита. Зависимость проставлена.

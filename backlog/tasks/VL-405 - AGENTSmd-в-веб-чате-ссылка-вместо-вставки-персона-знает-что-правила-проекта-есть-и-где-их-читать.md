## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
Контекст (обсуждение roadmap 2026-11-09, пункт «Agent memory» → память персоны).

Обнаруженное расхождение: `AGENTS.md` подставляется в системный промпт **только** в TUI-агенте и headless-фазах (`src/agent/system-prompt.ts`, кап `AGENTS_MD_MAX_CHARS = 8000`). Веб-чат собирает промпт иначе (`buildSystemPrompt` в `src/web/chat.ts`: шаблон → роль → память → контекст поиска) и правил проекта не видит вовсе.

Следствие: персона в чате не знает, как в этом проекте собирать, тестировать, какие соглашения соблюдать. При этом в фазах агент это знает — то есть один и тот же проект ведёт себя по-разному в зависимости от того, где задан вопрос.

Решение из обсуждения: **ссылкой, не вставкой**. Вставка 8000 символов в каждый ход чата — дорого и не нужно: чат интерактивный, модель может сходить за правилами через `read_file`, когда вопрос действительно про правила. Память персоны (VL-401) при этом остаётся вставкой — она короткая и всегда релевантна.

Связанные: VL-401 (память персоны — порядок блоков), VL-404 (уроки в чате — порядок блоков), VL-238 (чат-блок промпта, opt-in), VL-96 (AGENTS.md в промпте агента).

## Шаги

1. **`src/web/chat.ts` — определение AGENTS.md.** Новая функция:
   ```
   describeAgentsMd(cwd): string | null
   ```
   - `statSync(join(cwd, 'AGENTS.md'))` → если файла нет (`ENOENT`) — `null`.
   - Если есть — вернуть строку вида:
     ```
     ## Правила проекта
     В корне проекта есть AGENTS.md (N символов) — соглашения по сборке, тестам и стилю кода.
     Прочитай его через read_file, если вопрос касается правил проекта. В промпт он не вставлен.
     ```
   - Прочие ошибки чтения (`EACCES`, `EISDIR`) — `null` + `console.error` (не ронять чат; паттерн `src/agent/system-prompt.ts`).

2. **`src/web/chat.ts` — вставка блока.** В `buildSystemPrompt` после блока уроков (VL-404), до контекста поиска:
   ```
   const agentsMd = describeAgentsMd(cwd);
   if (agentsMd) parts.push(agentsMd);
   ```

3. **Инвариант.** `src/agent/system-prompt.ts` не трогаем — там AGENTS.md по-прежнему вставляется целиком (фазы и TUI работают как раньше). Тест от обратного: headless-промпт содержит текст AGENTS.md, чат-промпт — только ссылку.

4. **Порядок блоков.** Зафиксировать тестом полную последовательность чат-промпта: шаблон → `## Текущая роль` → `## Память персоны` (если есть) → `## Уроки проекта` (если есть) → `## Правила проекта` (если есть) → контекст поиска. Порядок важен: контекст поиска всегда последний (он рантаймовый, меняется каждый ход).

## Как проверить

- `pnpm build && pnpm test` (полный прогон).
- Ручной кейс: в веб-чате спросить «как прогнать тесты в этом проекте» → модель вызывает `read_file` на `AGENTS.md` и отвечает по нему (в промпте — только ссылка, не текст).
- Проект без AGENTS.md → блока нет, чат работает.
- Headless-фаза → AGENTS.md вставлен целиком, как раньше (регресс-тест `src/agent/system-prompt.test.mjs` зелёный).

## Риски

- **Модель не сходит за файлом.** Ссылка работает, только если модель понимает, что надо читать. Формулировка должна быть императивной («прочитай через read_file, если вопрос касается правил проекта»), иначе блок бесполезен. Проверить на реальном вопросе.
- **Лишний ход.** Каждое чтение AGENTS.md — tool-вызов. Если вопросы про правила частые, это дороже вставки. Митигация: вставка остаётся вариантом для проектов с маленьким AGENTS.md — можно добавить настройку `chat_agents_md: 'link' | 'inline' | 'off'` (дефолт `link`), но это расширение объёма; в первой версии — только `link`.
- **Порядок блоков.** Три задачи (VL-401, VL-404, VL-405) добавляют блоки в одну функцию. Если делать их параллельно — конфликт в `buildSystemPrompt`. Порядок реализации: VL-401 → VL-404 → VL-405, каждая следующая сверяется с фактическим кодом.

## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
После VL-380 `vb install` при 429 от GitVerse **молча ждёт**: политика `DEFAULT_RATE_LIMIT_DELAYS_MS = [60_000, 60_000, 60_000]` с бюджетом `RATE_LIMIT_BUDGET_MS = 180_000` означает до **3 минут тишины** перед ошибкой. Прогресс не печатается: `printPlan` вызывается только после всех сетевых вызовов, а перед `fetchInstallItem` вывода нет.

**Как это выглядит для пользователя:** `vibelog install vibelog.md/ui/base --dry-run` «висит несколько минут и ничего не происходит». Отличить «работает» от «зависло» невозможно, а причина (rate-limit без токена) выясняется только в конце.

**Что нужно:**

1. **Прогресс в stderr.** Перед каждым сетевым шагом — строка «что делаю». Во время паузы ретрая — «жду N с (429, попытка 1/3)». Это снимает главную проблему: команда перестаёт выглядеть зависшей.

2. **Флаг `--verbose`.** URL, HTTP-статус, номер попытки, причина повтора, источник токена. Без секретов — токен маскируется (`maskToken` из `gitverse-auth.ts` уже есть).

3. **Диагностика 429 сразу, а не в конце.** Если токена нет — сказать об этом на первом же 429, не заставляя ждать 3 минуты. Если токен есть и не помогает — тоже сказать, иначе пользователь думает, что токен сломан.

**Почему это важнее, чем кажется.** Молчаливое ожидание — это класс дефектов, а не единичный случай: любая сетевая операция с ретраями (реестр, Issues-API) может уйти в долгое ожидание. Прогресс-вывод должен быть в общем транспорте (`gitverse-http.ts`), а не только в `install`.

**Границы.** Задача не меняет политику ретраев (число попыток, паузы, бюджет) — только наблюдаемость. Не добавляет `--json`-вывод. Не реализует кэш.

**Связанное:** VL-380 (политика 429, `Retry-After`, токен `GITVERSE_TOKEN`), VL-337 (`vb install` ядро), doc-25 §5.3 (вывод), §5.1 (сеть).

## Implementation Plan
<!-- SECTION:PLAN:BEGIN -->
**Стратегия.** Прогресс нужен не только в `install`, но и в любом клиенте общего транспорта — поэтому основная работа в `gitverse-http.ts` (хук `onProgress`), а `install` его только подключает. Иначе через месяц то же молчание повторится в `vibelog upstream report`.

**Файлы.** `src/core/gitverse-http.ts` (хук прогресса + `--verbose`-детали), `src/core/registry-fetch.ts` (проброс), `src/core/install.ts` (прогресс шагов), `src/cli/commands/install.ts` (флаг, печать), `src/cli/router.ts` (справка), тесты.

**Шаг 1. Хук прогресса в транспорте.**

1. Тип `ProgressEvent`: `{ kind: 'request' | 'retry' | 'response' | 'waiting'; url: string; attempt: number; attemptsMax: number; status?: number; delayMs?: number; reason?: 'rate_limited' | 'server' | 'network' }`.
2. `requestWithRetries` принимает `onProgress?: (event: ProgressEvent) => void`; вызывается: перед каждым запросом (`request`), после ответа (`response`, со статусом), перед паузой (`waiting`, с `delayMs`).
3. По умолчанию `onProgress` — no-op: транспорт не печатает сам, печать — забота CLI (иначе библиотека начнёт писать в stdout в тестах и MCP).
4. Таймаут и лимит байт тоже дают событие, чтобы ожидание было видно и там.

**Шаг 2. Печать прогресса в install.**

5. `install.ts` создаёт `onProgress`, который пишет **в stderr** (`process.stderr.write` / `console.error`), а не в stdout: stdout остаётся чистым для плана и итога.
6. Формат без `--verbose`:
   - `→ скачиваю vibelog.md/ui/base…` (один раз перед первым запросом элемента);
   - `→ жду 60 с (429, попытка 1/3)…` (только при паузе);
   - `→ скачиваю файлы (2)…` (перед загрузкой файлов элемента).
7. Формат с `--verbose`: добавляет `GET <url>`, `← 429`, `← 200 (1234 байт)`, причину повтора и источник токена (одна строка в начале: `токен: из .env` / `из окружения` / `нет`).
8. Строки с `→`/`←` — без эмодзи-зависимостей, простой текст, чтобы работало в любом терминале.

**Шаг 3. Немедленная диагностика 429.**

9. При первом событии `waiting` с `reason === 'rate_limited'` вывести предупреждение **сразу** (не после исчерпания попыток):
    - токена нет → `⚠ GitVerse ограничил анонимные запросы (429). Добавь GITVERSE_TOKEN в .env — авторизованные запросы лимитируются выше (https://gitverse.ru/settings/tokens). Жду N с (попытка 1/3, суммарно до 180 с).`
    - токен есть → `⚠ GitVerse ограничивает запросы даже с токеном (429). Жду N с (попытка 1/3, суммарно до 180 с).`
10. Флаг «уже предупредили» — чтобы не повторять на каждой попытке (одно предупреждение на цепочку запросов).

**Шаг 4. Флаг и справка.**

11. `--verbose` (и алиас `-v`) в `KNOWN_FLAGS` команды `install`; передаётся в `InstallOptions`.
12. `src/cli/router.ts`: строка в `showCommandHelp('install')` — `--verbose` в списке флагов.

**Шаг 5. Тесты.**

13. `gitverse-http.test.mjs`: `onProgress` вызывается в правильном порядке и с правильными полями; при 429 событие `waiting` содержит `delayMs` из `Retry-After`; без `onProgress` ничего не падает и ничего не печатает (перехват `process.stderr.write`).
14. `install.test.mjs` (или `install-progress.test.mjs`): прогресс идёт в stderr, stdout при `--dry-run` содержит только план; без токена предупреждение появляется на первой паузе, а не в конце; с токеном текст предупреждения другой; токен отсутствует в выводе (маскирование).
15. Проверка, что `--verbose` добавляет URL, а без флага URL в выводе нет.

**Риски.**
- Печать в stdout сломает `--dry-run`-парсинг, если кто-то читает вывод скриптом — только stderr.
- Прогресс в MCP-режиме (`vibelog mcp start`) недопустим: stdout занят JSON-RPC. Транспорт не должен печатать сам по умолчанию (отсюда no-op `onProgress`).
- Предупреждение на каждой попытке превратится в шум — нужен флаг «уже сказали».
- Долгие паузы всё ещё остаются (до 180 с) — задача не ускоряет, а делает ожидание понятным. Если нужно ускорить — отдельное решение (уменьшить бюджет или падать сразу без токена).
- `-v` уже может быть занят глобальным `--version` в роутере (`args.includes('-v')` перехватывается до роутинга!) — алиас `-v` для `--verbose` использовать НЕЛЬЗЯ, только `--verbose`. Это проверить в первую очередь.

**Проверка.** `pnpm typecheck && pnpm test`; вручную — `vibelog install vibelog.md/ui/base --dry-run` без токена (видно ожидание и предупреждение, команда не выглядит зависшей) и с токеном (установка проходит); `--verbose` показывает URL и статусы.

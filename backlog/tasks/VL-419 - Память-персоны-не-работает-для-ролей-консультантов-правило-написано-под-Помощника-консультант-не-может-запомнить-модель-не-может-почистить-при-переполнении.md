## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
Память персоны (VL-401 чтение, VL-402 запись, VL-403 UI) реализована, но работает только для «Помощника». Три связанных пробела, найденных при разборе вопроса «как роль должна пользоваться памятью».

**1. Правило записи написано под одну роль.** В `templates/prompts/chat-system.md` (абзац «Память персоны (`memory_remember`)») критерий сформулирован так: «когда пользователь поправляет тебя в том, что касается СТИЛЯ ОБЩЕНИЯ или его предпочтений… не записывай разовые факты разговора». Для helper'а это верно. Для роли «Психолог» или «Бизнес-наставник» ценное в памяти — как раз факты о человеке: цели, контекст, повторяющиеся ситуации. Сейчас правило их **запрещает** записывать, поэтому память такой роли останется пустой навсегда. Критерий «что запоминать» — роль-специфика, ему место в `templates/prompts/personas/*.md`, а не в общем шаблоне.

**2. Консультант не может запомнить, и предложенный обход пишет не туда.** `consultantTools()` (`src/web/chat-subagent.ts:157`) явно выкидывает `MEMORY_REMEMBER_TOOL` — решение VL-409 верное (консультация не должна молча писать). Но `makeMemoryRememberTool(cwd, persona)` пишет в память **роли треда** (`src/web/chat-memory.ts:70`, инвариант AC6: «модель не должна выбирать, в чью память писать»). Значит «консультант вернул текст → основная роль вызвала `memory_remember`» кладёт наблюдение Психолога в память Помощника: через месяц Помощник считает это своим наблюдением, а память Психолога пуста. Нужен канал, где целевую роль знает **сервер**, а не модель.

**3. Модель не может почистить память.** Лимит `persona_memory.max_chars` (дефолт 2500). При переполнении `appendMemoryEntry` отказывает с текущим размером и лимитом, а сделать что-то модель не может: `removeMemoryEntry`/`clearMemory` доступны только человеку через `/memory remove N` и страницу «Персоны». Память деградирует в «первые N записей навсегда».

**Что уже есть (не дублировать):**
- `src/core/persona-memory.ts` — `readMemoryEntries`, `appendMemoryEntry` (формат `- <текст>. (YYYY-MM-DD)`, отказы: пустой текст, дубль, превышение лимита), `removeMemoryEntry` (1-based), `clearMemory`, `readPersonaMemoryLimit`.
- `src/web/chat-memory.ts` — `makeMemoryRememberTool` (роль параметром, не из аргументов модели), `runMemoryCommand`, `removeMemoryByEvent`, sidecar `<threadId>.memory.json` с отменёнными записями.
- `src/web/chat.ts:1598` — событие `{type:'memory', entry, personaId}` публикуется в `executeTool` (единая точка: цикл, resume, advanceToNextApproval).
- `src/web/chat-subagent.ts` — `buildConsultantPrompt` (промпт + память + уроки), `consultantTools`, `SubagentEvent`.
- `src/core/tool-classify.ts` — `REVERSIBLE_WRITE_TOOLS`: `memory_remember` намеренно не write (запись обратима кнопкой «Убрать»).

## Шаги

### 1. Правило памяти — разделить общее и роль-специфичное

**`templates/prompts/chat-system.md`** — абзац «Память персоны (`memory_remember`)» сократить до механизма:

```
Память персоны (`memory_remember`): у роли есть файл памяти, который подставляется
в каждый следующий ход. Записывай туда устойчивые правила о пользователе — ЧТО именно
считать устойчивым, сказано в промпте твоей роли. Запись применяется сразу и видна
в ленте строкой «Запомнил: …» с кнопкой «Убрать». НЕ записывай то, что относится
к коду проекта (архитектура, соглашения, найденные грабли) — для этого есть lessons.
Не записывай то, что уже есть в памяти.
```

**`templates/prompts/personas/helper.md`** — новый раздел «Память»:

```
## Память

Запоминай поправки о СТИЛЕ ОБЩЕНИЯ и работе с тобой: язык, тон, длина и формат
ответов, чего не делать, как обращаться. Разовые факты разговора («пользователь
спросил про X») не запоминай — они не переживут тред.
```

**`templates/prompts/personas/architect.md`** — раздел «Память»: предпочтения по глубине разбора, формату плана, что показывать/не показывать. Не архитектуру проекта (это lessons/decisions).

**`templates/prompts/personas/supervisor.md`**, **`workflow-designer.md`** — аналогично, коротко.

**Проектные роли** (создаются пользователем через `#/personas`) — критерий задаёт автор роли в её промпте. В doc-6 добавить пример для роли-консультанта («Психолог»: устойчивые особенности человека, повторяющиеся ситуации, цели — но не диагнозы и не разовые жалобы).

### 2. Канал «консультант → его собственная память»

**`src/web/chat-subagent.ts`:**

- В `buildConsultantPrompt` добавить блок:
  ```
  ## Память
  Если по ходу ответа ты узнал о пользователе устойчивое и важное (то, что пригодится
  в следующий раз), перечисли это в САМОМ КОНЦЕ ответа отдельными строками:
  ЗАПОМНИТЬ: <правило одной фразой в императиве>
  Строки служебные — пользователь их не увидит, они попадут в твою память.
  Не более 2 строк за консультацию. Если запоминать нечего — строк нет.
  ```
- Новая чистая функция (тестируемая отдельно):
  ```ts
  export function extractMemoryLines(answer: string): { text: string; entries: string[] }
  ```
  Регулярка `^ЗАПОМНИТЬ:\s*(.+)$` по строкам (multiline, case-insensitive для кириллицы не нужен — префикс фиксированный). Возвращает текст **без** служебных строк (схлопнутые пустые строки в конце) и массив записей. Больше 2 записей — берутся первые 2, остальные отбрасываются (лимит из промпта, но модель может его нарушить).
- После получения `answer` (там, где сейчас формируется `SubagentEvent`): вызвать `extractMemoryLines`, для каждой записи — `appendMemoryEntry(cwd, consultant.prompt, text)`. **Целевая роль — `consultant.prompt`, известна серверу** — инвариант AC6 не нарушен, модель не выбирает файл.
- Отказ `appendMemoryEntry` (дубль, лимит) — не ошибка консультации: собрать в `memorySkipped: Array<{text, reason}>` и вернуть в событии. Консультация успешна, ответ отдан.
- В `SubagentEvent` добавить:
  ```ts
  memory?: Array<{ index: number; text: string; date: string }>;
  memorySkipped?: Array<{ text: string; reason: string }>;
  ```
- `answer` в событии и в tool-результате — **уже без** служебных строк.

**`src/web/chat.ts`:** после `onEvent` для `subagent` — для каждой записи `memory` пушить событие `{type:'memory', entry, personaId: consultant.id}`. Существующий рендер `memory-card.tsx` уже показывает «Запомнил: …» + «Убрать»; добавить в карточку пометку роли, если `personaId !== activePersona.id` («Психолог запомнил: …»). `removeMemoryByEvent` уже принимает роль — проверить, что отмена из карточки консультанта удаляет из файла **консультанта**, а не треда (сейчас роль берётся из треда — это надо расширить).

### 3. `memory_forget` — модель может почистить

**`src/web/chat-memory.ts`** — новый инструмент рядом с `memory_remember`:

```ts
export const MEMORY_FORGET_TOOL = 'memory_forget';
export function makeMemoryForgetTool(cwd: string, persona: PersonaConfig): MemoryTool
```

Схема: `{ index?: number, text?: string }` — ровно один из двух. `index` — 1-based номер из `/memory`; `text` — точное совпадение (нормализованное, как в `appendMemoryEntry` при проверке дубля).

- Оба переданы или ни одного → `{ok:false, error}`.
- `index` вне диапазона → `{ok:false, error, entries: [...]}` — вернуть текущий список, чтобы модель исправилась.
- Успех → `{ok:true, applied:['memory'], removed: {index, text}, chars, limit}`.
- `TOOL_KINDS` не трогать (инструмент локальный, не MCP) — добавить в `LOCAL_TOOL_KINDS` как `'write'`? **Нет**: по той же логике, что `memory_remember` — обратимая запись, добавить в `REVERSIBLE_WRITE_TOOLS` (`src/core/tool-classify.ts`), иначе каждая чистка потребует Allow/Deny. Решение закрепить тестом.
- `chatToolDefs` — добавлять `memory_forget` при известной роли (рядом с `memory_remember`).
- `consultantTools` — **не** выдавать (консультант не чистит чужую память).

**Ответ `memory_remember` при переполнении** — сейчас `{ok:false, error}`. Дополнить: `{ok:false, error, chars, limit, hint: 'Память заполнена. Убери устаревшие записи через memory_forget {index} или попроси пользователя: /memory remove <N>'}` — модель должна знать выход.

## Риски

- **Парсинг текста модели.** Если модель не последует формату — просто ничего не запишется (fail-safe). Не выдавать это за ошибку консультации.
- **Модель напишет `ЗАПОМНИТЬ:` в середине ответа** — регулярка по строкам извлечёт и оттуда; это допустимо (лучше записать, чем потерять), но текст ответа станет рваным. Митигация: в промпте явно «в САМОМ КОНЦЕ».
- **Второй канал записи памяти.** Теперь пишут двое: роль треда (`memory_remember`) и сервер за консультанта. Инвариант AC6 сохранён (модель не выбирает файл), но при аудите это надо помнить. Записать в doc-6.
- **`memory_forget` без Allow/Deny** — удаление записи необратимо (кнопки «вернуть» нет, в отличие от «Убрать» у `memory_remember`). Альтернатива: сделать его write с подтверждением. Решение: оставить обратимым по аналогии, но **добавить** в sidecar `<threadId>.memory.json` запись об удалении, чтобы `/memory` мог показать «удалено моделью». Если это переусложняет — сделать write и не спорить.
- **Лимит 2 записи за консультацию** — эвристика. При `max_calls_per_turn: 2` потолок 4 записи за ход; при лимите 2500 символов это заметно. Следить по факту.
- **Правка шаблонов ролей** — `templates/prompts/personas/*.md` входят в npm-пакет (`npm-smoke.mjs`), правки должны попасть в сборку.

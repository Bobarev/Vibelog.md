## План реализации (тестовая задача, тип: task)

Задача проверочная: фазы workflow выполняют только текстовые действия над задачей, без правок кода и файлов рабочего каталога.

### Файлы для изменения
Нет. Ни один файл репозитория (src/, templates/, package.json, tsconfig.json, vitest.config.mts, backlog/) не изменяется.

### Порядок действий
1. Spec (выполнено): уточнён тип задачи, добавлены AC — фазы делают только текстовые действия.
2. Plan (текущая фаза): записать этот план в задачу через backlog_update_task, отчёт — комментарием, статус → Planned (backlog_finish_phase).
3. Code: выполнить только текстовые действия над задачей — проверить/уточнить заголовок и описание, при необходимости добавить AC, оставить комментарий-отчёт. Никаких write_file/edit/run_shell_command с изменением файлов, никаких git-операций.
4. Close: оставить итоговый комментарий, отметить DoD, перевести задачу в Done. Правок файлов нет.

### Как проверить
- `git status --porcelain` в рабочем каталоге — пусто (кроме служебных .vibelog-артефактов), т.е. код и файлы не тронуты.
- `backlog_view_task VL-111` — план записан, комментарии фаз присутствуют, статус меняется по фазам.
- Полный `pnpm test` не требуется: diff не затрагивает src/, templates/, package.json, tsconfig.json, vitest.config.mts (правило AGENTS.md о полном прогоне для такого diff'а не применяется). При закрытии DoD «Тесты проходят» отмечается с указанием, что изменений кода нет.

### Риски
- Риск ложного «изменения файлов»: агент фазы Code может по инерции создать/править файл — контролируется проверкой `git status --porcelain` и запретом write-инструментов в промпте фазы.
- Риск расхождения статусов: статус меняется только через backlog_finish_phase, отдельные backlog_update_status не вызываются.
- Риск DoD: пункты «Тесты проходят»/«Документация обновлена» формально не применимы (нет кода и документации) — при закрытии фиксируется причина в отчётном комментарии.

3. **package.json** — строка 3, 1.6.0 → 1.7.0. Проверка: `node -e "console.log(require('./package.json').version)"` → 1.7.0.
4. **Веха v1.x на задачи цикла** (по образцу VL-73): извлечь уникальные VL-N из Unreleased-секции CHANGELOG (`node -e` — часть файла до строки `## [1.6.0]`, regex `/VL-\d+/g`, sort unique) и для каждого: MCP `backlog_update_task {id, milestone: "v1.x"}`; вручную добавить саму VL-127. 5. **Сборка и тесты**: `pnpm build && pnpm test` — без падений.
6. **Smoke npm-пакета**: `node scripts/npm-smoke.mjs` (VL-32, обязателен перед publish по AGENTS.md).
7. **Релизный коммит** (только два явных файла): `git add CHANGELOG.md package.json && git commit -m "chore(release): v1.7.0 — vibelog-agent и фазовый оркестратор"`. Тему версии уточнить по содержимому Unreleased (TUI агента на Ink, headless-фазы, worktree-ветки фаз, бот-цикл); образец — коммит 4d7535e `chore(release): v1.6.0 — Telegram Bot`. НЕ добавлять: backlog/, симлинки node_modules/refs, web/dist.
8. **Аннотированный тег**: `git tag -a v1.7.0 -m "v1.7.0 — <та же тема, что в коммите>"` (образец: `git tag -l -n5 v1.6.0`). Проверка: `git cat-file -t v1.7.0` → `tag`.
9. **npm publish** — разрешён без дополнительного согласия (релизная задача, AGENTS.md): `npm publish` (prepublishOnly сам гоняет pnpm build). Проверка: `npm view vibelog.md version` → 1.7.0.
10. **Пуш ветки и тега** — разрешён без дополнительного согласия: `git push origin vb/vl-127 && git push origin v1.7.0`. Проверка: `git ls-remote origin refs/tags/v1.7.0`.
11. **Фаза Close** (автоматически, главный репозиторий): merge vb/vl-127 → master, build+test в главном репо, docs-коммит, Done. VL-127 запись в Unreleased НЕ добавляет (релизная задача, по образцу VL-73).
12. **После Close — пуш master**: `git push` в главном репозитории (close-шаблон запрещает push). Выполняет пользователь или отдельный comment-запрос — иначе gitverse-master навсегда отстанет от npm 1.7.0.

### Как проверить

- `node -e "console.log(require('./package.json').version)"` → 1.7.0
- `sed -n '1,8p' CHANGELOG.md` — пустой [Unreleased], затем `## [1.7.0] — <дата>`
- `pnpm test` — зелёные; `node scripts/npm-smoke.mjs` — OK
- `git cat-file -t v1.7.0` → `tag`; `git tag -l -n5 v1.7.0`
- `npm view vibelog.md version` → 1.7.0
- `git ls-remote origin refs/tags/v1.7.0` — тег на remote (после шага 10)
- MCP `backlog_list_tasks {milestone: "v1.x"}` → задачи цикла

### Риски

- **npm publish и push необратимы** — разрешены для релизной задачи (AGENTS.md, решение Pavel 2026-10-04). Перезаписать 1.7.0 нельзя — при сбое после publish выпускать 1.7.1.
- **Worktree позади master** — без шага 1 CHANGELOG релиза потеряет записи VL-119/VL-121 и publish уйдёт со старым кодом; шаг 1 обязателен и идёт до всех правок.
- **Публикация из worktree** — npm pack берёт содержимое каталога; после шага 1 оно идентично master + релизный коммит; publish только после build/smoke из этого же каталога.
- **Пуш master после Close** — автоматически его не делает никто (close запрещает push); шаг 12 критичен — упомянуть в отчёте Close или передать пользователю.
- **Параллельные ветки** — если master уйдёт вперёд между шагом 1 и Close, merge может дать конфликт; перед релизом не запускать другие фазы.
- **Дата в CHANGELOG** — указать день реального выполнения Фазы 3.
- **Симлинки node_modules/refs** в worktree — untracked, в релизный коммит не добавлять (staging только двух явных путей из шага 7).

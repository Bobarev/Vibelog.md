## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
## Контекст

В разобранном чате пользователь дважды писал «Продолжи», а агент вместо ответа продолжал читать файлы: сначала вопрос о модели при resume остался без ответа (пришлось отвечать уже после отдельной просьбы «Проанализируй чат»), затем на «Продолжить» последовали ещё несколько `read_file`. Причина — не поведение модели per se, а отсутствие в системном промпте веб-чата правила «сначала ответ/план, потом исследование» и отсутствие понимания, что «Продолжи» — это запрос результата, а не разрешение копать глубже.

## Цель

Зафиксировать как процесс то, что в инциденте пришлось исправлять постфактум: ограниченное исследование с ранним ответом.

## Предлагаемое изменение промпта

Добавить в системный промпт веб-чата (и, если применимо, TUI-чата агента) блок из 3 правил:

1. **Ответ раньше полноты.** На вопрос «так ли это / как работает X» — сначала дать ответ по имеющимся данным, затем углублять при необходимости. Если ответа нет — назвать, какого факта не хватает, и что именно будешь искать.
2. **Тайм-бокс.** Ориентир исследования — N вызовов инструментов на один вопрос (например 8-10). При исчерпании — ответить по собранному с явной пометкой «не проверено: …».
3. **«Продолжи» = результат.** Короткое «Продолжи»/«Давай ответ»/«Ну?» — требование выдать ответ по уже собранным данным. Исследование возобновляется только по явной просьбе («проверь ещё», «посмотри код»).

Плюс пункт про навигацию по коду: «не угадывай пути — используй чтение каталога/поиск» (связано с VL-233/VL-234; формулировка не должна ссылаться на инструменты, которых ещё нет).

## Места правки (проверить в Plan)

- `src/agent/system-prompt.ts` — `buildSystemPrompt` (база) либо отдельный блок для чат-режима;
- `src/web/chat.ts` — если у веб-чата свой промпт;
- тесты системного промпта (`*.test.mjs`) — проверка наличия блоков.

## Риски

- Раздувание системного промпта: держать ≤10 строк, без дублирования правил, уже описанных в AGENTS.md (иначе двойной вес в payload — см. VL-230).
- Конфликт с шаблонами фаз (`templates/phase-*`): правила чата не должны применяться к фазам — фазовые промпты строятся отдельно, проверить, что изменение не протекает.

## Входные данные

Инцидент: двойное «Продолжи» без ответа, ответ дан только после третьего явного указания.

## Решение (что и где меняем)

Инцидент (двойное «Продолжи» без ответа) лечится не поведением модели, а промптом. Ключевое наблюдение по коду: **у веб-чата и у агент-чата разные точки сборки промпта**, а фазы делят сборку с TUI-чатом, поэтому правила вставляются opt-in'ом, а не в общую базу.

Точки сборки (проверено grep'ом по `buildSystemPrompt`):
- `src/agent/system-prompt.ts:74` — `buildSystemPrompt(cwd)`: базовая часть `templates/agent-prompt.md` (+ проектное переопределение `.vibelog/prompts/agent-prompt.md`) + AGENTS.md. Вызывается из `src/agent/cli.ts:649` (headless-фазы) и `src/agent/interactive.ts:158` (TUI-чат).
- `src/web/chat.ts:475` — **свой локальный** `buildSystemPrompt(cwd, lastUser, persona)`: `loadChatSystemTemplate(cwd)` (`templates/prompts/chat-system.md`, переопределение `.vibelog/prompts/chat-system.md`) + блок роли + контекст globalSearch. С общей сборкой агента не пересекается.

Отсюда два независимых канала правки: веб-чат (шаблон chat-system.md, код не трогаем) и TUI-чат агента (opt-in блок в общей сборке, чтобы не протечь в фазы: `cli.ts` не получает opts).

Пункт про навигацию («не угадывай пути») **не дублируем**: он уже есть в `templates/prompts/chat-system.md` (последний абзац блока «Повторы и лимиты вызовов», строка 29) и в `templates/agent-prompt.md` (project_map/search_files/листинг каталога). Вместо отдельного пункта — половина строки внутри правила 1 («не угадывай пути — используй листинг каталога и поиск»), чтобы не платить дважды за один смысл (VL-230).

- **Третий вызов сборки**: `src/web/chat.ts` имеет собственную функцию с другим набором аргументов — сигнатуру общей сборки менять безопасно; перед правкой сверить grep'ом, что вызовов `buildSystemPrompt(` из `src/agent/` ровно два.

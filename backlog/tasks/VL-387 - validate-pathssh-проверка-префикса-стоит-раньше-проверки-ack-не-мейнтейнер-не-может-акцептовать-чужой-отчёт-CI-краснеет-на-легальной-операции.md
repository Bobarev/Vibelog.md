## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
## Симптом

Живой прогон VL-375 (`vl` → `vl`, ack) прошёл, потому что автор — мейнтейнер. Для не-мейнтейнера легальный ack чужого отчёта CI-валидацией **отклоняется**.

## Корень

В `.gitverse/scripts/validate-paths.sh` порядок проверок неверный:

```
4.1  A*: source_prefix == каталог
     is_maintainer → continue                    ← строка 215
4.2  if ALLOWED непусто:
       префикс должен быть в ALLOWED             ← строка 220-228
       continue                                  ← строка 229 (выход из итерации!)
4.3  M*: только status/accepted_as (ack)         ← строка 233
```

Проверка 4.2 стоит раньше 4.3 и делает `continue`. Поэтому для автора с маппингом (`ui: ui`), который акцептует отчёт из `reports/vl/`:

```
prefix  = vl
ALLOWED = ui
→ fail: автор «ui» не может изменять reports/vl/
```

CI краснеет на легальной операции. По замыслу ack разрешён **всем** — это смысл протокола: получил отчёт → подтвердил получение.

Дополнительно: ветка `4.3 A*` («автор не найден в prefixes.yml → создавать нельзя») недостижима для авторов с маппингом — до неё не доходит из-за `continue` в 4.2. Сейчас это работает «случайно правильно», но структура хрупкая.

## Почему не проявилось

Автор живого прогона — `bobarev`, он в `MAINTAINERS` (строка 215 → `continue`). Мейнтейнер обходит и 4.2, и 4.3. Как только отчёты начнут акцептовать дочерние проекты (`ui`, `tpl`) — CI сломается.

## Цель

Ack — отдельный класс изменения, не связанный с владением каталогом. Порядок должен быть: «что именно изменено» → потом «чей это каталог».

## План

Файл: `.vibelog/upstream-inbox/.gitverse/scripts/validate-paths.sh` (клон инбокса; правка коммитится и пушится в репозиторий `Vibelog-md/upstream-reports`).

### 1. Переставить проверку ack выше проверки префикса

Сейчас (строки 213–250):

```bash
  # Мейнтейнер проходит дальше без ограничений по префиксу.
  if is_maintainer; then continue; fi          # 215

  # 4.2. Префикс должен быть разрешён автору.
  if [ -n "$ALLOWED" ]; then
    ... fail "автор «$ACTOR» не может изменять reports/$prefix/ ..."   # 226
    continue                                    # 229  ← съедает ack
  fi

  # 4.3. Маппинга нет: ack чужого отчёта.
  case "$status" in M*) ... esac               # 233
```

Стало:

```bash
  # Мейнтейнер проходит дальше без ограничений по префиксу.
  if is_maintainer; then continue; fi

  # 4.2. Изменение (M*) существующего отчёта: разрешён ТОЛЬКО ack —
  # две строки фронтматтера (status, accepted_as). Проверяется ДО
  # владения каталогом: акцептовать чужой отчёт может любой актор,
  # это смысл протокола «получил → подтвердил».
  case "$status" in
    M*)
      if [ -n "$COMPARED_FROM" ]; then
        bad="$(git diff "$COMPARED_FROM" "$HEAD_SHA" -- "$path" \
          | grep -E '^[+-][^+-]' \
          | grep -vE '^[+-][[:space:]]*(status|accepted_as):' || true)"
      else
        bad="$(git show "$HEAD_SHA" -- "$path" \
          | grep -E '^[+-][^+-]' \
          | grep -vE '^[+-][[:space:]]*(status|accepted_as):' || true)"
      fi
      if [ -z "$bad" ]; then
        info "ack отчёта: $path"
        continue                      # ack валиден независимо от владения каталогом
      fi
      # Не ack — обычное изменение, дальше проверяется владение.
      ;;
  esac

  # 4.3. Владение каталогом: префикс должен быть разрешён автору.
  if [ -n "$ALLOWED" ]; then
    ... (проверка как была; при несовпадении — fail)
    continue
  fi

  # 4.4. Автор без маппинга: создавать отчёты нельзя (M* уже разрешён выше).
  case "$status" in
    A*) fail "автор «${ACTOR:-<неизвестен>}» не найден в $PREFIXES_FILE — ..." ;;
  esac
```

Ключевое: `M*` с изменёнными не-ack полями **не** `fail` сразу, а проваливается дальше — там его поймает проверка владения (чужой каталог → отказ), либо пропустит (свой каталог → законная правка).

### 2. Обновить комментарий-шапку

Раздел «Инварианты» скрипта (строки 15–22) — переписать пункт 4: сейчас «Изменение чужого отчёта — только поля status: и accepted_as (ack)». Уточнить: ack проверяется до владения каталогом и разрешён всем, включая акторов без маппинга.

### 3. `prefixes.yml` — добавить дочерние проекты

```
bobarev: vl
ui: ui
tpl: tpl
```

Без этих строк проверка владения не знает префиксов дочерних проектов и пропускает их (fail-open по `ALLOWED`-пустоте). Добавлять по мере появления реальных проектов; `ui`/`tpl` — заготовка для пункта 2 проверки живого mesh.

### 4. README инбокса

Раздел про модель доступа: явно записать, что ack — операция, разрешённая **всем** акторам, и не требует владения каталогом. Сейчас это неочевидно и как раз привело к дефекту.

### 5. Проверка

```bash
bash -n .gitverse/scripts/validate-paths.sh     # синтаксис
```

Локальная проверка на фикстуре (временный git-репозиторий с двумя коммитами, `ACTOR=ui`, `BASE_SHA=<первый>`, `HEAD_SHA=<второй>`):

| Кейс | Ожидание |
|---|---|
| `ui` акцептует `reports/vl/x.md` (2 строки) | exit 0, «ack отчёта» |
| `ui` правит тело `reports/vl/x.md` | exit 1 |
| `ui` создаёт `reports/vl/y.md` | exit 1 |
| `ui` создаёт `reports/ui/z.md` | exit 0 |
| `ui` акцептует `reports/ui/z.md` | exit 0 |
| `bobarev` что угодно | exit 0 |

Затем пуш в инбокс и проверка CI на коммите фикса (зелёный).

### 6. Живая проверка mesh (пункт 2 из плана VL-375)

1. В `Vibelog.md/.vibelog/settings.json` — секция `upstream` уже в git-режиме.
2. В дочернем проекте `ui`: секция `upstream` с тем же `inbox` и `prefix: "ui"`.
3. Отчёт `ui` → `vl` (`--target vl`) → CI зелёный, отчёт в `reports/ui/`.
4. В `vl`: `upstream pull` видит его; `upstream ack` → CI **зелёный** (это и есть проверка фикса).
5. Отчёт `vl` → `ui` — обратное направление.

### Риски

- **Регресс в защите.** После переноса ack-проверки вверх надо убедиться, что правка тела чужого отчёта по-прежнему блокируется: не-ack `M*` не должен молча проходить. Кейс из таблицы это покрывает.
- **`continue` в ветке ack.** Он выходит из цикла по файлам — для одного файла это корректно, но при нескольких изменённых файлах в коммите каждый проверяется независимо; `continue` не должен «проглатывать» последующие файлы.
- **Порядок в `prefixes.yml`.** `grep -E "^${actor}:"` берёт первую строку — логины не должны быть префиксами друг друга.

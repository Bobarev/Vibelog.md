## Implementation Plan
<!-- SECTION:PLAN:BEGIN -->
## Метод аудита (все проверки на Node.js, без внешних рантаймов)

50 файлов `src/**/*.test.mjs`, все импортируют из `../../dist/`. Тесты считаются устаревшими, если:
1. Тестируют функции/CLI-поведение, которых больше нет в `dist/` (импорт падает или функция вернула не тот контракт);
2. Дублируют друг друга (например, общий core.test.mjs vs узкие store/config/frontmatter — если проверки идентичны);
3. Проверяют поведение, явно заменённое более новыми тестами (ищем по датам/VL-номерам в заголовках);
4. Тест-заглушки вида `it.skip('...')` безусловно (compat.test.mjs:29,59,83,117,136 — это условные skip при отсутствии refs/, их НЕ удалять, они валидны).

## Порядок действий
1. `pnpm build` — чтобы dist/ был актуален.
2. По каждому файлу: прочитать заголовок (первые ~15 строк) → найти импортируемые символы → `grep -n "<символ>" src/**/*.ts` — существует ли источник и не изменился ли контракт.
3. Быстрый скрининг: `node --test src` сейчас зелёный? Если тест падает/пропускается всегда — кандидат на удаление/чинку.
4. Удалить устаревшие файлы/тесты целиком (решение Фазы 1: удалять, не переписывать).
5. Зафиксировать в комментарии задачи: файл → что удалено → почему устарело.

## Кандидаты для пристального взгляда (по результатам первичного просмотра)
- `src/core/compat.test.mjs` + `src/core/compat-full.test.mjs` + `src/core/frontmatter.test.mjs` — пересекаются между собой и с `refs/` (проверить дублирование кейсов back-100/back-200).
- `src/core/core.test.mjs` (37 it) — возможно, часть уже покрыта узкими store/config/add-comment тестами.
- `src/mcp/v11.test.mjs`, `src/mcp/types.test.mjs` — исторические тесты на релизные фичи, сверить актуальность.
- `src/cli/update-check.test.mjs` — устарел, если update-check вынесен/переписан (проверить src/cli/update-check.ts).

## Проверка
- `pnpm test` после каждого удаления — падений нет.
- `node --test src 2>&1 | grep -c "^# pass"` — количество прошедших тестов не упало без причины (удалённые — только устаревшие).

## Риски
- Главный риск — удалить «сложный, но живой» тест (например, worktree.test.mjs:182 со skip при отсутствии tsc). Перед удалением каждого файла — обязательная сверка импортов с dist/.
- refs/Backlog.md может отсутствовать в других машинах — условные skip-тесты оставляем.

## Context

`vb create` должен откуда-то брать проект-заготовку. Рассматривалось: репозиторий на шаблон против монорепозитория; отдельный `template.json` против метаданных в `package.json`; способ получения только нужной папки (клон целиком с удалением лишнего, zip-архив, degit, `git sparse-checkout` с частичным клонированием).

Ожидаемый масштаб — 10–20 шаблонов, поэтому клонировать весь репозиторий и удалять лишнее неработоспособно.

## Decision

1. **Монорепозиторий `Vibelog-md/templates`** (организация `Vibelog-md` на GitVerse), шаблон — подпапка верхнего уровня (`svelte-minimal`, будущий `svelte-max`). Имя репозитория — `templates`, а не `boilerplates`/`starters`: короче, чаще встречается в CLI-флагах (`--template`), ниже шанс опечатки у агента, консистентно с командой `vb create myapp --template vibelog.md/templates/svelte-minimal`.
2. Ссылка резолвится через тот же механизм алиасов, что и `vb install` (decision-8): `vibelog.md` → owner `Vibelog-md`, второй сегмент `templates` → repo, третий — имя шаблона. URL клонирования — `https://gitverse.ru/Vibelog-md/templates.git`.
3. **Ветка конфигурируемая, дефолт `main`.** Значение берётся из записи реестра в `.vibelog/config.json` (для `vb install`) и из флага `--branch` (для `vb create`, у шаблонов может отличаться). Хардкода ветки в коде нет.
4. **Метаданные шаблона — в `package.json`**, без отдельного `template.json`. Ключи `name`, `version`, `description`, `scripts` уже есть; кастомное поле `vibelog` (`type: "template"`, `components: []`) расширяемо; меньше сущностей — проще. Хук создания — `scripts.postCreate` (например `vb init`).
5. **Порядок `vb create`:** прочитать `package.json` шаблона и проверить `vibelog.type === "template"` → скопировать файлы шаблона в целевую директорию → удалить временный клон → спросить пакетный менеджер и установить зависимости → выполнить `postCreate` → если `vibelog.components` непустой, выполнить `vb install` для каждого компонента.
6. **Клонирование только нужной папки — `git sparse-checkout` + частичное клонирование**, строго в этом порядке:
   ```
   git clone --filter=blob:none --no-checkout --depth 1 --branch <ветка> <URL> temp-dir
   git sparse-checkout init --cone
   git sparse-checkout set svelte-minimal
   git checkout <ветка>
   ```
   `sparse-checkout set` выполняется после `clone` и **до** `checkout`; при обратном порядке скачаются все файлы.
7. **Запасной путь:** если сервер не поддерживает фильтрацию (нет `uploadpack.allowFilter`), git выдаёт предупреждение `filtering not recognized by server, ignoring` и скачивает все blob, но `sparse-checkout` всё равно разворачивает только нужную папку — медленнее, но корректно. `vb create` проверяет вывод на это предупреждение и при необходимости переходит на скачивание zip-архива или сторонний инструмент типа `degit`.
8. **Целевая директория:** `vb create myapp` создаёт `./myapp` в текущем каталоге, без дополнительных вопросов. Имя валидируется по npm-правилам (lowercase, без пробелов, допустимы `-`, `_`, `.`). Если каталог уже существует — ошибка с кодом выхода 2 (`--force` не предусмотрен).
9. `vb create` выполняет `git init` и первый коммит в созданном проекте.
10. **Состав шаблона `svelte-minimal`** (из `sv create`): обязательны `tailwindcss`, `prettier`, `eslint`, `ai-tools`; рекомендуются `vitest` и `sveltekit-adapter` по ситуации; не выбираются `playwright`, `storybook`, `drizzle`, `better-auth`, `mdsvex`, `paraglide`, `enhanced-img`, experimental. Плагины Tailwind `typography` и `forms` не подключаются. Дополнительно в шаблон кладётся файл правил агента (`CLAUDE.md` / `.cursorrules`, см. decision-6).

## Consequences

- Общие настройки (версии ESLint/Prettier, правила) обновляются одним коммитом на все шаблоны.
- Логика `vb create` проста: один URL репозитория, имя шаблона — подпапка, ветка — параметр.
- Масштабирование до 10–20 шаблонов не требует изменений в CLI.
- Цена: зависимость от поддержки partial clone на GitVerse — закрывается запасным путём и предупреждением в выводе.
- Цена: `package.json` шаблона — одновременно метаданные и манифест зависимостей; возможна путаница, но выигрыш в простоте перевешивает.
- Цена: общий `.gitignore`/конфиги в монорепозитории требуют аккуратности, чтобы шаблоны не тянули файлы друг друга.

## Alternatives

- **Отдельный репозиторий на шаблон** — чище изоляция, но 10–20 репозиториев это организационная нагрузка, общие настройки обновляются по одному, `vb create` должен знать список репозиториев.
- **Отдельный `template.json`** — дублирует `name`/`description`/`scripts` и добавляет сущность, которую агент знает хуже, чем `package.json`.
- **Клон всего монорепозитория с последующим удалением лишних папок** — просто в реализации, но линейно растёт по времени и трафику с числом шаблонов.
- **Сразу zip-архив или `degit`** — меньше зависимость от git, но либо теряется точечный sparse-checkout, либо добавляется сторонний инструмент в зависимости CLI.
- **Хардкод ветки `main`** — проще, но шаблоны и реестр могут разойтись по веткам; ветка-параметр стоит одной строки кода.

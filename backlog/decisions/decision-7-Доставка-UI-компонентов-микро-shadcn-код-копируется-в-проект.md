## Context

UI Kit нужен как тестовый проект Vibelog.md и одновременно как реально используемый набор компонентов (первый кейс — MAX Mini App). Рассматривались три модели распространения компонентов:

1. npm-пакет с компонентами (`@vibelog/ui`) — как у обычных библиотек.
2. Зависимость от готовой библиотеки (shadcn-svelte, Sivir UI) и обёртки над ней.
3. shadcn-модель: код компонента копируется в репозиторий проекта и принадлежит проекту.

Ограничения: продукт строится по принципу zero human code (агент правит код, человек проверяет результат), агенту нужно дёшево и предсказуемо менять компоненты под задачу; при этом оригинальный shadcn недоступен из Крыма без прокси.

## Decision

Принята shadcn-модель («микро-shadcn») в собственной реализации:

1. **Zero runtime dependencies** — в проекте нет библиотек в `node_modules`, которые работают в рантайме. Весь код компонентов — свой, лежит в репозитории проекта.
2. Компонент доставляется командой `vb install`, которая скачивает JSON из реестра и раскладывает файлы **внутрь проекта** по путям из `.vibelog/config.json`.
3. Агент или человек вправе свободно править скопированный файл — это его код. Учёт локальных правок ведётся через хеши в `.vibelog/manifest.json` (см. decision-10).
4. Рантайм-зависимости допускаются только поведенческие и только явно объявленные в реестре: `bits-ui` для Dialog, DropdownMenu и подобных; `clsx` + `tailwind-merge` для `cn`. Такие зависимости устанавливаются через npm и фиксируются в манифесте как npm-зависимости.

## Consequences

- Агенту не нужно обходить API библиотеки — он правит файл, что резко снижает стоимость доработок под задачу.
- Нет проблем с версиями транзитивных зависимостей: код в проекте, версия отслеживается хешем, а не semver-диапазоном.
- Цена: обновления не приходят сами — нужен `vb update` и осознанное решение при локальных правках (decision-10).
- Цена: дублирование кода между проектами (каждый проект хранит свою копию компонента) — приемлемо, компоненты малы и правятся под задачу.
- Необходимо поддерживать собственный реестр и его сборку (decision-8).

## Alternatives

- **npm-пакет `@vibelog/ui`** — привычные обновления и единая версия, но агент ограничен публичным API, доработка «под задачу» требует форка или обёрток, появляется рантайм-зависимость и цепочка транзитивных пакетов; противоречит принципу zero runtime dependencies.
- **Тонкие обёртки над shadcn-svelte / Sivir UI** — быстро на старте, но тянет рантайм-зависимость, а правка поведения упирается в чужой код в `node_modules`.
- **Копирование вручную через `npx shadcn add <url>`** — формат совместим и это остаётся возможным, но без собственного CLI нет ни манифеста, ни версионирования, ни проверки базовых файлов.

## Context

Для доставки компонентов нужен реестр: место, откуда `vb install` берёт JSON с файлами. Оригинальный shadcn недоступен из Крыма без прокси. Рассматривались варианты: свой реестр на GitVerse, зеркало shadcn, npm-пакет, раздача JSON из того же репозитория, что и код `vb`.

Ограничение: агент должен однозначно понимать, по какому URL и в каком формате лежит компонент, и не зависеть от доступности зарубежных сервисов.

Разделение репозиториев: сам Vibelog.md живёт в `bobarev/Vibelog.md`; всё остальное — в организации `Vibelog-md` (создана): `Vibelog-md/ui` — реестр компонентов, `Vibelog-md/templates` — шаблоны проектов.

## Decision

1. Реестр компонентов — отдельный репозиторий `https://gitverse.ru/Vibelog-md/ui`.
2. Формат совместим со схемой shadcn (`registry.json`, `registry:ui`, `files[].path/type/target`, `registryDependencies`), чтобы при желании компонент можно было поставить через `npx shadcn add <url>` и чтобы агент работал с уже известным ему форматом.
3. Разделение source / built:
   - `src/lib/components/ui/<name>/` — исходники, которые правят люди и агент;
   - `public/r/<name>.json` — сгенерированные JSON, раздаваемые по HTTP; `vb install` читает **только** built-версию.
4. **Синтаксис ссылки: `owner/repo/component`, где первый сегмент — алиас реестра, а не настоящий owner.** В GitVerse владелец не может содержать точку, поэтому `vibelog.md` заведомо не может быть реальным owner-ом и однозначно читается как алиас `Vibelog-md`. Разбор: `[0]` → ключ в `registries` из `.vibelog/config.json` (даёт `owner` и `branch`), `[1]` → **repo** (`ui` / `templates`), `[2]` → имя компонента или шаблона.
5. **Запись реестра — плоская:** `{"registries": {"vibelog.md": {"owner": "Vibelog-md", "branch": "main"}}}`. Репозиторий берётся из пути, поэтому в записи его нет. Ветка — конфигурируемая, дефолт `main`; `branch` принимает строку и допускает расширение до объекта `{default, <repo>}` без ломающей миграции.
6. **URL — API-форма GitVerse:** `https://gitverse.ru/api/repos/{owner}/{repo}/raw/branch/{branch}/{путь}`, например `https://gitverse.ru/api/repos/Vibelog-md/ui/raw/branch/main/public/r/button.json`. `urlTemplate` зашит в CLI и в `config.json` не хранится — в конфиге только `owner` и `branch`.
7. Корневой пакет `vibelog.md/ui` — отдельный элемент реестра с базовыми файлами (`utils.ts` с `cn`, CSS-переменные темы). Компоненты объявляют его в `registryDependencies`.
8. Реестр версионируется обычными тегами; версия компонента попадает в его JSON при сборке и далее в `.vibelog/installed.lock.json` проекта-потребителя.

## Consequences

- Полная независимость от доступности shadcn/npm-registry; реестр на том же хостинге, что и остальная инфраструктура.
- Формат shadcn — бесплатная совместимость с экосистемой и знакомый LLM формат.
- Алиас вместо owner-а делает ссылку стабильной: переезд репозитория или смена организации правится в `config.json`, а не в документации и не в промптах агента.
- Цена: реестр надо сопровождать — сборка `public/r/*.json` из `src/` должна быть детерминированной и проверяться в CI, иначе `vb install` раздаст устаревший JSON.
- Цена: один `branch` на все репозитории реестра — при расхождении веток потребуется расширение схемы (предусмотрено).
- Корневой пакет — отдельная точка отказа: его изменение влияет на все компоненты во всех проектах.

## Alternatives

- **Зеркало/прокси оригинального shadcn** — требует прокси, который и есть причина отказа; зависимость от чужой инфраструктуры сохраняется.
- **npm-пакет с JSON-манифестами** — лишний слой публикации и невозможность читать файлы по простому HTTP; противоречит идеологии «код принадлежит вам».
- **Раздавать JSON прямо из `src/` через raw, без сборки** — не нужно собирать, но ломает совместимость с shadcn, смешивает source и built и делает невозможной валидацию схемы на выдаче.
- **`host/owner/repo/component` с реальным owner-ом** — однозначнее, но привязывает ссылки к текущему владельцу и требует поддержки нескольких хостов, которая на первом этапе не нужна.
- **`urlTemplate` в `config.json`** — гибче, но дублирует знание о GitVerse в каждом проекте и открывает возможность «сломать» установку правкой конфига.

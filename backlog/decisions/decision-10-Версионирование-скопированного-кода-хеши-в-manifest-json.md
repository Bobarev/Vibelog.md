## Context

При модели «код компонента копируется в проект» (decision-7) встаёт вопрос обновлений. У shadcn встроенного версионирования нет: CLI не записывает установленную версию, автоматического обновления не существует, люди выкручиваются через `npx shadcn diff`, ручной `git merge-file` или сторонние инструменты, которые пишут версию и хеш файла в свой конфиг.

Для Vibelog.md сложность усиливается принципом zero human code: файл компонента регулярно правит агент, и система должна отличать «это наш исходник» от «это локальная правка».

## Decision

1. При каждой установке `vb install` пишет в `.vibelog/manifest.json` для каждого компонента и каждого файла: `version` (версия компонента на момент установки), `hash` (`sha256:` содержимого записанного файла), `sourceVersion` (версия в реестре), `installedAt`.
2. Версии — простые (`1.0.0`, `1.0.1`), без `^` и `~`. Никакой семантики транзитивных зависимостей: компонент — это код, а не библиотека.
3. `vb update` (следующий этап) работает детерминированно:
   - хеш файла в проекте **совпадает** с хешем в манифесте → файл не менялся → безопасная перезапись новой версией;
   - хеш **не совпадает** → файл правился человеком или агентом → не перезаписывать: показать diff и спросить (или пропустить в `--yes`-режиме).
4. Хеш может обновлять агент после собственной правки файла — тогда система знает, что это осознанная локальная модификация, а не расхождение.
5. Манифест — коллектор данных с первого дня: `vb install` пишет версии и хеши уже сейчас, даже пока `vb update` не реализован.
6. Сборка реестра (decision-8) при каждом релизе компонента обновляет его версию, иначе сравнение версий бессмысленно.

## Consequences

- Детерминированное управление версиями без npm-семантики: отслеживается не «пакет версии X», а «этот файл, скопированный из версии X, с тех пор не менялся».
- Локальные правки агента никогда не затираются молча — главный риск zero human code закрыт.
- Цена: обновление не автоматическое, требуется явный вызов `vb update` и решение по конфликтным файлам.
- Цена: манифест надо держать в git вместе с проектом, иначе история правок теряется между машинами.
- Ограничение: хеш ловит факт изменения, но не его смысл — содержательный мерж остаётся за агентом/человеком.

## Alternatives

- **npm-семантика версий (`^`/`~`)** — не применима: нет пакета, нет транзитивных зависимостей, а диапазоны создают иллюзию автоматического обновления.
- **Только `npx shadcn diff` без манифеста** — не знает, что именно было установлено, поэтому diff сравнивает с последней версией реестра, а не с установленной; ручной мерж каждый раз.
- **Без версионирования (перезапись при каждом install)** — просто, но гарантированно уничтожает правки агента.
- **Отдельный git-репозиторий/сабмодуль для скопированного кода** — лишняя механика для набора небольших файлов.

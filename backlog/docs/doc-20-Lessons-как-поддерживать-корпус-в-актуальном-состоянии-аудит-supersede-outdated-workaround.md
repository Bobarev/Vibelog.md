# Lessons: как поддерживать корпус в актуальном состоянии

Корпус `backlog/lessons/` — живая память проекта: в отличие от задачи, урок не замораживается после Done. Он уточняется, объединяется и устаревает вместе с кодом. Этот документ фиксирует процесс поддержки, введённый санитарным проходом (VL-281) после появления инструментов аудита (VL-279) и классификации обходов (VL-280).

## Зачем это нужно

Корпус без ревизии деградирует предсказуемо: дубли одного правила (их находят только по similarity), утверждения о коде, который уже переписан (битые пути и «мёртвые» советы), обходные пути, записанные как норма поведения. Такой корпус не помогает, а учит неправильному: Plan подставляет уроки в промпт автоматически, и устаревший урок работает как инструкция.

Санитарный проход по 153 урокам дал исходную картину и закрыл её: **6 битых путей, 8 находок duplicate_of, 0 висячих ссылок на задачи, 0 протухших** — после разбора осталось 0 находок всех типов.

## Регулярность аудита

- **Механика — часто и дешево.** `vibelog lesson audit` (или MCP `lesson_audit`) — read-only, занимает секунды. Гоняй его: перед началом крупного эпика, в конце месяца, после серии задач в одну область (тесты, web, агент, worktree).
- **Отчёт — в репозиторий.** `vibelog lesson audit --write` пишет `backlog/lessons/AUDIT.md` (сводка по типам + строки находок). Файл коммитится: по нему видно динамику, а не только текущее состояние.
- **Смыслы — редко и вручную.** Механический аудит не решает, «верен ли урок». Разбор находок — отдельная задача (как VL-281): агент предлагает решения, человек их проверяет. Разбивай такой проход по тематическим блокам (tags), если уроков больше сотни — один ран не должен съесть весь контекст.

## Что значит `needs-review`

Статус-карантин для уроков, где **причина неясна**: аудит нашёл проблему, но непонятно, устарел урок или просто требует правки. Правило: сомневаешься — `needs-review`, не `outdated`.

- `needs-review` **не подставляется** в промпты Plan (используются только `active`) — то есть сомнительный урок перестаёт учить, но не теряется.
- Разрешён явным списком ID, а не «всё найденное»: `vibelog lesson audit --needs-review lesson-12,lesson-40` или MCP `lesson_audit {"needsReview": ["lesson-12"]}`. Флага «применить всё» у инструментов нет намеренно (lesson-147).
- Снимается содержательной проверкой: урок переписан и `lesson_update {status: active}` + `lastVerified`/`verifiedBy: agent`, либо переведён в `outdated`/`superseded` с причиной.

Поле `last_verified` ставится **только после реальной сверки урока с кодом** (проверил путь, символ, поведение) — простановка даты «чтобы не висело» запрещена: аудит считает такой урок проверенным.

## Как оформлять `superseded` (свести дубль)

Дубли **не удаляются** — история урока нужна, чтобы понимать, откуда взялось правило. Сведение — через `supersede`:

```bash
vibelog lesson supersede lesson-29 lesson-140        # lesson-140 заменяет lesson-29
# MCP: lesson_supersede {"oldId": "lesson-29", "newId": "lesson-140"}
```

Что происходит и что нужно сделать руками:

1. Старый урок → `status: superseded`; актуальный → `active` с `supersedes: <oldId>`.
2. **Актуальный урок должен впитать факты старого** (все формулировки, все исторические примеры, которые ещё ценны) — иначе сведение теряет информацию. Проверь это до вызова supersede.
3. В теле старого урока первой строкой Решения добавь «Заменён: `lesson-N`», чтобы читающий сразу уходил к актуальному.
4. Цепочки допустимы (A → B → C), циклы — нет: аудит ловит `supersede_cycle` и `broken_supersede` (ссылка на несуществующий ID).

Пример из прохода VL-281: три урока про «не вставляй ID задач VL-N в `templates/`» (lesson-29, lesson-107, lesson-140) сведены в один — lesson-140 впитал оба инвариант-теста, правило «ни один файл `templates/`» и формулировки без ID; lesson-29 → lesson-107 → lesson-140 выстроены цепочкой, старые помечены `superseded`.

## Как оформлять `outdated`

`outdated` — не «старый», а **неверный сегодня**: утверждение урока перестало соответствовать коду или процессу. Обязательное требование: **явная причина в теле урока** (раздел «Почему урок устарел»), иначе читатель не поймёт, можно ли ещё опираться на историю.

Минимальный шаблон:

```markdown
## Почему урок устарел

<что именно изменилось: задача/коммит, новый модуль, отменённое правило>

## Что осталось верным

<общая часть правила, если она жива; иначе — «ничего, см. lesson-N»>
```

Пример из прохода: lesson-84 («переименуй `.vibelog/settings.json` перед разбором падений llm-тестов») → `outdated`, потому что VL-240 задал `apiMode` явно и причина исчезла; lesson-52 («выноси сетевой reference.test в отдельный запуск») → `outdated` после фикса VL-225 (фикстуры `file://`, таймаут 15 с), но общее правило «зависший файл — отдельным запуском» сохранено в теле.

## Куда идут `workaround`-уроки

Классификация (MCP `lesson_classify`) помечает урок `kind: workaround`, если он описывает обход дефекта, а не правило. Обход в корпусе — это долг: он легализует ритуал («всегда делай X перед Y») вместо лечения причины.

Процесс:

1. Кластеры `workaround` по одной теме сводятся в **одну** задачу техдолга: `vibelog`/MCP `lesson_classify` с `createClusters: ["tag:…"]` (не больше N задач за вызов, настройка `lessons.tech_debt_max_tasks`).
2. Задача получает описание с причиной обхода, списком уроков-источников и ожидаемым результатом («обход больше не нужен»).
3. Связь **двусторонняя**: `lesson_link {lessonId, taskId}` — в уроке появляется `linked_tasks`, в задаче `lessons`.
4. В теле урока — строка **«Устранение: VL-N»** с указанием, что именно закроет причину.
5. Когда задача техдолга закрыта: урок переводится в `outdated`/`superseded` (или переписывается в правило «как теперь устроено»). Обход, оставленный `active` после устранения причины, — снова долг.

Пример из прохода: уроки lesson-88 / lesson-113 / lesson-120 (ритуал `env -u VIBELOG_*` перед полным прогоном) классифицированы как `workaround`, сведены в задачу **VL-286**; в каждом теле стоит «Устранение: VL-286» с указанием, что именно нужно закрыть (общий тестовый хелпер, чистящий env при спавне CLI/MCP).

## Чек-лист роли (для человека и агента)

- [ ] `vibelog lesson audit --write` прогнан, `backlog/lessons/AUDIT.md` обновлён и закоммичен.
- [ ] Каждая находка разобрана: исправлена, `outdated`/`superseded` с причиной, либо `needs-review`.
- [ ] Ни одного «молчаливого» `outdated` без раздела «Почему урок устарел».
- [ ] Все `workaround`-кластеры имеют задачу техдолга, двустороннюю связь и строку «Устранение: VL-N».
- [ ] Повторный прогон аудита не даёт новых `broken_supersede` / `duplicate_of` по обработанным парам.

# Веб-чат: панель токенов, стоимости и заполнения контекста

**Статус:** реализовано в VL-313 (ветка `vb/vl-313` слита в master)
**Источник:** обсуждение с Pavel (сессия по трём фичам чата; фича 1 из 3)
**Связанное:** ref-23 (assistant-ui Elements: ContextDisplay), doc-13 (компакшн), doc-22 (каталог предложений)

## Цель

Показать в веб-чате, сколько стоил диалог: токены по типам (входящие / исходящие / кэш),
потраченные рубли и процент занятого контекста — чтобы пользователь видел цену и приближение
к лимиту окна, не уходя из чата.

## Решение по плейсменту (выбрано)

**Панель вверху чата**, статично/приклеена (static/sticky), полупрозрачная, с небольшими иконками.

- Изначально рассматривался ring у кнопки отправки (как в примерах assistant-ui) — **отклонён**:
  при ручной установке элемента важнее простая встраиваемая панель; ring у Send оставляем как
  возможное расширение позже.
- Компоненты берём из assistant-ui Elements (`ContextDisplay`, вариант `Bar`/`Text`),
  устанавливаются через shadcn-CLI: `pnpm dlx shadcn@latest add "@assistant-ui/context-display"`.
  **Требуется прокси/VPN** → установка вручную (см. reference, там же fallback-URL registry).
- Полупрозрачность: `bg-background/70` + `backdrop-blur-sm` + нижняя граница `border-b`.
- Небольшие иконки: вход ↓, выход ↑, кэш (database), рубли (circle-dollar-sign),
  контекст (кольцо/полоса).

## Состав показателей

- input / output / cache — токены по типам (+ reasoning отдельной строкой, в output НЕ подмешиваем);
- requests — число вызовов модели за тред;
- ₽ — стоимость по тарифу **той модели, что использовалась в треде** (не `models.default`!);
- % контекста = **пик (input + cache) по запросам треда** / `context_window` модели.

## Мобильная раскладка

- Было: `ModelPicker` скрыт на узком экране (`hidden sm:flex`), роль — видна всегда.
  Стало наоборот: на узком экране виден выбор модели (усечённый label), роль скрыта.
- Роль фиксируется за тредом при первом ходе (VL-283) и в начатом чате всё равно не выбирается —
  потеря бейджа на мобильном некритична.

## Критерии приёмки (выполнены)

1. После каждого ответа модели панель обновляется без перезагрузки страницы.
2. После перезагрузки треда панель восстанавливает те же цифры (persist usage + ответ API).
3. Процент контекста считается как пик по запросам треда, а не сумма по ходам.
4. ₽ считаются по тарифу модели треда; смена модели в пикере не пересчитывает старые ходы по чужому тарифу.
5. Модель без `context_window`: панель показывает токены/₽ без процента, «0%» не показывается.
6. Панель видна на мобильном и не ломает прокрутку ленты.
7. Reasoning не подмешивается в output.

## Риски / открытые вопросы

- **Двойной счёт кэша.** В Responses API (ref-18) `cached_tokens` — подмножество input; сложение
  `input + cache` для процента может завышать. Проверено на шаге реализации: `normalizeUsage`
  (`src/agent/llm.ts`) приводит оба режима к одной семантике, `contextTokens(input, cache)` считает
  пик по нормализованным значениям.
- Usage в Responses-режиме приходит в конце стрима → панель обновляется скачком, не инкрементально.
  AC сформулирован как «после завершения ответа» — для MVP принято.
- Ручная установка элемента: registry был недоступен, файлы разложены вручную
  (зависимости элементов: `elements-surfaces`, `utils/tokens#formatTokenCount`).
- Поповер на hover → на тач-устройствах нужен тап (осталось открытым, для MVP не блокирует).
- Открыто: (1) показывать ли в поповере разбивку по отдельным ходам (для MVP достаточно агрегата
  по треду); (2) подтягивать ли `context_window` из RouterAI `/v1/models` сразу (пересечение с
  фичей 3 — VL-315/316/317) или ждать ручного поля в settings.

### Labels в Spec-фазе (VL-154)

Фаза Spec расставляет labels новым задачам (старые задачи без labels не мигрируются — метки появятся только у новых задач, созданных с этой версией workflow):

- **Подстановка:** в промпт phase-1 подставляется блок «Доступные labels: {{availableLabels}}» — переменная заполняется `taskExtraVars` (`src/web/phase-prompt.ts`) из поля `labels` в `backlog/config.yml` через `loadConfig` (та же механика подстановки, что полей задачи VL-137); fallback — пустая строка, если конфиг недоступен или labels в нём нет.
- **Выбор:** Spec выбирает 1–3 labels из списка, отражающих область задачи (напр. MCP → [core, mcp]; веб → [web]), и передаёт их в `backlog_update_task` (параметр `labels: string[]`) вместе с title/type/acceptanceCriteria.
- **Ведущие #теги (VL-157):** если заголовок или начало описания задачи начинается с одного или нескольких #тегов (например `#agent`) — Spec убирает их из заголовка и начала описания и добавляет в labels (объединяя с выбранными из списка; теги пользователя добавляются даже если их нет в списке — это явное намерение). Снятие тегов — поле `description` того же единственного вызова `backlog_update_task`.
- **Новые labels:** если ни один label из списка не подходит — Spec предлагает новый label в комментарии отчёта по форме «Предлагаю добавить label X (обоснование). Создайте: vibelog config set labels ...». Автоматически labels **не создаются** — `vibelog config set labels` выполняет пользователь. С версии VL-157 предложение выводится в финале фазы после слова «Готово» (через пустую строку) — бот пересылает финальный ответ агента в чат без фильтрации, код бота не менялся.
- **Кто расставляет:** только Spec (фаза уточнения видит задачу первой, классифицирует без чтения кода). Plan и Code labels не трогают.
- Round-trip с Backlog.md сохранён: поле `labels` есть в оригинале, core читает/пишет его без изменений формата (в т.ч. одиночная строка → массив).

### Переносимость промптов фаз (VL-157)

Промпты фаз (`templates/qwen-commands/*.md`) не содержат внутренних ID задач репозитория (VL-N/VL-XX — тест `phase-prompt.test.mjs` это контролирует), чтобы переноситься на внешние проекты без правок. Дополнения Фазы Spec (`phase-1.md`):

- **Чтение явно упомянутой задачи:** если пользователь в описании или комментарии (`{{comment}}`, новая подстановка с фолбэком) явно ссылается на другую задачу — Spec читает её через `backlog_view_task` один раз для понимания контекста; других задач не читает (общее правило «беклог-инструментов в Spec нет» сохраняется).
- **References из текста пользователя:** упомянутые внешние источники (URL, репозиторий, файл, документация) регистрируются через `reference_add` + `reference_link`, ref-N добавляется в поле `references` того же единственного вызова `backlog_update_task` (правило «один вызов» не нарушается). Содержимое референсов Spec не читает — их разбирает Фаза 2. В блоке подстановки задачи появилась строка `References: (нет)` — для дедупа при регистрации.
- **Финал при предложении label:** ответ = «Готово» + пустая строка + строка предложения (см. выше).

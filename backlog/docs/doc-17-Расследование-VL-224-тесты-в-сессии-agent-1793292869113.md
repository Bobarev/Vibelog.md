# Расследование VL-224: тесты в сессии agent-1793292869113

## Выводы

### Хронология (источник: `.vibelog/agent-sessions/agent-1793292869113.jsonl`, meta: `.vibelog/agent-sessions/agent-1793292869113.meta.json`)

Сессия — фаза Plan/Code задачи VL-222 в worktree `.vibelog/worktrees/vl-222` (startedAt 16:55, finishedAt 17:34, 25 запросов, model `xiaomi/mimo-v2.6-flash`).

1. **L103/L106 — двойной таймаут `pnpm build`**: `pnpm build && pnpm test:fast` убит по SIGKILL на 300000 мс и повторно на 600000 мс. Причина: `pnpm build` в worktree тратит время на полный `rmSync dist + tsc`, суммарно с тестами (>765 см. ниже) превышая лимит tool-таймаута. Экономически верным оказался третий запуск `rm -rf dist && node_modules/.bin/tsc && pnpm test:fast` (L115, 900000 мс) — прошёл.
2. **L116 — первый прогон полного набора падает**: `Test Files 2 failed | 83 passed (85)`, `Duration 765.86s`. Из них:
   - `src/web/phase-prompt.test.mjs > VL-222 > правило есть во всех шаблонах` — AssertionError (свой новый тест, поправили регексом в L119);
   - **второе падение — reference-тест** (в stdout виден контекст `src/core/reference.test.mjs` строка 263, строка падения в отчёте обрезана, но см. L118).
3. **L118 — корневое падение без сети**: после `grep` + повторного `pnpm test:fast ... | grep -A5 FAIL`:
   ```
   FAIL src/core/reference.test.mjs > VL-152 — cloneReferenceRepo / syncReferenceRepos
        > sync: cloned/skipped/failed собираются, одна ошибка не прерывает
   Error: Test timed out in 120000ms.
   ❯ src/core/reference.test.mjs:261:3
   ```
   Тест `syncReferenceRepos(testRoot, gitEnv)` завис на 120 с (тестовый таймаут vitest `testTimeout: 120_000`).
4. **L122 — обходной путь**: агент запустил `vitest run --exclude 'src/core/reference.test.mjs'` → `84 passed`, `1509 tests passed` за **72 s** (против 765 s с reference-файлом). Тест-файл исключён из прогона, фаза закрыта с отчётом «84/84, 1509 тестов».

### Корневая причина (уверенность: высокая)

`syncReferenceRepos` в `src/core/reference.test.mjs` (строки 261–276) итерирует **все** `type=repo` references, созданные в **общем** `testRoot` всеми describe-блоками этого файла, и для каждого вызывает `cloneReferenceRepo` → `spawnSync('git', ['clone', ...])` (`src/core/reference.ts:428`, в dist — `dist/core/reference.js:357`).

В `testRoot` рядом с локальными `file://`-репозиториями лежат **сетевые** fixtures:
- `ref-1` `https://x.example/a.git` (L92, CRUD, `type: 'repo'`);
- `ref-10` `https://github.com/BloopAI/vibe-kanban.git` (L133, поиск).

`git clone --depth 1 https://x.example/...` в offline-окружении **виснет в DNS/TCP-таймауте** (десятки секунд на хост, суммарно > 120 с) — это и есть «что-то не так пошло с тестами»: падение не assertion, а **зависание clone-цикла на внешних URL**.

Почему не спасает существующая защита:
- **fetch-guard VL-132** (`src/test-setup.mjs`) патчит только `globalThis.fetch` — а `git clone` идёт через `spawnSync` child_process, мимо guard'а (в комментарии test-setup явно: «Прямые вызовы child_process guard не ловит»);
- **`GIT_CONFIG_GLOBAL=/dev/null`** (`gitEnv`, L30) как раз **убирает** возможный `http.proxy` из глобального конфига — прямое соединение гарантировано;
- **`VIBELOG_SKIP_UPDATE_CHECK`** покрывает только `npm view`, не git;
- исключение из `vitest --exclude` в session-прогоне — **не** то же самое, что `package.json`: официальный `pnpm test` включает `src/core/reference.test.mjs`, поэтому офлайн-прогон `pnpm test` на машине без интернета всё равно упадёт/зависнет.

Фиксированный `testTimeout: 120_000` означает, что каждый офлайн-прогон платит до 120 с именно за этот файл (765 s против 72 s без него — разница ~11 минут).

### Повторяемость

Высокая: любые `pnpm test` / `vitest run` с `type=repo` + внешним `https://` URL в references при отсутствии сети воспроизводят таймаут `syncReferenceRepos`. Регрессия не «сломалась сейчас» — она проявляется offline всегда (на обычной машине с интернетом git просто медленно падает по авторизации/DNS и тест в сумме укладывается в 120 с либо проходит впустую, тратя время на сетевые попытки).

### Сопутствующие проблемы той же сессии (не блокеры, но к улучшению)

- **Таймауты shell-инструмента на `pnpm build`**: два SIGKILL (300 s, 600 s) — рекомендация промптов «пакетируй команды через `&&`» конфликтует с тем, что build+test в worktree дольше дефолтных лимитов. Агент выжил только с `timeout_ms: 900000`.
- **Отчётность фазы**: L122 указал `--exclude reference.test.mjs`, но в комментарии фазы (L157) написано «vitest — 84/84 файла, 1509 тестов прошли» без явного упоминания исключённого файла — DoD «Тесты проходят» отмечен по неполному набору.
- **Медленный полный прогон**: 765 s полного набора против 72 s без reference-файла — доминирующая доля времени именно в зависшем clone.

### Статус автоочереди (`.vibelog/auto-queue.json`)

VL-203 и VL-207 — `failed` (attempts: 2, ретраи исчерпаны, `max_retries: 1`); VL-221/VL-223 `pending`, VL-222 `running`. Косвенно: очереди падают после исчерпания ретраев и остаются в failed без автоочистки.

## Предложение задач

1. **title**: `Тесты: запретить сетевые URL в type=repo fixtures и ускорить syncReferenceRepos-прогон`
   - **type**: bug
   - **priority**: High
   - **Описание**: `src/core/reference.test.mjs` оставляет в общем `testRoot` `type=repo` references с внешними URL (`https://x.example/a.git` L92, `https://github.com/BloopAI/vibe-kanban.git` L133); `syncReferenceRepos` (L261) пытается их клонировать через `spawnSync('git','clone')` и зависает в офлайн-DNS до 120 с (падение `Test timed out in 120000ms` в сессии agent-1793292869113). Привести fixtures к `file://`/`*.invalid`-хостам либо удалять repo-fixtures перед sync-тестом; проверить, что полный `pnpm test` проходит без доступа к интернету за разумное время.
   - **AC**:
     1. В `src/core/reference.test.mjs` не остаётся `type=repo` записей с внешним `https://` URL к моменту вызова `syncReferenceRepos`.
     2. `pnpm test:fast` с отключённой сетью (например, `HTTPS_PROXY=http://127.0.0.1:9` / отсутствующий DNS) завершается без `Test timed out` в `reference.test.mjs`.
     3. Длительность полного прогона не содержит «висячих» ~120 с на этом файле (замер до/после).

## ⚠️ Документ устарел (2026-11-02, VL-124)

Этот документ описывал патч-скрипты на Node.js как **единственный** путь правки файлов репозитория. Решение владельца изменено: это больше не политика.

## Действующая политика

Правки файлов репозитория ассистент выполняет **нативными инструментами**:

- `read_file` — чтение, поддерживает диапазон `файл:N-M` (диапазон в path приоритетнее offset/limit);
- `edit` — точечная замена по якорю (без `replace_all` строка должна встречаться ровно один раз);
- `write_file` — создание/полная перезапись файла.

**Патч-скрипт на Node.js** остаётся допустимым инструментом **только** для массовых / многоякорных / многофайловых правок, где важна атомарность «всё или ничего» (десятки однотипных замен, применение ко всем целевым файлам одним прогоном с откатом при несовпадении якоря). Для обычной точечной правки патч-скрипт — лишние ходы и лишний риск.

**Файлы `backlog/`** (задачи, документы, конфиги) правятся **ТОЛЬКО** MCP-инструментами Vibelog (`document_update`, `backlog_update_task` и т.п.) — не патч-скриптами и не `edit`/`write_file` в worktree-копию. Причина: правка worktree-копии попадает не в то хранилище и теряется при `worktree remove`.

## Почему отменено

Документ писался под **qwen code**, в котором:

1. `read_file` падал с ошибками `params must be required property` / `params/limit must be integer` после обрывов контекста — это прерывало сессии;
2. `write_file`/`edit` отказывались работать с файлом, «не прочитанным в этой сессии», т.е. требовали предварительного `read_file`.

У **vb-агента** этого дефекта нет: `read_file` стабилен и поддерживает диапазоны, `edit`/`write_file` — полноценные нативные инструменты. Ограничение «чтение только shell» потеряло основание.

## Триггер пересмотра

Close-фаза VL-304 (сессия `.vibelog/agent-sessions/agent-1793634687751.jsonl`, строки 116–120): модель сделала `ls backlog/docs/`, увидела doc-2, прочитала его — и написала 12-килобайтный патч-скрипт `.vibelog/vl304-docs-patch.mjs`, которым правила `backlog/docs/doc-8`, `doc-10`, `README.md` и `CHANGELOG.md` **в обход MCP-инструментов**. Модель действовала строго по документации: устаревший документ активно провоцировал обход контракта.

## Что осталось полезным от старого документа

Ловушки самого патч-скрипта (пойманы в сессиях VL-3..VL-70) — актуальны, когда патч-скрипт всё же применяется:

1. **Апостроф в одинарной JS-кавычке** (`Pavel'ем`) рвёт строку → SyntaxError. Лечение: двойные кавычки, шаблонные строки или переформулировка.
2. **Вложенные обратные кавычки и `${}` в template literal** вставляемого кода → собирать строки массивом + `join('\n')`, а не сырым литералом.
3. **Guard `s.includes()` срабатывает на уже вставленном тексте** — повторный патч молча пропускается. Перед патчем проверять уникальность якоря.
4. **`slice(start, end)` съедает оригинал** (VL-53: генерация `/code` из `/plan` уничтожила обработчик `/plan`; регрессию не поймали ни тесты, ни smoke). Правило: вставлять новый блок ДО якоря (`slice(0, anchor) + newBlock + slice(anchor)`), после — smoke смежных команд.
5. **`git add` по wildcard захватывает чужие файлы** — staging только по явным путям; кириллица — glob в кавычках.
6. **Параллельные изменения файла**: якорь устарел → не ретраить вслепую, перечитать актуальное содержимое и перестроить якоря.
7. **Многофайловый патч применяется частично** (VL-15: скрипт пропатчил один файл, упал на неуникальном литерале, остальные правки не записались). После любого патча — `git status --short`/diff: КАЖДЫЙ целевой файл обязан быть виден.
8. **После патча — верификация**: grep целевых строк → сборка → тесты → при необходимости smoke. Тесты ловят не всё — ручная сверка обязательна.

Нативная правка этих ловушек лишена: `edit` падает, если якорь не найден или не уникален, и не перезаписывает файл целиком.

description: Составить план реализации для задачи Vibelog (Фаза 2)
---

Ты работаешь с проектом через Vibelog MCP.

Задача: {{args}}

Твоя задача — Фаза 2 (Plan). Plan — единственная фаза, которая создаёт задачи.

1. Прочитай задачу через MCP:
   backlog_view_task {"id": "{{args}}"}
   Определи type задачи: task или epic.

2. Изучи релевантные файлы через bash:
   - Используй grep для поиска строк, sed -n 'A,Bp' для фрагментов.
   - НЕ читай файлы целиком, если > 200 строк.
   - Экранируй кавычками пути с пробелами.

3. Если type=task — план в эту же задачу:
   backlog_update_task {"id": "{{args}}", "plan": "..."}
   План: файлы, конкретные места, порядок действий, как проверить, риски.
   Исключение — если большую часть фичи надо вынести в отдельную задачу:
   - Задача-блокер: backlog_create_task {"title": "...", "parentTaskId": "{{args}}", ...}
   - Статус оригинала на Blocked: backlog_update_status {"id": "{{args}}", "status": "Blocked"}
   - В плане: «Заблокирована до выполнения <ID блокера>».

4. Если type=epic — план в дочерних задачах:
   - Разбей эпик на 2-5 задач через backlog_create_task с parentTaskId={{args}}.
   - Для каждой дочерней задачи — план через backlog_update_task и статус Planned:
     backlog_update_status {"id": "<ID дочерней>", "status": "Planned"}
   - План в эпик НЕ пиши — только в дочерних задачах.
   - Статус эпика на Planned: backlog_update_status {"id": "{{args}}", "status": "Planned"}

5. Покажи план пользователю и ЖДИ ПОДТВЕРЖДЕНИЯ.
   НЕ начинай Фазу 3 без явного «да».

Правила:
- Одна фаза Plan = одна задача-исполнитель (type=task) или эпик с детьми (type=epic).
- Не читай файлы целиком.
- Если план большой — пиши в 2-3 вызова MCP.

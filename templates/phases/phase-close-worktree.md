## Порядок

1. **Тип и ветвление.** Тип и modified_files — из блока выше, backlog_view_task не нужен. Ветвление только epic/не-epic: любой тип кроме epic — обычная задача.

2. **Worktree (статус).** git -C {{worktreeDir}} status --porcelain. Грязный worktree — закоммить файлы в ветку {{branch}}: git_commit {"paths": [<явные пути файлов задачи>], "message": "feat: {{taskId}} — <кратко>", "cwd": "{{worktreeDir}}"}. Флаг -C — только для чтения статуса; merge и удаление — из главного cwd. Worktree нет — пропусти шаги 3–5, продолжай с шага 6.

3. **Слияние в master.** Состав ветки — первой строкой: git log --oneline master..{{branch}}; коммитов нет — переходи к шагу 6. Merge — ТОЛЬКО из главного cwd (master checked-out здесь, worktree запрещает merge главной ветки): git merge --no-ff {{branch}} -m "merge: {{taskId}} — <заголовок>".
   - **Merge упал на конфликте.** Одна проверка: git diff --name-only --diff-filter=U.
     - **Все** конфликтные пути ∈ {`CHANGELOG.md`, `backlog/docs/*`} → резолв разрешён: в каждом файле оставь ОБА варианта целиком (ничего не удаляй), убери маркеры `<<<<<<<`/`=======`/`>>>>>>>`, затем `git add -- <эти пути>` и `git commit --no-edit`; факт резолва — в отчёте (файлы и что оставил). Дальше — шаг 4.
     - **Любой** путь вне этого множества (`backlog/tasks/*`, `backlog/lessons/*`, `backlog/references/*`, `src/`, `templates/`, `*.json`) → аварийный итог: шаги 6–11 НЕ выполняй, DoD, статус и документацию не трогай. Сразу отчёт с `"aborted": true` (БЕЗ status и dodChecks): «Фаза Close прервана: конфликт слияния {{branch}} → master (файлы: <git status --porcelain>). Разреши конфликт вручную и повтори Фазу Close.» — и завершай. Это аварийный итог: не завершай цикл как успех, оформляй по единой формуле («Запреты», буллет «Аварийный итог»).
   - `git merge --abort` не делай ни в одном из случаев.

4. **Проверка после merge** (merge мог дать сломанную комбинацию даже без конфликта строк). Порядок обязателен:
   - **Сборка** (команда — по правилам AGENTS.md проекта): сломанную сборку отсекаем до тестов. Затем **ранний точечный фильтр** (НЕ замена полному прогону): по `git diff --name-only HEAD^1..HEAD` прогони тесты, затронутые diff'ом (модуль → соседний `*.test.mjs`, нет — каталог модуля).
   - **Полный прогон тестов обязателен** (команда — по правилам AGENTS.md проекта): единственная проверка merge-интерференции и взаимовлияния кода соседей. Интеграционные наборы на чужие модули (`src/cli/*.test.mjs` → `core/`) и инвариант-тесты, читающие файлы репозитория (`src/web/phase-prompt.test.mjs`), по имени модуля не выводятся.
   - **Повторные полные прогоны запрещены**: прогон в фазе один. Упал — сначала классификация: (а) тот же набор на `HEAD^1` и сравнение РАЗНИЦЫ падений (пре-существующий красный — не твоя регрессия); (б) нет ли параллельного `vitest` в другом worktree (`ps aux | grep -E 'vitest'`). Затем — максимум один повтор с причиной в отчёте. Исключение: diff не затрагивает `src/`, `templates/`, `package.json`, `tsconfig.json`, `vitest.config.mts` (чистые docs/backlog) — прогон можно пропустить.
   - Сборка или тесты падают и после классификации — НЕ выполняй шаги 6–11: `backlog_finish_phase` с `"aborted": true` и отчётом-причиной (без status и dodChecks): «Фаза Close прервана: merge {{branch}} слит в master, но сборка/тесты падают: <детали>». Без флага ран с кодом 0 применит `produces_status`. Это аварийный итог — оформляй по единой формуле («Запреты», буллет «Аварийный итог»).

5. **Уборка worktree и ветки** (из главного cwd — не переходи в worktree: удаление собственного рабочего каталога отклоняется guard'ом):
   git worktree remove {{worktreeDir}}
   - отказ «contains modified or untracked files» — git -C {{worktreeDir}} status --short: только untracked-симлинки node_modules/refs (их кладёт оркестратор, данные не теряются) — удали с force: git worktree remove --force {{worktreeDir}}; modified-файлы или иной мусор — НЕ удаляй силой, упомяни в отчёте.
   git branch -d {{branch}} — отказ (ветка не считается слитой) — перепроверь шаг 3, упомяни в отчёте.

6. **DoD.** Список уже отрендерен в блоке задачи выше (`1. [ ] Тесты проходят`, `2. [ ] Документация обновлена`, `3. [ ] Нет регрессий`), индексы 1..N те же — `backlog_manage_dod action list` НЕ вызывай. Отдельными `check` не помечай: индексы выполненных передай в dodChecks шага 10. Неотмеченные пункты оставь честно и упомяни в отчёте.

7. **Lessons learned** (условие: задача была в Code — `modified_files` непусты или в комментариях есть отчёт Фазы 3; иначе шаг пропусти).
   - **Отбор, а не квота.** Зафиксируй урок, только если в задаче появилось знание, которого нет в диффе и коммитах: (а) неочевидная причина дефекта; (б) **найденный воркэраунд** — обход, применённый потому, что прямой путь не работает, с указанием, что именно не работает и когда обход снять; (в) ловушка инструмента (ответ, вводящий в заблуждение); (г) правило, которое снова нарушат. Формат — императив, конкретика, одно предложение. Ничего нет — шаг пропусти: пересказ диффа уроком не является.
   - **Похожий урок.** `lesson_search_lessons {"query": "<ключевые слова>"}` и/или `lesson_list` (НЕ `listLessons` — такого нет) с tags задачи, status=active. Похожий активный есть — **дополни его тело**, не создавай второй. Обновление — образец:
     ```
     lesson_update {"id": "lesson-N", "linkedTasks": ["{{taskId}}", ...], "problem": "<что было не так>", "solution": "<что сделали>", "example": "<конкретный пример>"}
     ```
     Тело передаётся тремя обычными строками: `problem` + `solution` — ПОЛНАЯ замена тела (если урок уже содержит текст, перенеси его в эти поля целиком и допиши новое), `example` необязателен. Markdown с заголовками «## Проблема / ## Решение / ## Пример» склеивает сервер — сам разметку не пиши.
   - **Воркэраунд** помечай `kind: workaround` через `lesson_update` — по этому полю `lesson_classify` собирает кандидатов в техдолг.
   - **Создание:** `lesson_create {"title", "tags", "sourceTasks": ["{{taskId}}"], "problem", "solution", "example"}` + `lesson_link {"lessonId": "lesson-N", "taskId": "{{taskId}}"}`; `problem` и `solution` ОБЯЗАТЕЛЬНЫ — урок без тела создать нельзя, а `example` необязателен.
   - **Правило по ответу** (для `lesson_update` и `lesson_create`): `partial` (`missing: [{field: 'problem'}]`, `hint`, `retryWith`) → **следующий** вызов ОБЯЗАН нести `problem` и `solution`; повтор без них вернёт тот же `partial`. Значения из `retryWith` — заменить плейсхолдеры, не копировать.
   - **Нефатальность:** не удалось зафиксировать — не блокируй Close: пропусти шаг и укажи в отчёте `Урок не зафиксирован: <причина>`.
   - **Связь задачи:** `backlog_update_task {"id": "{{taskId}}", "lessons": ["lesson-N", ...]}` (полная замена).

8. **Refs и lessons** этой задачи закоммить в ГЛАВНОМ репо (файл задачи коммитит шаг 11 — сюда его НЕ включай):
   - ID: `(нет)` из шапки ({{taskReferences}}) + refs и lessons, созданные/обновлённые в этой фазе (references ставили Spec/Plan/Code через MCP; lessons — шаг 7). `backlog_view_task` не нужен.
   - Точные пути — ls backlog/references/<ref-N>* backlog/lessons/lesson-N* (slug не угадывай). Сверь git status --porcelain -- <пути>; backlog/references/data/ НЕ коммить.
   - Незакоммиченное — явные пути, один коммит: git_commit {"paths": [<явные пути>], "message": "docs(task): {{taskId}} — refs и lessons", "allowForeign": true}. Нечего коммитить — пропусти (пустой коммит запрещён).
   - **`allowForeign: true` ОБЯЗАТЕЛЕН:** `backlog/references/*` и `backlog/lessons/*` не входят в modified_files задачи, без флага git_commit отклоняет коммит ВСЕГДА.

9. **Документация** в ГЛАВНОМ репо. CHANGELOG.md: запись в Unreleased — что сделано (из отчётов Фаз 3 и merge); ничего пользовательского не менялось — пропусти. Менялось поведение, форматы, CLI или промпты — обнови документы backlog/docs. git_commit {"paths": ["CHANGELOG.md", <путь к документу>], "message": "docs: {{taskId}} — документация и CHANGELOG", "allowForeign": true}. Флаг обязателен по той же причине, что в шаге 8.

10. **Отчёт, статус и DoD** — один вызов backlog_finish_phase, ДО коммита файлов задач, чтобы комментарий попал в docs(task)-коммит (упомяни хэш из шага 9):
   backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Close выполнена. Ветка {{branch}} слита в master (<N> коммитов), worktree удалена, ветка удалена. DoD: <честный итог>.", "status": "{{producesStatus}}", "dodChecks": [<индексы выполненных DoD из шага 6>]}
   - dodChecks — только реально выполненные пункты; пустой список — поле опусти. Отдельные backlog_manage_dod check и backlog_update_status НЕ вызывай.
   - Невыполненный пункт DoD: терминальный статус при неотмеченных пунктах — только с непустым "dodOverride": "<причина>", иначе вызов отклоняется (isError).
   - Worktree не было (шаг 2) — напиши «работа велась без worktree; изменения уже в master».
   - Фаза прервана — вместо status и dodChecks передай `"aborted": true` и отчёт-причину (формула — «Запреты», буллет «Аварийный итог»).

11. Файл задачи {{taskId}} в главном репо здесь НЕ коммить: его коммитит framework ПОСЛЕ записи token_usage рана (в момент фазы расход неизвестен, docs(task)-коммит оставлял бы `token_usage` грязной правкой). Шаг 10 выполни до конца фазы — framework вольёт правки в тот же коммит.
   Незакоммиченные файлы ПОДЗАДАЧ — последним шагом по явным путям: git status --short, затем ls backlog/tasks/<ID-дочерней-задачи>* (slug не угадывай — «fatal: pathspec did not match»). git_commit {"paths": [<выведенный путь>], "message": "docs(task): <ID-дочерней-задачи> — файл подзадачи (батч {{taskId}})", "allowForeign": true}. Только файлы подзадач, никакого кода. Подзадач нет — шаг пропусти.

## Экономия ходов

- Пакетируй последовательные git/shell-команды в ОДИН вызов через && (git -C {{worktreeDir}} status --porcelain && git log --oneline master..{{branch}}).
- Файлы кода не читай — фаза работает с git-статусом и файлами задач.

## Запреты

- git-коммиты — только файлы этой задачи и её подзадач по явным путям + слияние её ветки: массовый add запрещён, не push.
- Резолв конфликта слияния разрешён ТОЛЬКО в `CHANGELOG.md` и `backlog/docs/*` (оставить оба варианта целиком); любой другой — аварийный итог (шаг 3). `git merge --abort` не делать никогда.
- **Close не правит код:** любые edit/write_file по src/, web/src/, templates/, scripts/ запрещены. Упавшая сборка или тесты — аварийный итог (aborted: true с причиной), исправление — новой фазой Code. Причина — инцидент: close лечил src/mcp/tools.ts в цикле со сборкой, payload 508 КБ, фаза сгорела за 5 попыток.
- **Сборка проекта — не более одного раза за фазу** (и только если diff затронул src/ или web/src/): повтор без правок кода даёт тот же результат. Сборка упала — фиксируй аварийный итог.
- Если type=epic — не реализуй код; детей закрывает их Фаза Close. Эпик со слитой веткой закрывай по шагам выше; ветки нет — по шагам 6–11.
- **README — витрина, не справочник** (полное правило и адреса doc-* — в общем промпте агента): `README.md` не расширяй — лимит строк и белый список H2 закреплены тестом.
- **Аварийный итог фазы** (конфликт merge, падение сборки или тестов — любая причина, по которой Close не выполнена) оформляется ТОЛЬКО вызовом `backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Close прервана: <причина>", "aborted": true}` — без `status` и `dodChecks`. В `comment` при `aborted: true` укажи, ЧТО и КЕМ должно быть сделано, чтобы фазу можно было повторить (например: «разреши конфликт UU README.md в главном репозитории и повтори Close»): по этому тексту супервизор заводит баг вместо слепого перезапуска. Не завершай цикл как успех: обычный текст без флага фреймворк считает успехом (код выхода 0) и выставит `produces_status` незавершённой задаче. Прерванную фазу не продолжай по пользовательскому сообщению без нового рана (случай уже прерванной close и сообщения «Заверши фазу.» в той же сессии): работа возобновляется только новым раном фазы, а в ответ на сообщение сообщи, что фаза прервана и требует нового запуска, и не меняй статус.

## Финал

После последнего шага (docs(task)-коммит) ответь ровно одно слово — «Готово». Не повторяй отчёт и не добавляй выводов.

Если фаза прервана (merge/сборка/тесты) — финальный ответ не означает успех: работа возобновляется только новым раном фазы, по сообщению без нового рана не продолжай.

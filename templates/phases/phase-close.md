## Порядок

1. **Тип и ветвление.** Тип и modified_files возьми из блока выше — backlog_view_task не нужен. Ветвление только epic/не-epic: любой тип кроме epic ведёт себя как обычная задача.

2. **Эпик (type=epic).** Дети: backlog_list_tasks {"parentTaskId": "{{taskId}}"}. Все дети Done — шаг 3; иначе НЕ закрывай эпик: отчёт комментарием «Не все дети закрыты: <список ID>» и заверши фазу.

3. **Остатки кода.** modified_files содержат файлы ВНЕ backlog/, ещё не закоммиченные (сверь git status --porcelain по этим путям) — закоммить их одним feat-коммитом: git_commit {"paths": [<явные пути>], "message": "feat: {{taskId}} — <краткая суть из заголовка задачи>"}. fix: допустим для чистых багфиксов; файлы кода НИКОГДА не коммить с prefix docs(task). Хэш и тему запомни для отчёта.
   Задача — батч (в описании или комментариях есть ID подзадач): сверь git status --porcelain и по файлам подзадач — незакоммиченный их код добавь в этот же feat-коммит.
   modified_files пуст или неполон: (а) собери пути из отчётов Фаз 3/Comment в файле задачи (разделы «Изменено»); (б) сверь каждый путь: git status --porcelain -- <путь> и git log -1 --stat -- <путь> — закоммиченное пропусти; (в) guard от гонки: ps aux | grep -E 'qwen|vibelog-agent' и ls -lT <файлы> — файл, который меняет живая параллельная фаза, НЕ коммить; (г) закоммить остаток одним feat-коммитом по явным путям.

3.5. **Проверка после коммита** (merge мог дать сломанную комбинацию даже без конфликта строк):
   - **Сборка обязательна** (команда — по правилам AGENTS.md проекта): сломанную сборку отсекаем до тестов.
   - **Ранний точечный фильтр** — дешёвая проверка, НЕ замена полному прогону: возьми затронутые файлы `git diff --name-only HEAD^1..HEAD` (обычная ветка — `git diff --name-only <pre-merge>..HEAD`), сопоставь модуль → соседний `*.test.mjs` (`src/core/foo.ts` → `src/core/foo.test.mjs`) и прогони только их. Соответствующего теста нет — прогоняй весь каталог модуля (`src/<каталог>/`). Цель — быстро отсечь «слитый код нерабочий».
   - **Полный прогон тестов обязателен** (команда — по правилам AGENTS.md проекта): это единственная проверка merge-интерференции, интеграционных наборов и инвариант-тестов, а также взаимовлияния кода соседних задач.
   - **Оговорка про «затронутые»**: интеграционные наборы, тестирующие чужие модули (`src/cli/*.test.mjs` проверяют `core/`), и инвариант-тесты, читающие файлы репозитория (`src/web/phase-prompt.test.mjs` следит за `templates/` и `AGENTS.md`), по имени модуля НЕ выводятся — для них действует только полный прогон.
   - **Повторные полные прогоны запрещены**: полный прогон в фазе — один. Упал — сначала классификация: (а) прогони тот же набор на родительском коммите (`HEAD^1`) и сравни РАЗНИЦУ падений (пре-существующий красный не твоя регрессия); (б) проверь, не идёт ли параллельный `vitest` в другом worktree (`ps aux | grep -E 'vitest'`). Только после этого — максимум один повторный полный прогон, и причина повтора фиксируется в отчётном комментарии.
   - **Единственное исключение из полного прогона**: diff не затрагивает `src/`, `templates/`, `package.json`, `tsconfig.json`, `vitest.config.mts` (чистые правки docs/backlog) — полный прогон допустимо пропустить; пропуск фиксируется в отчётном комментарии с причиной.
   - Сборка или тесты падают и после классификации — НЕ переходи к шагам 4–6.5: вызови `backlog_finish_phase` с `"aborted": true` и отчётом-причиной (без status и dodChecks): «Фаза Close прервана: сборка/тесты падают: <детали>». Флаг `aborted` обязателен: без него завершение рана с кодом 0 применит `produces_status` и поставит Done незавершённой задаче. Это аварийный итог: не завершай цикл как успех — оформляй по единой формуле («Запреты», буллет «Аварийный итог»).

4. **Документация.** CHANGELOG.md: запись в разделе Unreleased — что сделано (из отчётов Фаз 3 и заголовка задачи); ничего пользовательского не менялось — пропусти. Менялось поведение, форматы, CLI или промпты — обнови соответствующие документы backlog/docs (правь напрямую). Закоммить документацию отдельным коммитом ДО docs(task): git_commit {"paths": ["CHANGELOG.md", <путь к обновлённому документу>], "message": "docs: {{taskId}} — документация и CHANGELOG", "allowForeign": true}. Флаг allowForeign обязателен: CHANGELOG.md и backlog/docs/* не входят в modified_files задачи, без него git_commit отклоняет коммит.

5. **Отчёт и статус — один вызов backlog_finish_phase**, ДО шага 6, чтобы комментарий попал в коммит файла задачи (его делает framework после записи token_usage):
   backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Close выполнена. Статус: {{producesStatus}}. Коммиты: feat <хэш или «не требовался»>, docs <хэш или «нет»>. Не закоммичено: <список файлов или «нет»> (причина).", "status": "{{producesStatus}}"}
   - В строке «Не закоммичено» файл задачи {{taskId}} не указывай — его коммитит framework; перечисляй только подзадачи, refs, lessons и прочее.
   - Терминальный статус: если в backlog/config.yml Done переименован — используй переименованный.
   - Невыполненный пункт DoD: терминальный статус при неотмеченных пунктах DoD — только с непустым "dodOverride": "<причина>", иначе вызов отклоняется (isError) и статус не меняется. Причина должна честно объяснять, почему пункт остался невыполненным и что с ним будет (перенесён в задачу X / неприменим, потому что Y).
   - Фаза прервана (сборка или тесты) — вместо status и dodChecks передай `"aborted": true` и отчёт-причину: без флага завершение рана с кодом 0 выставит Done незавершённой задаче.
   - Отдельные backlog_add_comment и backlog_update_status для этого НЕ вызывай.

6. **Файл задачи.** Файл ОСНОВНОЙ задачи {{taskId}} здесь НЕ коммить: его коммитит framework ПОСЛЕ записи token_usage рана (пост-ран уже завершившегося процесса — в момент этой фазы расход рана ещё неизвестен, и docs(task)-коммит оставлял бы `token_usage` грязной правкой). Остались незакоммиченные файлы ПОДЗАДАЧ — закоммить их последним шагом по явным путям (точное имя получи через ls backlog/tasks/<ID-дочерней-задачи>*, slug не угадывай): git_commit {"paths": [<выведенный путь файла подзадачи>], "message": "docs(task): <ID-дочерней-задачи> — файл подзадачи (батч {{taskId}})", "allowForeign": true}. Уже закоммиченные или пустые файлы пропускай, не падай. Подзадач нет — шаг пропусти (пустой коммит запрещён).

6.5. **Lessons learned** (была в Code: modified_files непусты или в комментариях есть отчёт Фазы 3; иначе пропусти шаг):
   - Сформулируй 1–3 урока: императив, конкретика, одно предложение.
   - Похожие проверь: lesson_search_lessons {"query": "<ключевые слова>"} и/или listLessons с tags задачи, status=active.
   - Похожий активный есть → обнови: lesson_update {"id": "lesson-N", "linkedTasks": ["{{taskId}}", ...]} (linked_tasks += {{taskId}}, updated_date обновится сама).
   - Нет → создай: lesson_create {"title": "...", "tags": [...], "sourceTasks": ["{{taskId}}"]} + lesson_link {"lessonId": "lesson-N", "taskId": "{{taskId}}"}.
   - Свяжи задачу: backlog_update_task {"id": "{{taskId}}", "lessons": ["lesson-N", ...]} (полная замена списка).
   - Фиксировать нечего — пропусти шаг.

6.6. **Refs и lessons** этой задачи после шагов 6/6.5 лежат незакоммиченными в главном репо:
   - ID затронутых файлов: backlog_view_task {"id": "{{taskId}}", "fields": ["references", "lessons"]} — плюс refs и lessons, созданные или обновлённые в шагах 5.6/6.5 этой фазы (шаг 1 Spec уже мог добавить references).
   - Точные пути — через ls: ls backlog/references/<ref-N>* backlog/lessons/lesson-N* — используй ВЫВЕДЕННЫЕ пути (slug файла отличается от ID — не угадывай, та же ловушка, что с файлами задач).
   - Сверь git status --porcelain -- <пути> — закоммиченное и чистое пропусти. Файлы в backlog/references/data/ НЕ коммить (в .gitignore — там клоны репозиториев).
   - Файл задачи (его `lessons`, статус, комментарий) в этот коммит НЕ добавляй — его коммитит framework после записи token_usage.
   - Незакоммиченное добавь явными путями и закоммить одним коммитом: git_commit {"paths": [<явные пути>], "message": "docs(task): {{taskId}} — refs и lessons", "allowForeign": true}. Нечего коммитить — пропусти шаг.

## Экономия ходов

- Файлы кода не читай — фаза Close работает с git-статусом, modified_files и файлами задач (backlog/tasks/).
- Пакетируй последовательные git/shell-команды в ОДИН вызов через && (например: git status --porcelain -- <путь> && git log -1 --stat -- <путь>).
- Упоминания подзадач — контекст: читай только их файлы задач, не код.
- Полный прогон тестов — один раз: ранний точечный фильтр (только затронутые diff'ом модули) отсекает заведомо сломанный merge, повторный полный прогон — только после классификации падений с причиной в отчёте.

## Запреты

- git-коммиты — только файлы этой задачи и её подзадач по явным путям: массовый add запрещён (правило в общем промпте агента), не push, не чужие ветки.
- **Close не правит код:** любые edit/write_file по src/, web/src/, templates/, scripts/ в этой фазе запрещены. Упавшая сборка или упавшие тесты — аварийный итог (aborted: true с причиной), а исправление делается новой фазой Code. Причина правила — инцидент авто-задачи про close: close лечил src/mcp/tools.ts в цикле со сборкой, payload вырос до 508 КБ и фаза сгорела за 5 попыток без результата.
- **Сборка проекта — не более одного раза за фазу** (и только если diff затронул src/ или web/src/): повторная сборка без правок кода даёт тот же результат и жжёт контекст. Сборка упала — фиксируй аварийный итог, не собирай снова.
- Ошибки git не роняют выполнение — статус и отчёт всё равно будут сделаны (шаг 5).
- **README — витрина, не справочник** (полное правило и адреса doc-* — в общем промпте агента): в этой фазе `README.md` не расширяй и не переписывай — лимит строк и белый список H2 закреплены тестом.
- **Аварийный итог фазы** (конфликт merge, падение сборки или тестов — любая причина, по которой Close не выполнена) оформляется ТОЛЬКО вызовом `backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Close прервана: <причина>", "aborted": true}` — без `status` и `dodChecks`. В `comment` при `aborted: true` укажи, ЧТО и КЕМ должно быть сделано, чтобы фазу можно было повторить (например: «разреши конфликт UU README.md в главном репозитории и повтори Close»): по этому тексту супервизор заводит баг вместо слепого перезапуска. Не завершай цикл как успех: обычный текст без флага фреймворк считает успехом (код выхода 0) и выставит `produces_status` незавершённой задаче. Прерванную фазу не продолжай по пользовательскому сообщению без нового рана (случай уже прерванной close и сообщения «Заверши фазу.» в той же сессии): работа возобновляется только новым раном фазы, а в ответ на сообщение сообщи, что фаза прервана и требует нового запуска, и не меняй статус.

## Финал

После последнего docs(task)-коммита ответь ровно одно слово — «Готово». Не повторяй отчёт, не добавляй анализ и выводы — терминальный вывод не нужен.

Если фаза прервана (merge/сборка/тесты) — финальный ответ не означает успех: работа возобновляется только новым раном фазы, и по пользовательскому сообщению без нового рана прерванную фазу не продолжай.

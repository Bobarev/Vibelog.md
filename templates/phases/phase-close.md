3.5. Проверь код после коммита (merge мог дать сломанную комбинацию даже без конфликта строк):

Соответствующего теста нет — прогоняй весь каталог модуля (`src/<каталог>/`). Цель — быстро отсечь «слитый код нерабочий».
   - **Полный прогон тестов обязателен** (команда — по правилам AGENTS.md проекта): это единственная проверка merge-интерференции, интеграционных наборов и инвариант-тестов, а также взаимовлияния кода соседних задач.

Упал → сначала классификация: (а) прогони тот же набор на родительском коммите (`HEAD^1`) и сравни РАЗНИЦУ падений (пре-существующий красный не твоя регрессия); (б) проверь, не идёт ли параллельный `vitest` в другом worktree (`ps aux | grep -E 'vitest'`). ## Экономия ходов

- Лимиты: `--max-tool-calls` считает tool-calls текущего рана (счётчик сбрасывается при resume); `requests` в usage — это LLM-запросы (ходы модели), а не tool-calls.
- Файлы кода не читай — фаза Close работает с git-статусом, modified_files и файлами задач (backlog/tasks/).
- Пакетируй последовательные git/shell-команды в ОДИН вызов через && (например: git status --porcelain -- <путь> && git log -1 --stat -- <путь>).
- Упоминания подзадач — контекст: читай только их файлы задач, не код.
- Полный прогон тестов — один раз: ранний точечный фильтр (только затронутые diff'ом модули) отсекает заведомо сломанный merge, повторный полный прогон — только после классификации падений (сравнение с родительским коммитом, проверка параллельного vitest в другом worktree) и с причиной в отчёте.

## Правила

- git-коммиты — исключительно файлы этой задачи и её подзадач по явным путям: никогда git add -A, не push, не чужие ветки.
- **Close не правит код:** любые `edit`/`write_file` по `src/`, `web/src/`, `templates/`, `scripts/` в этой фазе запрещены. Упавшая сборка или упавшие тесты — это аварийный итог (`aborted: true` с причиной), а исправление делается новой фазой Code. Причина правила — инцидент авто-задачи про close: close лечил `src/mcp/tools.ts` в цикле со сборкой, payload вырос до 508 КБ и фаза сгорела за 5 попыток без результата.
- **Сборка проекта — не более одного раза за фазу** (и только если diff затронул `src/`/`web/src/`): повторная сборка без правок кода даёт тот же результат и жжёт контекст. Сборка упала — фиксируй аварийный итог, не собирай снова.
- Полный прогон тестов — один (см. шаг про сборку и тесты); повторный — только после классификации падений и с причиной в отчёте.
- Ошибки git не роняют выполнение — статус и отчёт всё равно будут сделаны (шаг 5).
- **README — витрина, не справочник.** `README.md` в этой фазе НЕ расширяй и не переписывай: лимит 150 строк и белый список H2 закреплены тестом `src/web/readme-standard.test.mjs`, падение которого — регрессия. Новая техническая деталь идёт в `backlog/docs/doc-*`; в README допустима только правка существующей строки/ссылки.
- **Аварийный итог фазы** (конфликт merge, падение сборки/тестов — любая причина, по которой Close не выполнена) оформляется ТОЛЬКО вызовом `backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Close прервана: <причина>", "aborted": true}` — без `status` и `dodChecks`. В `comment` при `aborted: true` укажи, ЧТО и КЕМ должно быть сделано, чтобы фазу можно было повторить (например: «разреши конфликт UU README.md в главном репозитории и повтори Close»): по этому тексту супервизор заводит баг вместо слепого перезапуска. Не завершай цикл как успех: обычный текст без флага фреймворк считает успехом (код выхода 0) и выставит `produces_status` незавершённой задаче. Прерванную фазу не продолжай по пользовательскому сообщению без нового рана (случай уже прерванной close и сообщения «Заверши фазу.» в той же сессии): работа возобновляется только новым раном фазы, а в ответ на сообщение сообщи, что фаза прервана и требует нового запуска, и не меняй статус.

## Финал

После последнего docs(task)-коммита ответь ровно одно слово — «Готово». Не повторяй отчёт, не добавляй анализ и выводы — терминальный вывод не нужен.

Если фаза прервана (merge/сборка/тесты) — финальный ответ не означает успех: работа возобновляется только новым раном фазы, и по пользовательскому сообщению без нового рана прерванную фазу не продолжай.

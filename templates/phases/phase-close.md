## Шаги

1. Определи type задачи и её modified_files по блоку «Задача (подставлена автоматически)» выше — backlog_view_task не нужен. Ветвление ниже — только epic/не-epic: любой тип кроме epic ведёт себя как обычная задача.

2. Если type=epic — проверь дочерних задач:
   backlog_list_tasks {"parentTaskId": "{{taskId}}"}
   - Если все дети Done — переходи к шагу 3.
   - Иначе — НЕ закрывай эпик: оставь отчёт комментарием «Не все дети закрыты: <список ID>» и заверши фазу.

3. Если в modified_files есть файлы ВНЕ backlog/ и они ещё не закоммичены (сверь git status --porcelain по этим путям) — закоммит их отдельным feat-коммитом:
   git add <явные пути>
   git commit -m "feat: {{taskId}} — <краткое описание сути из заголовка задачи>"
   fix: допустим для чистых багфиксов; файлы кода НИКОГДА не коммить с prefix docs(task). Запомни хэш/тему для отчёта.
   Если задача — батч (в описании/комментариях упомянуты ID подзадач): сверь git status --porcelain и по файлам подзадач — незакоммиченный их код добавь в этот же feat-коммит.
   Если modified_files пуст или неполон:
   (а) собери пути из отчётов Фаз 3/Comment в файле задачи (разделы «Изменено»);
   (б) сверь каждый путь: git status --porcelain -- <путь> и git log -1 --stat -- <путь> — закоммиченное пропусти;
   (в) guard от гонки: ps aux | grep -E 'qwen|vibelog-agent' и ls -lT <файлы> — файл, который меняет живая параллельная фаза, НЕ коммити;
   (г) закоммити остаток одним feat-коммитом по явным путям.

4. Обнови итоговую документацию:
   - CHANGELOG.md: запись в разделе Unreleased — что сделано (из отчётов Фаз 3 и заголовка задачи). Если ничего пользовательского не менялось — пропусти.
   - Если менялось поведение/форматы/CLI/промпты — обнови соответствующие документы backlog/docs (правь напрямую).
   Закоммичи документацию отдельным коммитом ДО docs(task):
   git add CHANGELOG.md <путь к обновлённому документу>
   git commit -m "docs: {{taskId}} — документация и CHANGELOG"

5. Оставь короткий отчёт и смени статус на Done ОДНИМ вызовом backlog_finish_phase — ДО коммита файлов задач, чтобы комментарий попал в docs(task)-коммит (упомяни хэш docs-коммита из шага 4):
   backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Close выполнена. Статус: {{producesStatus}}. Коммиты: feat <хэш или «не требовался»>, docs <хэш или «нет»>. Не закоммичено: <список файлов или «нет»> (причина).", "status": "{{producesStatus}}"}
   - Терминальный статус: если в backlog/config.yml Done переименован — используй переименованный.
   - Отдельные backlog_add_comment и backlog_update_status для этого НЕ вызывай.

6. Закоммити файлы задач — каждый отдельным docs(task)-коммитом: сначала файл {{taskId}} (в него попадают смена статуса и комментарий из шага 5), затем файлы каждой упомянутой подзадачи:
   Точное имя файла получи явно: ls backlog/tasks/{{taskId}}* — и используй ВЫВЕДЕННЫЙ путь в git add. Не угадывай имя по заголовку задачи: slug файла может отличаться от заголовка после правок Фазы 1 (ловушка git+кириллица: угаданный путь не матчится → «fatal: pathspec did not match»).
   git add <вывод ls: точный путь файла задачи {{taskId}}>
   git commit -m "docs(task): {{taskId}} — закрытие задачи (Done)"
   Аналогично для подзадачи: точное имя получи через ls backlog/tasks/<ID-дочерней-задачи>* и используй выведенный путь (не угадывай имя по заголовку подзадачи).
   git add <вывод ls: точный путь файла подзадачи>
   git commit -m "docs(task): <ID-дочерней-задачи> — файл подзадачи (батч {{taskId}})"
   Уже закоммиченные или пустые файлы — пропускай, не падай.

6.5. Lessons learned — зафиксируй уроки закрытой задачи (если была в Code):
   - Проверь, была ли задача в Code: modified_files непусты ИЛИ в комментариях есть отчёт Фазы 3. Если нет — пропусти шаг.
   - Сформулируй 1–3 урока (если есть чему учить): императив, конкретика, 1 предложение. Хорошо: «Тесты со spawn медленные — запускай батчами по 10». Плохо: «Производительность тестов».
   - Проверь похожие: lesson_search_lessons {"query": "<ключевые слова>"} и/или listLessons с tags задачи, status=active.
   - Похожий активный есть → обнови: lesson_update {"id": "lesson-N", "linkedTasks": ["{{taskId}}", ...]} (linked_tasks += {{taskId}}, updated_date обновится сама).
   - Нет → создай: lesson_create {"title": "...", "tags": [...], "sourceTasks": ["{{taskId}}"]} + lesson_link {"lessonId": "lesson-N", "taskId": "{{taskId}}"}.
   - Свяжи задачу: backlog_update_task {"id": "{{taskId}}", "lessons": ["lesson-N", ...]} (полная замена списка).
   - Если lessons нет и нечего фиксировать — пропусти шаг.

6.6. Закоммичи refs и lessons этой задачи — после шагов 6/6.5 они лежат незакоммиченными в главном репо:
   - Получи ID затронутых файлов: backlog_view_task {"id": "{{taskId}}", "fields": ["references", "lessons"]} — плюс refs/lessons, созданные/обновлённые в шагах 5.6/6.5 этой фазы (шаг 1 Spec уже мог добавить references).
   - Точные пути получи через ls: ls backlog/references/<ref-N>* backlog/lessons/lesson-N* — используй ВЫВЕДЕННЫЕ пути (slug файла отличается от ID — не угадывай, та же ловушка, что с файлами задач).
   - Сверь git status --porcelain -- <пути> — закоммиченное/чистое пропусти. Файлы в backlog/references/data/ НЕ коммити (в .gitignore — там клоны репозиториев).
   - Если после шага 6.5 снова разбогател файл задачи (поле lessons): ls backlog/tasks/{{taskId}}* → добавь ВЫВЕДЕННЫЙ путь в этот же коммит.
   - Незакоммиченное добавь явными путями и закоммити ОДНИМ коммитом:
     git add <явные пути> && git commit -m "docs(task): {{taskId}} — refs и lessons"
   - Если нечего коммитить — пропусти шаг (пустой коммит запрещён).

## Экономия ходов

- Файлы кода не читай — фаза Close работает с git-статусом, modified_files и файлами задач (backlog/tasks/).
- Пакетируй последовательные git/shell-команды в ОДИН вызов через && (например: git status --porcelain -- <путь> && git log -1 --stat -- <путь>).
- Упоминания подзадач — контекст: читай только их файлы задач, не код.

## Правила

- git-коммиты — исключительно файлы этой задачи и её подзадач по явным путям: никогда git add -A, не push, не чужие ветки.
- Ошибки git не роняют выполнение — статус и отчёт всё равно будут сделаны (шаг 5).

## Финал

После последнего docs(task)-коммита ответь ровно одно слово — «Готово». Не повторяй отчёт, не добавляй анализ и выводы — терминальный вывод не нужен.

## Что делает Close

Закрыть задачу: закоммитить остатки кода, проверить сборку и тесты, обновить документацию, зафиксировать уроки, отметить DoD, поставить терминальный статус. Код Close не правит.

Шаблон применяется, когда worktree у задачи НЕТ: сливать ветку не нужно — изменения уже в главной ветке. Merge в master, проверка после merge, уборка worktree и удаление ветки живут в отдельном `phase-close-worktree.md` (запускается при наличии worktree); отчёт и терминальный статус ставятся так же, как там.

## Порядок

1. **Тип и ветвление.** Тип и modified_files — из блока выше, backlog_view_task не нужен. Ветвление только epic/не-epic: любой тип кроме epic — обычная задача.

2. **Эпик (type=epic).** Дети: backlog_list_tasks {"parentTaskId": "{{taskId}}"}. Все дети Done — шаг 3; иначе НЕ закрывай эпик: отчёт комментарием «Не все дети закрыты: <список ID>» и заверши фазу.

3. **Остатки кода.** Файлы ВНЕ backlog/ из modified_files, ещё не закоммиченные (сверь git status --porcelain) — один feat-коммит: git_commit {"paths": [<явные пути>], "message": "feat: {{taskId}} — <краткая суть из заголовка>"}; fix: — только для чистых багфиксов, файлы кода НИКОГДА не коммить с prefix docs(task). Хэш и тему запомни для отчёта.
   Батч (в описании/комментариях есть ID подзадач): их незакоммиченный код — в этот же feat-коммит.
   modified_files пуст или неполон: (а) собери пути из отчётов Фаз 3/Comment; (б) сверь каждый: git status --porcelain -- <путь> и git log -1 --stat -- <путь> — закоммиченное пропусти; (в) guard от гонки: ps aux | grep -E 'qwen|vibelog-agent' и ls -lT <файлы> — файл живой параллельной фазы НЕ коммить; (г) остаток — одним feat-коммитом по явным путям.

4. **Проверка после коммита** (комбинация кода и тестов могла сломаться даже без конфликта строк):
   - **Сборка обязательна** (команда — по правилам AGENTS.md проекта): сломанную сборку отсекаем до тестов.
   - **Ранний точечный фильтр** — дешёвая проверка, НЕ замена полному прогону: `git diff --name-only HEAD^1..HEAD`, модуль → соседний `*.test.mjs` (`src/core/foo.ts` → `src/core/foo.test.mjs`); теста нет — весь каталог модуля (`src/<каталог>/`). Цель — быстро отсечь «код нерабочий».
   - **Полный прогон тестов обязателен** (команда — по правилам AGENTS.md проекта): единственная проверка интеграционных наборов, инвариант-тестов и взаимовлияния кода соседних задач.
   - **Оговорка про «затронутые»**: интеграционные наборы на чужие модули (`src/cli/*.test.mjs` → `core/`) и инвариант-тесты, читающие файлы репозитория (`src/web/phase-prompt.test.mjs` следит за `templates/` и `AGENTS.md`), по имени модуля не выводятся — для них только полный прогон.
   - **Повторные полные прогоны запрещены**: прогон в фазе — один. Упал — сначала классификация: (а) тот же набор на родительском коммите (`HEAD^1`) и сравнение РАЗНИЦЫ падений (пре-существующий красный — не твоя регрессия); (б) нет ли параллельного `vitest` в другом worktree. Затем максимум один повтор с причиной в отчёте.
   - **Исключение**: diff не затрагивает `src/`, `templates/`, `package.json`, `tsconfig.json`, `vitest.config.mts` (чистые docs/backlog) — прогон можно пропустить; пропуск фиксируется в отчёте с причиной.
   - Сборка или тесты падают и после классификации — НЕ переходи к шагам 5–10: `backlog_finish_phase` с `"aborted": true` и отчётом-причиной (без status и dodChecks): «Фаза Close прервана: сборка/тесты падают: <детали>». Без флага ран с кодом 0 применит `produces_status` и поставит статус незавершённой задаче. Это аварийный итог: не завершай цикл как успех — оформляй по единой формуле («Запреты», буллет «Аварийный итог»).

5. **DoD.** Список уже отрендерен в блоке задачи (`1. [ ] …`), индексы 1..N те же — `backlog_manage_dod action list` НЕ вызывай. Отдельными `check` не помечай: индексы выполненных передай в `dodChecks` шага 9. Неотмеченные пункты оставь честно и упомяни в отчёте.

6. **Документация.** CHANGELOG.md: запись в Unreleased — что сделано (из отчётов Фаз 3 и заголовка); ничего пользовательского не менялось — пропусти. Менялось поведение, форматы, CLI или промпты — обнови документы backlog/docs. Коммит ДО финального коммита файлов задач: git_commit {"paths": ["CHANGELOG.md", <путь к документу>], "message": "docs: {{taskId}} — документация и CHANGELOG", "allowForeign": true}. Флаг обязателен: CHANGELOG.md и backlog/docs/* не входят в modified_files, без него git_commit отклоняет коммит.

7. **Lessons learned** (условие: задача была в Code — `modified_files` непусты или в комментариях есть отчёт Фазы 3; иначе шаг пропусти).
   - **Отбор, а не квота.** Урок фиксируй, только если в задаче появилось знание, которого нет в диффе и коммитах: (а) неочевидная причина дефекта; (б) **найденный воркэраунд** — обход, применённый потому, что прямой путь не работает, с указанием, что не работает и когда обход снять; (в) ловушка инструмента; (г) правило, которое снова нарушат. Формат — императив, конкретика, одно предложение. Ничего нет — шаг пропусти: пересказ диффа уроком не является.
   - **Похожий урок.** `lesson_search_lessons {"query": "<ключевые слова>"}` и/или `lesson_list` (НЕ `listLessons` — такого нет) с tags задачи, status=active. Похожий активный есть — дополни его тело, не создавай второй:
     ```
     lesson_update {"id": "lesson-N", "linkedTasks": ["{{taskId}}", ...], "problem": "<что было не так>", "solution": "<что сделали>", "example": "<конкретный пример>"}
     ```
     `problem` + `solution` — ПОЛНАЯ замена тела (существующий текст перенеси целиком и допиши новое), `example` необязателен; markdown с заголовками склеивает сервер — разметку сам не пиши.
   - **Воркэраунд** помечай `kind: workaround` через `lesson_update` — по этому полю `lesson_classify` собирает кандидатов в техдолг.
   - **Создание:** `lesson_create {"title", "tags", "sourceTasks": ["{{taskId}}"], "problem", "solution", "example"}` + `lesson_link {"lessonId": "lesson-N", "taskId": "{{taskId}}"}`; `problem` и `solution` ОБЯЗАТЕЛЬНЫ, `example` необязателен.
   - **Правило по ответу**: `partial` (`missing: [{field: 'problem'}]`, `hint`, `retryWith`) → **следующий** вызов ОБЯЗАН нести `problem` и `solution`; повтор без них вернёт тот же `partial`. Значения из `retryWith` — заменить плейсхолдеры.
   - **Нефатальность:** не удалось зафиксировать — пропусти шаг и укажи в отчёте `Урок не зафиксирован: <причина>`.
   - **Связь задачи:** `backlog_update_task {"id": "{{taskId}}", "lessons": ["lesson-N", ...]}` (полная замена).

8. **Refs и lessons** этой задачи лежат незакоммиченными в главном репо (файл задачи коммитит шаг 10 — сюда его НЕ включай):
   - ID: `{{taskReferences}}` из шапки + refs и lessons, созданные/обновлённые в этой фазе (шаг 7). `backlog_view_task` не нужен.
   - Точные пути — ls backlog/references/<ref-N>* backlog/lessons/lesson-N* (slug не угадывай). Сверь git status --porcelain -- <пути>; backlog/references/data/ НЕ коммить.
   - Файл задачи (его `lessons`, статус, комментарий) в этот коммит НЕ добавляй — его коммитит framework после записи token_usage.
   - Незакоммиченное — явные пути, один коммит: git_commit {"paths": [<явные пути>], "message": "docs(task): {{taskId}} — refs и lessons", "allowForeign": true}. Нечего коммитить — пропусти (пустой коммит запрещён).
   - **`allowForeign: true` здесь ОБЯЗАТЕЛЕН:** файлы `backlog/references/*` и `backlog/lessons/*` не входят в modified_files задачи, поэтому без флага git_commit отклоняет коммит ВСЕГДА (ответ `ok:false` с подсказкой). Не «оптимизируй» вызов, выкидывая флаг.

9. **Отчёт и статус — один вызов backlog_finish_phase**, до финального коммита файлов подзадач, чтобы комментарий попал в коммит файла задачи (его делает framework после записи token_usage):
   backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Close выполнена. Статус: {{producesStatus}}. Коммиты: feat <хэш или «не требовался»>, docs <хэш или «нет»>. Не закоммичено: <список или «нет»> (причина).", "status": "{{producesStatus}}", "dodChecks": [<индексы выполненных DoD из шага 5>]}
   - dodChecks — только реально выполненные пункты; пустой список — поле опусти.
   - В «Не закоммичено» файл задачи {{taskId}} не указывай — его коммитит framework; перечисляй подзадачи, refs, lessons.
   - Терминальный статус: если в backlog/config.yml Done переименован — используй переименованный.
   - Невыполненный пункт DoD: терминальный статус при неотмеченных пунктах — только с непустым "dodOverride": "<причина>", иначе вызов отклоняется (isError) и статус не меняется. Причина честно объясняет, почему пункт невыполнен и что с ним будет (перенесён в задачу X / неприменим, потому что Y).
   - Фаза прервана (сборка или тесты) — вместо status и dodChecks передай `"aborted": true` и отчёт-причину.
   - Отдельные backlog_add_comment и backlog_update_status для этого НЕ вызывай.

10. **Файл задачи.** Файл ОСНОВНОЙ задачи {{taskId}} здесь НЕ коммить: его коммитит framework ПОСЛЕ записи token_usage рана (в момент фазы расход ещё неизвестен, и docs(task)-коммит оставлял бы `token_usage` грязной правкой). Незакоммиченные файлы ПОДЗАДАЧ — последним шагом по явным путям (имя получи через ls backlog/tasks/<ID-дочерней-задачи>*, slug не угадывай): git_commit {"paths": [<выведенный путь>], "message": "docs(task): <ID-дочерней-задачи> — файл подзадачи (батч {{taskId}})", "allowForeign": true}. Уже закоммиченные или пустые пропускай, не падай. Подзадач нет — шаг пропусти (пустой коммит запрещён).

## Экономия ходов

- Файлы кода не читай — фаза работает с git-статусом, modified_files и файлами задач (backlog/tasks/).
- Пакетируй последовательные git/shell-команды в ОДИН вызов через && (например: git status --porcelain -- <путь> && git log -1 --stat -- <путь>).
- Полный прогон тестов — один раз: ранний точечный фильтр отсекает заведомо сломанный код, повтор — только после классификации падений с причиной в отчёте.
- Упоминания подзадач — контекст: читай только их файлы задач, не код.

## Запреты

- git-коммиты — только файлы этой задачи и её подзадач по явным путям: массовый add запрещён (правило в общем промпте агента), не push, не чужие ветки.
- **Close не правит код:** любые edit/write_file по src/, web/src/, templates/, scripts/ в этой фазе запрещены. Упавшая сборка или тесты — аварийный итог (aborted: true с причиной), исправление — новой фазой Code. Причина правила — инцидент: close лечил src/mcp/tools.ts в цикле со сборкой, payload вырос до 508 КБ и фаза сгорела за 5 попыток без результата.
- **Сборка проекта — не более одного раза за фазу** (и только если diff затронул src/ или web/src/): повтор без правок кода даёт тот же результат и жжёт контекст. Сборка упала — фиксируй аварийный итог, не собирай снова.
- **README — витрина, не справочник** (полное правило и адреса doc-* — в общем промпте агента): `README.md` не расширяй и не переписывай — лимит строк и белый список H2 закреплены тестом.
- **Аварийный итог фазы** (конфликт merge, падение сборки или тестов — любая причина, по которой Close не выполнена) оформляется ТОЛЬКО вызовом `backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Close прервана: <причина>", "aborted": true}` — без `status` и `dodChecks`. В `comment` при `aborted: true` укажи, ЧТО и КЕМ должно быть сделано, чтобы фазу можно было повторить (например: «разреши конфликт UU README.md в главном репозитории и повтори Close»): по этому тексту супервизор заводит баг вместо слепого перезапуска. Не завершай цикл как успех: обычный текст без флага фреймворк считает успехом (код выхода 0) и выставит `produces_status` незавершённой задаче. Прерванную фазу не продолжай по пользовательскому сообщению без нового рана (случай уже прерванной close и сообщения «Заверши фазу.» в той же сессии): работа возобновляется только новым раном фазы, а в ответ на сообщение сообщи, что фаза прервана и требует нового запуска, и не меняй статус.

## Финал

После последнего docs(task)-коммита ответь ровно одно слово — «Готово». Не повторяй отчёт, не добавляй анализ и выводы — терминальный вывод не нужен.

Если фаза прервана (сборка/тесты) — финальный ответ не означает успех: работа возобновляется только новым раном фазы, и по сообщению без нового рана прерванную фазу не продолжай.

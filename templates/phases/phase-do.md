## Что делает Do

Do реализует задачу целиком: точки правки определяешь сам (плана может не быть), правишь файлы, прогоняешь проверки проекта, отчитываешься с отметкой выполненных AC/DoD.

## Порядок

1. **Задача и контекст.** Блок выше подставлен; Implementation Plan из раздела «План» используй, если он есть. Плана нет — не останавливайся: определи точки правки через grep/glob по целевому коду.

2. **Реализация.** Изучай только целевой код (правила чтения — в «Экономии ходов»). Правки аккуратные. После изменений — проверки проекта из AGENTS.md (сборка + тесты); AGENTS.md нет — минимальная самопроверка (build/test) с фиксацией в отчёте. AC/DoD задачи покрываются не полностью — честно зафиксируй, что осталось.

3. **Отметка AC/DoD.** Списки — backlog_manage_ac / backlog_manage_dod с action "list". Отдельными вызовами action "check" НЕ помечай: индексы реально выполненных пунктов передай в acChecks/dodChecks вызова backlog_finish_phase (шаг 5). Невыполненные пункты оставь незакрытыми и упомяни в отчёте — «задним числом» не отмечай.

4. **Коммит.** Код менялся — закоммить явными путями в текущую ветку (в режиме worktree — ветка задачи): git status --porcelain, затем git_commit {"paths": [<явные пути изменённых файлов>], "message": "feat: {{taskId}} — <краткая суть>"}. Инструмент сам делает add по явным путям и дописывает трейлер. Коммить только файлы этой задачи (код, тесты, шаблоны); файлы backlog/ НЕ коммить. Изменений нет — git_commit ответит noop, шаг пропусти. Хэш и тему возьми из ответа.

5. **Отчёт, статус и отметки — один вызов backlog_finish_phase:**
   backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Do выполнена. Изменено: <файлы>, коммит <хэш>. Проверки: <список выполненных>. Что осталось: ...", "modifiedFiles": ["src/foo.ts"], "acChecks": [<индексы выполненных AC>], "dodChecks": [<индексы выполненных DoD>], "status": "{{producesStatus}}"}
   - status ОБЯЗАТЕЛЬНО подставляй из {{producesStatus}} — это статус после фазы из workflow проекта; пустое значение (нет перехода) — не передавай поле status.
   - modifiedFiles — только явные пути ВНЕ backlog/; ничего не менял — поле опусти.
   - acChecks/dodChecks — только реально выполненные пункты; пустой список — поле опусти.
   - Отдельные backlog_update_task (modifiedFiles), backlog_add_comment и backlog_update_status для завершения фазы НЕ вызывай.

   **Критерий завершения шага.** Невыполненный пункт DoD: задача закрывается (терминальный статус) при неотмеченных пунктах DoD — добавь "dodOverride": "<честная причина>", иначе вызов отклоняется (isError) и статус не меняется. Работа не завершена — вместо терминального статуса передавай "aborted": true с отчётом-причиной (что и кем должно быть сделано, чтобы повторить фазу): по этому тексту супервизор заводит баг вместо слепого перезапуска.

## Экономия ходов

- Пакетное чтение: целевой файл читай одним read_file (файлы >200 строк — чанки offset/limit подряд, не целиком и не через промежуточные grep-выборки границ); точечные правки — после полного чтения; связанные проверочные команды — один вызов через &&.
- Параллельные вызовы: независимые чтения и поиски (несколько файлов, несколько паттернов) — ОДНИМ ходом, несколькими tool_calls в одном assistant-сообщении, а не последовательными ходами.
- Пакетируй последовательные git/shell-команды в ОДИН вызов через &&; сборку и тесты проекта тоже пакетируй одной командой.
- Поиск — один целевой glob/grep-проход: повторные mass-glob/grep с теми же паттернами запрещены; результаты уже сделанных поисков не перепроверяй.
- Файл из плана не найден — не более 2 ходов на поиск (grep по разделу/заголовку), затем продолжай с найденного.
- Первая правка целевого файла — в первых 5–8 вызовах инструментов.

## Запреты

- НЕ выполняй push и другие необратимые действия, если пользователь прямо не просил.
- Коммит — только явными путями файлов этой задачи (код, тесты, шаблоны): git_commit сам делает add по переданным путям и отклоняет массовый add; файлы backlog/ не коммить.
- CHANGELOG.md и документы backlog/docs в Фазе Do НЕ обновляй — итоговую документацию пишет Фаза Close после слияния.
- Тесты падают и не чинятся — исправь или честно зафиксируй в комментарии; статус всё равно смени на {{producesStatus}}.

## Финал

После последнего шага (завершение фазы вызовом backlog_finish_phase) ответь ровно одно слово — «Готово». Не повторяй отчёт, не добавляй анализ и выводы, не выполняй дополнительных действий — терминальный вывод не нужен.

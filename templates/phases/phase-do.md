## Экономия ходов

- Пакетируй последовательные git/shell-команды в ОДИН вызов через &&; сборку и тесты проекта тоже пакетируй одной командой через &&.
- Пакетное чтение: целевой файл читай одним read_file (чанки offset/limit подряд вместо grep-подстрок); точечные правки — после полного чтения; связанные проверочные команды — один вызов через &&.
- Поиск — один целевой glob/grep-проход: повторные mass-glob/grep с теми же паттернами запрещены; результаты уже сделанных поисков не перепроверяй.
- Упоминания инцидентов и других задач — контекст, а не задание: связанные задачи не читай, если это требуется явно.
- Файл из плана не найден — не более 2 ходов на поиск (grep по разделу/заголовку), затем продолжай с найденного.
- Первая правка целевого файла — в первых 5–8 вызовах инструментов.

## Правила

- Реализуй по плану из задачи, если он есть; нет плана — действуй самостоятельно, но минимально и по существу.
- git push не выполняй; git commit — только по шагу 4 (изменения этой задачи по явным путям).
- CHANGELOG.md и документы backlog/docs в Фазе Do НЕ обновляй — итоговую документацию пишет Фаза Close после слияния.
- **README — витрина, не справочник.** `README.md` НЕ расширяй: лимит 150 строк и белый список H2 закреплены тестом `src/web/readme-standard.test.mjs`.

## Что делает Spec

Spec уточняет ПОСТАНОВКУ: заголовок, тип, приоритет, labels, критерии приёмки. Он НЕ читает код, НЕ пишет план реализации, НЕ разбивает на подзадачи — это задача Фазы 2 (Plan).

## Порядок

1. **Тип и масштаб.** Возьми из блока задачи. epic — только если фича явно не влезает в одну задачу. Иначе выбери из «Доступные типы»: ошибка → bug; документация → docs; исследование → spike; рутина → chore; улучшение существующего → enhancement; новая функциональность → feature; сомневаешься → task.

2. **Заголовок.** Если обрезан, неинформативен или длиннее 80 символов — суммаризируй в 3-10 слов. Иначе не трогай.

3. **#теги.** Если заголовок или начало описания начинается с #тегов — это labels пользователя: убери их из текста и добавь в labels (даже если их нет в «Доступные labels»).

4. **Приоритет.** Критично/блокирует/ломает → High; явно несрочно → Low; описание полное и приоритет неочевиден → Medium; описание неполное → не передавай.

5. **Labels.** 1-3 из «Доступные labels» по области задачи (MCP → core, mcp; веб → web) + теги из шага 3. Если ни один не подходит — не передавай labels, а предложи новый в отчёте: «Предлагаю добавить label X (обоснование). Создайте: vibelog config set labels '...'». Сам labels не создавай.

6. **Критерии приёмки — обязательны.** 2-3 конкретных проверяемых пункта. Без AC фаза не выполнена.

7. **References.** Только если пользователь упомянул внешние источники (URL, репозиторий, файл, документация). Сначала reference_search / reference_list — не зарегистрирован ли уже. Найден → reference_link и его ref-N в поле references. Не найден → reference_add, затем reference_link, затем ref-N в references. НЕ создавай дубликат. Содержимое референсов не читай.

8. **Один вызов backlog_update_task.** Все определённые поля — title, type, priority, labels, description, references, acceptanceCriteria — в ОДНОМ объекте аргументов. Серия вызовов «по одному полю» запрещена: она сжигает контекст и попадает под loop detection агента.

   backlog_update_task {"id": "{{taskId}}", "title": "...", "type": "...", "priority": "...", "labels": ["..."], "description": "...", "references": ["ref-N"], "acceptanceCriteria": ["...", "..."]}

   - description — только если снимал #теги (шаг 3) или уточняешь постановку; иначе не передавай.
   - references — только если регистрировал источники (шаг 7).
   - Поля, которые не определил, просто не передавай.

   **Критерий завершения шага 5.** Ответ инструмента — JSON:
   - `applied` — что записалось. Поле уже в `applied` → НЕ передавай его повторно.
   - `skipped` — что не записалось: не дожимай повтором, упомяни в отчёте.
   - `idempotentReplay: true` — уже применено ранее, второго эффекта не нужно.
   - `ok: true` → сразу шаг 9.
   - `ok: false` → `reason: not_confirmed` — один повтор с новым idempotencyKey; `reason: denied` — не повторяй, только отчёт без status.

9. **Отчёт — один вызов backlog_finish_phase.**

   Описание полное (AC заполнены):
   backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза 1 (Spec) выполнена. Заголовок: <изменён|оставлен>. Тип: <...>. Масштаб: <task|epic>. Приоритет: <...>. Labels: <...>. References: <ref-N|нет>. AC: <N пунктов>. Вопросов нет.", "status": "{{producesStatus}}"}

   Описание неполное — только комментарий, БЕЗ status, с вопросами:
   backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза 1 (Spec) выполнена. Заголовок: <...>. Тип: не изменён. Масштаб: не определён (описание неполное). Приоритет: не определён. Labels: <...>. References: <...>. Жду ответов на вопросы:\n\n### 1. <вопрос>\n- [ ] <вариант A>\n- [ ] <вариант B>\n- [ ] Другое → \n\n### 2. <вопрос>\n→ \n\n### Дополнительные комментарии\n→ "}

   При неполном описании НЕ уточняй задачу серией backlog_update_task — сразу отчёт без status. Единственное исключение — снятие ведущих #тегов (шаг 3): оно делается тем же единственным вызовом.

## Формат финала

Нет вопросов → ответь ровно «Готово» (+ строка «Предлагаю добавить label ...», если предлагаешь новый label).

Есть вопросы → шаблон в code block, тот же текст, что в комментарии:

=====
## Уточнения по задаче
Ответь на вопросы ниже, расставив галочки или вписав ответ после →.
```
### 1. <вопрос>

- [ ] <вариант A>
- [ ] <вариант B>
- [ ] Другое → 

### Дополнительные комментарии

→ 
```
Жду твоего ответа на это сообщение для продолжения.
=====

## Запреты

- НЕ читай код (никаких grep/sed по src/), НЕ изучай содержимое референсов.
- НЕ пиши Implementation Plan, НЕ разбивай на подзадачи, НЕ создавай задач.
- НЕ вызывай backlog_view_task для самой задачи — она подставлена выше. Исключение: пользователь явно ссылается на другую задачу — прочитай её ОДИН раз.
- НЕ вызывай backlog_add_comment и backlog_update_status — отчёт и статус идут одним backlog_finish_phase.
- НЕ выполняй git-операции, НЕ правь файлы задач напрямую.
- Если что-то пошло не так — комментарий с описанием проблемы, статус не меняй.

## Что делает Analyze

Детерминированный разбор сессии (это штатная команда /analyze): статистика по jsonl, вердикт «объём задачи vs тупик», рекомендации. Это разбор, а не исполнение задачи.

## Порядок

1. **Статистика** — одним node-скриптом (`node -e` или `node --input-type=module -e`; ЗАПРЕТ python/perl/awk/jq — внешние рантаймы запрещены проектом) по файлу {{sessionPath}}:
   - длительность сессии: старт — ms-epoch из ID сессии `agent-(\d+)`, конец — mtime jsonl;
   - прогоны по «Продолжи»: user-сообщения (role='user') с текстом «Продолжи» и его вариациями — количество и доля от всех user-сообщений;
   - wall-убийства: содержимое (content) с «Превышен лимит --max-wall-time» — сколько раз;
   - «Пустой ответ модели»: вхождения в content — сколько раз;
   - NaN-индексы: «Неверный индекс: NaN» — сколько раз;
   - профиль tool-вызовов по именам: assistant.tool_calls[].name — счётчик по каждому имени (вызовы и доля);
   - топ-10 tool-выводов по длине: role='tool', имя инструмента через tool_call_id → длина content;
   - чтения и правки по файлам: path из аргументов вызовов read_file/edit/write_file/grep/glob — счётчики по каждому файлу;
   - повторы по ключу `<инструмент>|<path|pattern>`: топ-10 с числом обращений и долей повторных вызовов от всех tool-вызовов сессии (готовые цифры — в блоке «Повторы обращений» выше; скриптом пересчитай только если блок говорит «нет данных»).
   Выведи сводку компактной таблицей или списком.

2. **Вердикт.** Сопоставь объём задачи с тупиком и расточительством: при подставленном {{taskId}} прочитай задачу через MCP (backlog_view_task), только если нужен контекст объёма (AC, план); при пустой мете backlog_view_task НЕ нужен. Количественные выводы из статистики шага 1 (сколько ходов убито wall-time, доля прогонов «Продолжи», топ вызовов, какие файлы перечитывались). Обязательно назови топ перечитываемых файлов и топ повторяющихся grep/glob-запросов с цифрами (из блока «Повторы обращений» выше) — это основное доказательство расточительства. Итог: «задача в пределах объёма» либо «тупик/расточительство» с конкретными цифрами-доказательствами.

3. **Рекомендации.** Сначала backlog_search по ключевым словам найденной проблемы — не заведена ли уже задача на неё; рекомендации ссылай на найденные существующие задачи. НОВЫХ задач НЕ создавать — только рекомендации.

4. **Отчёт** кратким текстом: статистика → вердикт → рекомендации. Финальный текст должен содержать отчёт.

## Запреты

- НЕ создавай задачи, НЕ меняй статусы и НЕ коммить — это разбор, а не исполнение задачи.
- НЕ читай jsonl построчно через MCP-инструменты: статистика считается одним node-скриптом.
- Не изучай посторонние задачи и файлы сверх протокола выше; внешние рантаймы (python/perl/awk/jq) запрещены.

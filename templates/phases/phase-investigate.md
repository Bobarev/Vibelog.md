## Цель фазы

Расследовать инцидент/проблему и подготовить документ с выводами И предложениями задач. Создание задач — НЕ твоя работа: предложения материализует фаза materialize после твоего Review.

## Шаги

1. Блок задачи подставлен — backlog_view_task не нужен.

2. Собери данные (команды пакетируй через &&):
   - сессии агента: ls .vibelog/agent-sessions/ → чтение релевантных *.jsonl и *.meta.json (фазы, ошибки, stderr, тайминги; хвосты длинных строк — последними 100–200 строками, не файлом целиком);
   - .vibelog/auto-queue.json — состояние автоочереди (retry/failed);
   - git log -15 --oneline и git status --porcelain;
   - целевой код: grep/glob по подсказкам из описания задачи (не читай файлы целиком > 200 строк);
   - комментарии задачи — блок выше.

3. Проанализируй: хронология событий, корневая причина (или гипотезы с уровнем уверенности), затронутые компоненты, повторяемость.

4. Создай документ расследования:
   document_create {"title": "Расследование {{taskId}}: <предмет>", "type": "other", "content": "<markdown>", "tags": ["investigation"]}
   Разделы документа:
   - «Выводы» — факты, причины, цитаты логов/сессий (с путями файлов);
   - «Предложение задач» — каждое предложение пронумеруй и опиши полями готовыми для создания: title; type (один из: {{availableTypes}}); priority (один из: {{availablePriorities}}); описание; 1–3 AC.

5. Оставь отчёт и смени статус ОДНИМ вызовом:
   backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Investigate выполнена. Документ: <id>. Выводы: <2–3 тезиса>. Предложено задач: N (№1 — <title>, №2 — <title>). Статус: {{producesStatus}}.", "status": "{{producesStatus}}"}
   Отдельные backlog_add_comment и backlog_update_status НЕ вызывай.

## Запреты

- НЕ создавать задачи — это фаза materialize.
- НЕ менять статусы вручную и не архивировать задачу — только finish_phase выше.
- НЕ коммитить: фаза только читает данные и пишет документ/отчёт через MCP.

## Экономия ходов

- Пакетируй последовательные команды в ОДИН вызов через &&.
- Поиски: не более 2 ходов на один файл/сессию, затем двигайся дальше.

## Правила

- Если подставлен блок «Режим параллельной разработки» — работай в worktree; иначе в главном каталоге. Сессии и автоочередь (.vibelog/) читай по путям главного репозитория — там они и хранятся.
- Работай только чтением; правки — только через MCP (document_create, backlog_finish_phase).

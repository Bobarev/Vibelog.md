## Что делает Investigate

Расследовать инцидент или проблему и подготовить документ с выводами И предложениями задач. Создание задач — НЕ твоя работа: предложения материализует фаза materialize после Review.

## Порядок

1. **Блок задачи** подставлен — backlog_view_task не нужен.

2. **Данные.** Собери: сессии агента (ls .vibelog/agent-sessions/, затем релевантные *.jsonl и *.meta.json — фазы, ошибки, stderr, тайминги; длинные строки обзором через agent_session_outline, не файлом целиком); .vibelog/auto-queue.json (retry/failed); git log -15 --oneline и git status --porcelain; целевой код по подсказкам из описания; комментарии задачи из блока выше. Команды пакетируй через &&.

3. **Анализ.** Хронология событий, корневая причина (или гипотезы с уровнем уверенности), затронутые компоненты, повторяемость.

4. **Документ расследования:**
   document_create {"title": "Расследование {{taskId}}: <предмет>", "type": "other", "content": "<markdown>", "tags": ["investigation"]}
   Разделы документа: «Выводы» — факты, причины, цитаты логов и сессий (с путями файлов); «Предложение задач» — каждое предложение пронумеруй и опиши готовыми к созданию полями: title; type (один из: {{availableTypes}}); priority (один из: {{availablePriorities}}); описание; 1–3 AC.

5. **Отчёт и статус — один вызов:**
   backlog_finish_phase {"id": "{{taskId}}", "comment": "Фаза Investigate выполнена. Документ: <id>. Выводы: <2–3 тезиса>. Предложено задач: N (№1 — <title>, №2 — <title>). Статус: {{producesStatus}}.", "status": "{{producesStatus}}"}
   Отдельные backlog_add_comment и backlog_update_status НЕ вызывай.

## Экономия ходов

- Пакетируй последовательные команды в ОДИН вызов через &&.
- Пакетное чтение: целевой файл читай одним read_file (при >200 строк — чанки offset/limit подряд, без промежуточного grep-поиска границ); связанные проверочные команды — один вызов через &&.
- Параллельные вызовы: независимые чтения и поиски (несколько файлов, несколько паттернов) — ОДНИМ ходом, несколькими tool_calls в одном assistant-сообщении, а не последовательными ходами.
- Поиски: не более 2 ходов на один файл или сессию, затем двигайся дальше; повторные переборы тех же glob/grep-паттернов запрещены — один проход.

## Запреты

- НЕ создавать задачи — это фаза materialize; не создавай их ни вызовом backlog_create_task, ни вручную.
- НЕ меняй статусы вручную и не архивируй задачу — только finish_phase выше.
- НЕ коммить: фаза только читает данные и пишет документ и отчёт через MCP.

## Правила

- Если подставлен блок «Режим параллельной разработки» — работай в worktree; иначе в главном каталоге. Сессии и автоочередь (.vibelog/) читай по путям главного репозитория — там они и хранятся.
- Работай только чтением; правки — только через MCP (document_create, backlog_finish_phase).

## Что делает Reject

Откатить незакоммиченные изменения задачи, не тронув чужое, и оставить итог комментарием. Статус меняет механика после фазы.

## Порядок

1. **Блок задачи** подставлен — backlog_view_task не нужен.

2. **Начатые изменения.** git status --porcelain и git diff в текущем каталоге (одной командой через &&).

3. **Откат** незакоммиченных изменений, принадлежащих задаче: только поимённо из git status/diff — git restore <file> по одному файлу. Файлы backlog/ и чужие (не относящиеся к задаче) не трогать; файлы, которые невозможно откатить (закоммиченные, чужие, backlog/), — просто перечисли в итоге, не меняй.

4. **Итог комментарием:**
   backlog_add_comment {"id": "{{taskId}}", "author": "@agent", "comment": "Фаза Reject выполнена: откачано <файлы или «нет»>; не откачано: <если есть>; причина: {{comment}}"}
   Фолбэк: если вместо причины подставлена строка «без комментария» (запуск без комментария) — причина в итоге не нужна, не выдумывай её.

## Запреты

- Запрещены reset/checkout широкого охвата, commit, push — только restore поимённо и один backlog_add_comment.
- Работа идёт в git worktree задачи, если он есть (блок «Режим параллельной разработки»); иначе — в главном каталоге. В обоих случаях откат только поимённый из git status/diff.
- Статус НЕ меняй и файл задачи НЕ архивируй — это делает механика после фазы.
- Файл из шага 2 не найден или не менялся — не более 2 ходов на поиск, затем переходи к итогу (шаг 4).

## Финал

После последнего шага (итог комментарием) ответь ровно одно слово — «Готово». Не повторяй отчёт, не добавляй анализ и выводы, не выполняй дополнительных действий — терминальный вывод не нужен.

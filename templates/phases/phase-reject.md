## Шаги

1. Блок задачи подставлен — backlog_view_task не нужен.

2. Определи начатые изменения задачи: `git status --porcelain` и `git diff` в текущем каталоге (одной командой через &&).

3. Откати НЕЗАКОММИЧЕННЫЕ изменения, принадлежащие задаче:
   - только поимённо из git status/diff: `git restore <file>` по одному файлу;
   - запрещены reset/checkout широкого охвата, commit, push;
   - файлы backlog/ и чужие (не относящиеся к задаче) файлы не трогать;
   - файлы, которые невозможно откатить (закоммиченные, чужие, backlog/) — просто перечисли в итоге, не меняй.

4. Оставь итог комментарием:
   backlog_add_comment {"id": "{{taskId}}", "author": "@agent", "comment": "Фаза Reject выполнена: откачано <файлы или «нет»>; не откачано: <если есть>; причина: {{comment}}"}

   Если {{comment}} не подставлено (запуск без комментария) — причина в итоге не нужна, не выдумывай её.

5. Статус НЕ меняй и файл задачи НЕ архивируй — это делает механика после фазы.

## Экономия ходов

- Пакетируй последовательные git/shell-команды в ОДИН вызов через &&.
- Файл из шага 2 не найден/не менялся — не более 2 ходов на поиск, затем переходи к шагу 4.

## Правила

- Работа идёт в git worktree задачи, если он есть (см. блок «Режим параллельной разработки» ниже); иначе — в главном каталоге. В обоих случаях откат только поимённый из git status/diff.
- Никаких commit/push — только restore поимённо и backlog_add_comment.

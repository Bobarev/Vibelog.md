# AGENTS.md — Vibelog.md

Этот проект — **Vibelog.md**, markdown-нативный таск-менеджер для git-репозиториев, максимально совместимый с Backlog.md. Реализуется на чистом Node.js + pnpm, без нативных зависимостей.

## Зачем этот проект существует

Оригинальный **Backlog.md** невозможно запустить на macOS 10.15 Catalina (использует нативный Bun-рантайм). Также на Catalina не работают Claude Code, Opencode и другие популярные AI-агенты — работает **только Qwen Code**. Поэтому нужен инструмент, который:

1. Работает на Catalina + Node.js 20+.
2. Полностью совместим по формату данных с Backlog.md (чтобы при апгрейде на новую macOS можно было просто переключиться на оригинал).
3. Интегрируется с Qwen Code через CLI и MCP.

Совместимость нужна **только с Qwen Code** — остальные агенты могут использовать оригинал Backlog.md.

## Язык

**Всё на русском языке:**
- Комментарии в коде — обязательно, подробные, объясняющие «почему», а не «что».
- JSDoc-блоки для всех экспортируемых функций.
- Сообщения об ошибках — на русском.
- Тексты CLI-вывода — на русском.
- Документация, README, планы — на русском.
- Коммиты — на русском (`feat: добавить парсер YAML`).

Английский — только там, где это технически неизбежно (имена полей frontmatter для совместимости с Backlog.md, имена MCP-инструментов, ключи JSON-RPC).

## Что нужно сделать

Реализовать проект по плану из файлов `plan/PLAN-*.md`. Каждый файл — отдельный этап. Этапы выполняются последовательно.

**Порядок работы:**

1. **Прочитай `plan/PLAN-00-OVERVIEW.md`** — общая архитектура и контекст.
2. **Изучи оригинал Backlog.md** по пути `/Users/bob/Dev/ton/ai/Backlog.md` — исходники, формат задач, CLI-команды, MCP-инструменты, конфиг. Особое внимание: `src/`, `backlog/tasks/`, `backlog.config.yml`, `CLI-INSTRUCTIONS.md`, `ADVANCED-CONFIG.md`.
3. **Начни с `plan/PLAN-01-SCAFFOLD.md`** — структура проекта, `package.json`, pnpm.
4. **Далее последовательно:** `PLAN-02`, `PLAN-03`, ..., `PLAN-08`.

## Право на корректировку плана

Если в процессе изучения оригинала Backlog.md ты обнаружишь, что план содержит **неточности, упущения или недостаточный функционал** для совместимости — **вноси правки прямо в файлы `plan/PLAN-*.md`**. Не нужно спрашивать разрешения. Коммить изменения плана отдельно с сообщением вида:

```
docs(plan): уточнить формат AC по результатам анализа Backlog.md
```

Это относится к:
- Формату frontmatter (новые поля, изменённые типы).
- Формату AC/DoD (нумерация, маркеры).
- Структуре папок внутри `backlog/`.
- CLI-флагам и их алиасам.
- MCP-инструментам (названия, схемы параметров).
- Формату конфига.
- Любым другим аспектам совместимости.

## Важные правила

- **Только чистый Node.js** (ES modules, `.mjs`). Никаких нативных зависимостей, node-gyp, SQLite, Bun.
- **pnpm** — менеджер пакетов, версия **10.7.1** (`packageManager: "pnpm@10.7.1"`).
- **Zero runtime dependencies.** YAML и markdown — свои мини-парсеры.
- **Совместимость с Backlog.md** — максимальная.
- **Node.js 20+**, macOS 10.15 Catalina (проверять, что нет нативных модулей).
- **Не использовать Claude Code / Codex / Opencode** — они не работают на Catalina. Целевой агент — Qwen Code.

## Как отслеживать прогресс

Используй сам Vibelog.md для трекинга задач (dogfooding):

```bash
node bin/vibelog.mjs init "Vibelog.md"
node bin/vibelog.mjs task create "Реализовать PLAN-01: Scaffold" -d "..." --ac "..."
```

На этапе PLAN-01 CLI ещё не готов — первые задачи можно создавать как markdown-файлы вручную, следуя формату из плана.

Ты работаешь с проектом через Vibelog MCP.

Пользователь описал фичу: {{args}}

Твоя задача — Фаза 1 (Spec). Spec — фаза уточнения, а не декомпозиции:
НЕ создаёт новых задач — только уточняет исходную и определяет её тип.

1. Изучи репозиторий через bash: grep, sed, ls. НЕ читай файлы целиком,
   если они > 200 строк. Экранируй кавычками пути с пробелами.

2. Определи масштаб фичи:
   - Укладывается в одну задачу → type=task.
   - Явно не укладывается (несколько независимых частей) → type=epic.

3. Уточни задачу через MCP backlog_update_task:
   - Дополни описание (детали, контекст).
   - Уточни 2-3 критерия приёмки (конкретные, проверяемые).
   - Установи type (task или epic).
   - Если описание неполное (непонятна цель, нет критериев или ограничений) — не додумывай: задай вопросы пользователю и жди ответа.

4. Покажи пользователю уточнённую задачу и ЖДИ ПОДТВЕРЖДЕНИЯ.
   НЕ начинай Фазу 2 без явного «да».

Правила:
- НЕ создавай новых задач через backlog_create_task — декомпозиция забота Фазы 2 (Plan).
- Если фича большая — просто пометь type=epic.
